# 화면 설계 가이드

디자인 핸드오프(Claude Design 캔버스 "우리동네체온계 홈 시안")와 함께 받은 작업 안내를 옮긴 문서다. 범위·디자인 규칙·문구 규칙·구현 순서의 정본이다.

시안 원본은 [`design/`](design/README.md) 에 있다. 우선순위는 **화면 명세서(`screen-spec.md`) > 시안(`design/screens/*.dc.html`) > `design/tokens.json`** 이다. 셋이 다르면 명세서를 따른다.

> 화면 명세서 `screen-spec.md` 는 아직 받지 못했다. 받으면 이 폴더(`frontend/docs/screen-spec.md`)에 둔다.

## 범위 (제출 신청서 기준, 바꾸지 말 것)

- 성인 본인 보고만 만든다. 아이 대리 보고와 학부모 그룹(S09)은 만들지 않는다.
- 행정동은 사용자가 직접 고른다. 위치 권한을 요청하지 않는다. 이름·연락처·정확한 주소·GPS·자유 입력을 받지 않는다.
- 보고는 "증상 없음" 또는 증상군(발열·기침·인후통 / 구토·설사)이다. 같은 사람의 같은 주 보고는 고칠 수 있고 집계는 1회다.
- 개별 보고 보관 기간은 52주다. 시안(Setup-3 · Settings)의 "12주" 는 낡은 문구라 쓰지 않는다(시안과 다른 결정, 백엔드 entity-design §8 — 건강정보 동의 S02-4 · 내 정보 S10 · 최근 보고 내역이 같은 값을 쓴다).
- 표시는 참여자 대비 증상 비율이다. 참여 100명 미만이면 "자료 부족"으로 두고 증상 비율·상태색을 숨긴다. 참여 진행 막대만 보인다.
- 예방 안내는 운영자가 검토·발행한 주에만 보인다. AI 는 안내문 초안 작성에만 쓴다.
- 공식 정보(질병관리청)와 시민 자가보고를 한 UI 요소에 섞지 않는다.

## 상태 단계

시안과 `tokens.json` 의 `status` 가 정본이다.

| 키             | 라벨          | 의미                                                                         |
| -------------- | ------------- | ---------------------------------------------------------------------------- |
| `normal`       | 평소 수준     | 기준선과 비슷하다                                                            |
| `slight`       | 조금 늘었어요 | 기준선보다 `slightDeltaPp`(3%p) 이상 높다                                    |
| `high`         | 많이 늘었어요 | 기준선보다 `highDeltaPp`(8%p) 이상 높다                                      |
| `insufficient` | 자료 부족     | 참여자가 `publicThresholdParticipants`(100명) 미만이다. 수치·상태색을 숨긴다 |

> 루트 `CLAUDE.md` 는 기획서 기준 단계 이름(`좋음` / `보통` / `주의` / `판단 보류`)을 적고 있다. 시안은 위 이름으로 바뀌었다. 백엔드 enum 과 맞출 때 어느 쪽을 쓸지 팀에서 확정한다.

## 기술 스택 (제안, 팀과 확정 후 수정)

- Next.js(App Router) + TypeScript + Tailwind CSS
- PWA: 서비스 워커 + Web Push. iOS 는 홈 화면에 추가한 뒤에만 알림을 받을 수 있으므로 S12 안내가 꼭 필요하다. 매니페스트 · 임시 아이콘 · 서비스 워커 자리(2단계 등록)는 [SCREENS.md](design/SCREENS.md) "앱 매니페스트 · 아이콘 · 서비스 워커 자리" 에 있다.
- 지도: MapLibre GL + SGIS 행정구역 경계(GeoJSON). 핀 없이 행정동 색칠만 한다.
- 서체: npm `pretendard`
- 데이터 패칭: 라이브러리 없이 `src/lib/api/` 의 얇은 `fetch` 래퍼(#126 에서 결정, [conventions.md](conventions.md) "API 계층")
- 백엔드·인프라·LLM 은 별도 담당이다. API 계약은 [api-contract-draft.md](api-contract-draft.md) 다(인증 · 회원 · 행정동 확정, 그 밖은 백엔드와 맞춘 뒤 확정).

## 디자인 규칙

- 토큰은 `design/tokens.json` 을 Tailwind theme 로 옮겨서만 쓴다. 임의 색·그림자·그라데이션을 쓰지 않는다.
- 카드는 홈 상태 카드 하나뿐이다. 나머지는 섹션 제목 + 리스트 행 + 1px 구분선 + 8px 회색 띠로 만든다.
- 상태는 항상 색과 글자 라벨을 함께 보인다. 터치 영역은 최소 44×44 다.
- 반응형은 모바일 390 / 태블릿 834 / 데스크톱 1440 시안을 기준으로 한다.
  - 보고·판단 기준은 모바일에서 바텀시트, 태블릿·데스크톱에서 가운데 대화상자다.
  - 설치 안내(S12 `/install`)는 모바일에서 전체 화면, 태블릿·데스크톱에서 가운데 대화상자 모양의 단독 화면이다.
  - 첫 진입 데스크톱은 왼쪽 콘텐츠 + 오른쪽 어두운 이미지 패널이다.

## 문구 규칙

- 한 문장에 한 가지 말만 쓴다.
- 쉼표로 두 문장을 잇지 않는다("~인지, ~해요", "~하고, ~돼요" 금지). 목록 나열은 괜찮다.
- "위험", "비상", "유행"(공식 정보 제외)처럼 불안을 키우는 단어를 쓰지 않는다.

## 구현 순서

1. 기반: 토큰·서체·공통 컴포넌트(상태 라벨, 게이지, 리스트 행, 버튼, 바텀시트/대화상자, 토스트, 탭바·헤더)
2. S03 홈 4상태 + S11 판단 기준 (목 데이터로 먼저)
3. S05·S06 보고 흐름 (되돌리기 포함) — `design/screens/Flow.dc.html` 의 상태 전환 참고
4. S01·S02 첫 진입, S10 내 정보, S12 설치 안내, PWA·웹푸시
5. S04 지도 (SGIS 경계 연동)
6. S07·S08 안내·공식 정보
7. 운영자 A01–A03
8. API 연동, 오류·오프라인·불러오는 중 상태

각 단계가 끝나면 해당 시안과 화면을 나란히 놓고 간격·문구 차이를 확인한다. 화면 ID ↔ 시안 파일 ↔ 라우트는 [`design/SCREENS.md`](design/SCREENS.md) 에 있다.
