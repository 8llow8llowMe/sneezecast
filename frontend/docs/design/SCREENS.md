## 첫 진입 (S01 · S02 · S13) 메모

- 단계 표시는 `n / 4` 입니다. 시안은 `/ 3` 이지만 S02-4 증상 보고 동의가 더해질 예정입니다.
- 둘러보기 변형: S01 `보고 없이 둘러보기` → `/browse/region` (Setup-1-browse). 단계 표시가 없고 버튼이 `이 동네 보기` 이며, 고르면 `/?region=<행정동 코드>` 홈으로 갑니다.
- S02-1 동네 선택 · 결과 없음 · 둘러보기와 S02-2 성인 확인은 새 캔버스 `auth/screens/` 의 Setup-1 · Setup-1-empty · Setup-1-browse · Setup-2 가 정본입니다. 이 폴더의 `screens/Setup-1*` · `Setup-2*` 와 다르면 새 쪽을 따릅니다.
- 흐름: S01 `시작하기` → `/login`(S13-1) → 카카오 신규 회원이면 `/setup/region?from=kakao`. 로그인 화면은 단계 표시가 없습니다.
- `/login` 상태는 주소 쿼리로 받습니다: `?error=kakao-fail` · `?error=kakao-exists` · `?reason=expired`. 연동 때 카카오 콜백 · 세션 만료가 같은 쿼리로 돌려보냅니다. `/login/email?reason=reset-done` 은 비밀번호를 바꾼 뒤입니다.
- 이메일 로그인 목(`features/auth/auth-client.ts`)에서 상태를 재현하는 입력: 이메일 `locked@example.com` → 잠김(locked), 비밀번호 `wrong` → 맞지 않음(wrong), 그 밖 → 성공(홈으로).
- 이메일 가입 흐름: `/login` 이메일로 가입하기 → `/signup/email` → `/signup/code` → `/signup/account` → `/setup/region`. 단계 표시는 없습니다. 입력값은 메모리(Provider)에만 두고, 중간 단계에 바로 들어오면 `/signup/email` 로 돌려보냅니다.
- 백엔드 #56 화면 계약(`backend/docs/modules.md` "화면 계약")에 맞춰 시안과 다르게 둔 것:
  - S13-2 에 "이미 가입된 이메일"(exists) 상태가 없습니다. 코드 받기는 가입 여부와 무관하게 같은 응답이라 늘 `/signup/code` 로 가고, S13-3 제목 아래에 "이미 가입한 이메일이면 코드 대신 안내 메일이 가요." 를 늘 보입니다.
  - 코드 요청 제한(limit)은 남은 시간을 주지 않아 "조금 뒤 다시 시도해 주세요" 로 씁니다(시안 "10분 뒤").
  - 코드 확인은 5번까지 틀릴 수 있어 첫 실패 문구가 "남은 시도는 4번이에요" 입니다(시안 장면은 3번).
  - 백엔드는 남은 시도 횟수를 주지 않습니다(틀림 `AUTH_003`, 5번째 `AUTH_005` 잠김 + 코드 삭제, 그다음 확인은 `AUTH_004` 만료). 연동 때 `auth-client.ts` 가 이메일별 실패 수를 세어 남은 시도를 채우고, 코드를 다시 받으면(sent) 0 으로 되돌립니다. 목도 잠기면 코드를 지워 그다음 확인이 expired 입니다.
  - 비밀번호는 8~20자 · 영문과 숫자 함께 · 공백 없이입니다. 도움말 "8~20자 · 영문과 숫자 포함 · 띄어쓰기 없이", 오류 "영문과 숫자를 함께 8~20자로, 띄어쓰기 없이 써 주세요." (시안 "8자 이상 · 영문과 숫자 포함" · "8자 이상으로 영문과 숫자를 함께 써 주세요.")
- 가입 목(`features/auth/auth-client.ts`)에서 상태를 재현하는 입력:
  - 코드 받기: 이메일 `limit@example.com` → 요청 많음(limit), 형식이 틀리면 invalid(보낼 때 판단). 그 밖은 이미 가입한 이메일이어도 보냄
  - 코드 확인: `000000` → 틀림(남은 시도 4번부터 1씩 줄고 5번째에 locked), `999999` → 잠김(locked), 잠긴 뒤 · 5분이 지나면 expired, 그 밖 6자리 → 성공
  - 비밀번호 · 닉네임: 8자 미만 · 20자 초과이거나 영문 · 숫자 중 하나가 없거나 공백이 있으면 pw-rule, 확인이 다르면 pw-mismatch, 닉네임 2~10자 밖이면 nick-long(다음을 누를 때 판단)
- 가입 마무리: 성인 확인 `다음` → `/setup/terms`(S02-3) → 가입 요청 → (이메일 가입만) 로그인 → 내 동네 저장 → `/setup/health-consent`(S02-4, 기록을 바꿔 감) → `동의하고 시작하기` 또는 `나중에 할게요` → 홈 `/`(기록을 바꿔 감).
  - 가입 응답에 토큰이 없어 이메일 가입은 가입 뒤 이메일 · 비밀번호로 로그인합니다. 카카오 가입은 이미 로그인한 상태라 바로 동네를 저장합니다.
  - 가입 종류는 Provider 초안의 `method` 로 가립니다: 이메일 화면이 코드를 보내면 `email`, 로그인 화면에서 카카오로 시작하거나 S02-1 이 `?from=kakao` 로 열리면 `kakao`, `/login` 에 들어오면 지웁니다. 모르면 S02-3 이 `/login` 으로, 이메일 가입인데 인증 · 비밀번호가 없으면 `/signup/email` 로 돌려보냅니다.
  - 가입 · 로그인 · 동네 저장 중 하나가 실패하면 다시 누를 때 끝난 단계는 보내지 않습니다(가입 두 번 금지). 응답을 기다리는 동안 화면을 떠나도 서버에서 끝난 단계는 Provider 에 남깁니다. 비밀번호는 로그인을 마친 뒤 지웁니다.
  - 이 진행은 가입 시도 하나에만 딸립니다. `/login` 에 들어오거나 카카오로 시작하면(`resetSignup`), 이메일 화면이 코드를 보내면 비웁니다.
  - **연동 요구사항**: 카카오 신규 회원 콜백은 `?from=kakao` 로 S02-1(`/setup/region?from=kakao`, `paths.ts` 의 `SETUP_REGION_FROM_KAKAO_PATH`)에 돌아옵니다. 실제 카카오 로그인은 페이지를 새로 열어 메모리가 비므로, S02-1 이 이 표시를 보고 가입 종류가 카카오가 아니면 가입 초안 · 마무리 진행을 비우고(`resetSignup`) `method: 'kakao'` 로 둡니다. 이미 카카오면(S13-1 에서 시작 · 뒤로 가기로 다시 옴) 진행 중인 가입을 지우지 않습니다. 목 `startKakaoLogin` 도 같은 주소를 돌려줘 홈의 로그인 안내 시트(첫 진입 Provider 밖)에서 시작해도 S02-3 까지 카카오 가입으로 이어집니다.
  - 인증을 마친 지 30분이 지나 가입이 인증 만료(`AUTH_007`)로 돌아오면 인증 · 비밀번호를 지우고 `/signup/email?reason=verification-expired` 로 갑니다. 이메일 화면은 "인증 시간이 지났어요. 이메일 인증부터 다시 해 주세요." 를 띄우고, 다시 인증하면 닉네임은 남아 있습니다.
  - 전체 동의는 필수 둘이 켜졌는지를 따릅니다(시안 default 는 선택이 꺼져도 전체 동의가 켜짐). 켜면 선택까지 모두 켜고 끄면 모두 끕니다.
  - 약관 "보기" 는 본문이 아직 없어 "약관 본문을 준비하고 있어요" 알림만 띄웁니다.
  - S02-4 는 시안에 뒤로 버튼이 있지만 가입을 마친 뒤라 숨깁니다(가입 동의로 돌아가 다시 가입하지 않게).
  - 동의 문서 버전은 `features/auth/legal.ts` 가 정본이고 백엔드 `legal.*-version` 을 맞춥니다.
- 가입 목 재현 입력: 이메일 `signup-fail@example.com` 으로 가입하면 가입 요청이 거부되고, `verify-expired@example.com` 이면 늘 인증 만료입니다. `locked@example.com` 으로 가입하면 가입은 되고 이어지는 로그인이 잠김으로 실패합니다(로그인 목과 같은 입력). 이 입력은 다시 눌러도 계속 실패합니다(로그인 재시도가 성공하는 흐름은 자동 테스트가 덮습니다).
- 비밀번호 재설정 흐름(S13-6): `/login/email` 의 `비밀번호를 잊었어요` → `/password/reset`(이메일) → `/password/reset/code` → `/password/reset/new` → `/login/email?reason=reset-done`(기록을 바꿔 감). 단계 표시는 없습니다.
  - 이메일 · 코드 단계는 시안 안내(`auth/README.md`)대로 가입 화면을 재사용합니다. 두 흐름이 `features/auth/email-step.tsx` · `code-step.tsx` 를 같이 쓰고 문구 · 보낼 · 확인할 함수 · 인증 결과를 남기는 법(가입은 인증 시각, 재설정은 일회용 토큰) · 앞뒤 경로만 다르게 넘깁니다. 한도 · 상태(invalid · limit · wrong · expired · locked · 인증 마침)는 가입과 같습니다.
  - 시안에 재설정용 원문이 없어 가입 문구에서 바꾼 것: 이메일 단계 제목 "가입한 이메일을 알려 주세요"(가입 "이메일을 알려 주세요"), 코드 단계 제목 아래 중립 문구 "가입한 이메일이면 코드를 보내 드려요."(가입 "이미 가입한 이메일이면 코드 대신 안내 메일이 가요."). 버튼("인증 코드 받기" · "확인") · 도움말 · 오류 · 오른쪽 패널 문구는 가입과 같습니다.
  - 가입 여부를 드러내지 않습니다. 코드 받기는 가입 여부와 무관하게 같은 응답이라고 가정해 늘 코드 단계로 가고, "가입하지 않은 이메일" 상태가 없습니다.
  - 새 비밀번호(Password-reset default · mismatch · rule): 규칙 · 문구는 S13-4 와 같습니다 — 도움말 "8~20자 · 영문과 숫자 포함 · 띄어쓰기 없이", 오류 "영문과 숫자를 함께 8~20자로, 띄어쓰기 없이 써 주세요." · "비밀번호가 서로 달라요." (시안 "8자 이상 · 영문과 숫자 포함" · "8자 이상으로 영문과 숫자를 함께 써 주세요."). 오류는 시안 rule 장면(확인 칸이 빈 채 오류)과 달리 `비밀번호 바꾸기` 를 누를 때 처음 보입니다(S13-4 와 같은 규칙, 빈 칸이 있으면 버튼이 꺼져 있음). 보내지 못하면 빨강 상자 "비밀번호를 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요." 는 시안에 없어 더했습니다.
  - 코드를 맞히면 서버가 **일회용 재설정 토큰**(15분)을 주고, 새 비밀번호 요청은 이메일이 아니라 이 토큰으로 보냅니다(토큰 없이 이메일만으로 재설정하지 않습니다 — `docs/api-contract-draft.md`).
  - 값은 Provider 의 재설정 초안(`passwordReset`: 이메일 · 보낸 시각 · 재설정 토큰)에만 두고 가입 초안과 섞지 않습니다. 토큰은 주소 · 로그 · 브라우저 저장소에 남기지 않습니다. 새 비밀번호는 그 화면 상태에만 둡니다. 중간 단계에 바로 들어오면(값이 없음, 새 비밀번호 단계는 토큰이 없음) `/password/reset` 으로 돌려보냅니다. 가입 초안의 인증으로는 열리지 않습니다.
  - 새 비밀번호를 보내는 중에는 버튼 · 칸과 함께 머리줄 뒤로도 꺼 둡니다(`aria-disabled`).
  - 초안을 비우는 때: 이메일 단계가 코드를 새로 보내면 새로 씀, 코드를 다시 받으면 토큰을 지움, 재설정을 마치면 보낸 시각 · 토큰을 지움(이메일은 남겨 `/login/email` 이메일 칸을 채움 — 주소에는 넣지 않습니다), 인증 만료면 보낸 시각 · 토큰을 지움, `/login/email` · `/login` 에 들어오면 이메일만 남기고 지움. 공용 기기에서 새 비밀번호 단계까지 간 뒤 이메일 로그인으로 돌아오면 앞으로 가기로 새 비밀번호 화면에 다시 들어갈 수 없습니다(이메일 단계로 돌려보냄).
  - 재설정이 인증 만료로 돌아오면 `/password/reset?reason=verification-expired` 로 가고 이메일 단계가 "인증 시간이 지났어요. 이메일 인증부터 다시 해 주세요." 를 띄웁니다(가입과 같음).
  - 재설정 목(`features/auth/auth-client.ts`, 가입 인증과 같은 입력 · 저장소는 따로) 재현 입력: 코드 받기 `limit@example.com` → limit, 코드 확인 `000000` → 틀림(5번째에 locked) · `999999` → locked · 5분이 지나면 expired, 재설정 `verify-expired@example.com` 로 받은 토큰 → 늘 인증 만료, `reset-fail@example.com` 로 받은 토큰 → 응답을 받지 못함(빨강 상자, 다시 눌러도 계속 실패). 토큰은 한 번만 쓰고 15분이 지나면 인증 만료입니다. 가입 코드 · 인증으로 재설정을 마칠 수 없고 그 반대도 같습니다.
- 로그인 · 가입 화면의 오른쪽 일러스트도 `public/onboarding/neighborhood.svg` 와 같습니다.
- 검색 결과 없음은 Setup-1-empty 문구(`‘검색어’과 맞는 행정동이 없어요`)를 따르고, 조사(과/와)는 받침에 맞춰 고릅니다. 불러오지 못함은 시안이 없어 같은 모양에 문구만 바꿨습니다.
- 데스크톱 오른쪽 일러스트는 Start-T · Start-D · Setup-1/2/3-D 가 모두 같아 `public/onboarding/neighborhood.svg` 하나로 뽑았습니다.

## 홈 보고 진입 · 목 회원 상태 (S03 · Login-sheet · Consent-health-sheet)

- 보고는 건강정보 동의를 한 회원만 합니다. 홈의 보고 버튼(모바일 하단 · 태블릿 · 데스크톱 머리줄)은 모두 같은 함수를 부르고 회원 상태로 나뉩니다 (`features/home/report-gate.ts`).

  | 회원 상태 | 보고 버튼 | 열리는 것 |
  | --- | --- | --- |
  | 비회원 `guest` | `로그인하고 보고하기` | 로그인 안내 시트 `?report=login` |
  | 동의 안 한 회원 `member-no-consent` | `이번 주 건강 보고하기` | 증상 보고 동의 시트 `?report=health-consent` |
  | 동의한 회원 `member` | `이번 주 건강 보고하기` | 보고 흐름 `?report=start` (S05) |

- 두 시트는 보고 흐름의 앞 단계라 같은 쿼리 `?report=` 의 값으로 둡니다. 버튼으로 열 때는 기록을 쌓고(`push`) 닫기 · 휴대폰 뒤로 가기로 닫힙니다. 동의 시트에서 동의하면 값만 `start` 로 바꿔(`replace`) 뒤로 가기가 동의 시트를 건너뛰어 홈으로 갑니다. 다른 쿼리(`region` · `mock` 등)는 열고 닫아도 남습니다.
- 주소로 바로 들어온 값이 회원 상태에 맞지 않으면 기록을 쌓지 않고 맞는 시트로 바꿉니다: 비회원의 `?report=start`(보고 흐름 어느 단계든) · `health-consent` → `login`, 동의 안 한 회원의 보고 흐름 · `login` → `health-consent`, 동의한 회원의 `login` · `health-consent` → `start`. 보고 흐름과 보낸 보고 표시는 동의한 회원에게만 그립니다.
- 비회원 홈(Home-guest)은 동네 현황(상태 카드 · 공식 정보 · 증상별 변화 · 동네 안내)이 회원 홈과 같고, 자료 부족이면 수치 · 상태색을 숨기는 규칙도 같습니다. 모바일은 하단 버튼 위에 `로그인하면 이번 주 보고를 할 수 있어요`, 태블릿 · 데스크톱은 본문 맨 위(태블릿 격자 위 · 데스크톱 오른쪽 패널 맨 위)에 안내 상자 `로그인하면 이번 주 보고를 할 수 있어요. 동네 현황은 지금처럼 볼 수 있어요.` 를 둡니다.
- 둘러보기에서 온 `?region=<코드>` 는 `app/(home)/page.tsx` 가 아는 코드일 때 홈에 넘기고, 홈이 탭바 · 데스크톱 메뉴 링크 뒤에 붙입니다(`/?region=` · `/map?region=` · `/me?region=`).
- 로그인 안내 시트: `카카오로 계속하기` 는 `startKakaoLogin` 이 돌려준 주소(`/setup/region?from=kakao`)로 갑니다(보내는 중 꺼짐, 시작하지 못하면 시트 안 빨강 상자). `이메일로 시작하기` 는 이메일 로그인 `/login/email` 로 갑니다 — 홈을 둘러보다 보고하려는 사람은 이미 회원인 경우가 많고, 이메일 로그인 화면에 `이메일로 가입하기` 링크가 있어 처음인 사람도 바로 가입으로 갈 수 있습니다.
- 증상 보고 동의 시트: S02-4 와 같은 고지 표 · 체크 · 버튼(`features/auth/health-consent.tsx`)을 쓰고, 동의 값도 같습니다(`SENSITIVE_HEALTH_INFO` + 문서 버전). 체크해야 `동의하고 보고하기` 가 켜지고, 보내지 못하면 빨강 상자로 알린 뒤 다시 누를 수 있습니다. `나중에 할게요` 는 닫기입니다. 응답 전에 시트가 닫히면 늦은 응답으로 보고 흐름을 열지 않습니다(동의는 서버 · 목 세션에 남습니다).
- **목 회원 상태** (API 연동 전, `features/auth/auth-client.ts` · `use-mock-auth.ts`):
  - 정하는 순서: ① 주소 `?mock-auth=guest|member|member-no-consent`(QA 용 덮어쓰기, 모르는 값은 무시) ② `auth-client` 모듈 메모리의 목 세션 ③ 기본 `guest`.
  - 목 세션이 바뀌는 때: 카카오 가입 성공(S02-3) · 이메일 로그인 성공(S13-5, 이메일 가입 뒤 S02-3 의 로그인 포함) → `member-no-consent`, 건강정보 동의 성공(S02-4 · 동의 시트) → `member`, 내 정보(S10)의 동의 철회 → `member-no-consent`, 로그아웃 · 탈퇴 → `guest`. 화면 코드는 고치지 않습니다.
  - 새로고침하면 목 세션이 비어 `guest` 로 돌아갑니다(브라우저 저장소에 남기지 않음). 앱 안 이동(가입 · 로그인 · 동의 뒤 홈으로)에서만 이어집니다.
  - 서버는 목 세션을 몰라 첫 그림(하이드레이션)은 `guest` 로 그립니다. 목 세션은 새로고침하면 비므로 지금은 겉으로 드러나지 않지만, 연동 때 세션을 쿠키 등에서 읽으면 회원이 처음 그릴 때 잠깐 비회원 홈이 보일 수 있습니다 — 서버가 세션을 읽어 넘기도록 함께 바꿉니다.
  - 동의 시트에서 동의하면 `?mock-auth=` 덮어쓰기를 주소에서 지웁니다. 남겨 두면 동의한 뒤에도 미동의로 보여 보고 흐름이 다시 동의 시트로 바뀝니다. 지운 뒤에는 목 세션(`member`)을 따릅니다.
  - 목 로그인은 동의 여부를 몰라 이전에 동의했어도 `member-no-consent` 가 됩니다. 연동 때 서버 세션이 동의 상태를 알려 줍니다.
  - **연동 요구사항**: `useMockAuth` 의 `?mock-auth=` 덮어쓰기(와 내 정보의 `?mock-provider=`)는 실제 세션 연동 때 지웁니다. 남기면 주소만으로 회원 · 동의 확인을 건너뛰는 인가 우회가 됩니다.
- 후속 후보: 둘러보기에서 고른 `?region=` 을 로그인 안내 시트 → 가입 흐름의 S02-1 초기 선택으로 넘기기 (지금은 S02-1 에서 다시 고릅니다).
- 시안과 다르게 둔 것:
  - 두 시트는 공통 `Modal` 을 그대로 써서 모바일 시트의 줄 간격이 16(시안 14), 태블릿 · 데스크톱 대화상자 제목이 24(시안 22)입니다. 보고 흐름 · 판단 기준 시트와 같은 값입니다.
  - 태블릿 비회원 안내 상자는 격자 첫 줄(두 칸)이라 아래 간격이 28 입니다(시안은 본문 간격 24).
  - 카카오 버튼은 보내는 중 `disabled` 로 끕니다(S13-1 과 같음).

- 머리줄 보고 버튼(태블릿 · 데스크톱): 비회원 `로그인하고 보고하기` → `/login`, 회원 → 홈의 보고 진입 `/?report=health-consent`(미동의) · `/?report=start`(동의). 비로그인 안내 상자의 `로그인하고 보고하기` 도 `/login` 입니다.

- 비밀번호를 바꾸거나 정하고 돌아오면 알림(토스트) "비밀번호를 바꿨어요" · "비밀번호를 설정했어요. 이제 이메일로도 로그인할 수 있어요" 를 띄웁니다. 알림은 주소 쿼리가 아니라 내 정보 레이아웃(`app/me/layout.tsx` 의 `MeTrailProvider`)에 한 번 쓰는 값으로 넘기고, 내 정보가 하이드레이션 · 회원 판단 뒤 꺼내 띄우고 바로 비웁니다(비회원이면 띄우지 않고 비우기만). 레이아웃 메모리라 새로고침하면 사라집니다.
- 아직 없는 화면은 홈처럼 "○○ 화면은 준비하고 있어요" 알림을 띄웁니다: 닉네임 바꾸기 · 내 동네 바꾸기 · 관심 동네 · 알림 설정 · 보고 수정 · 최근 보고 내역 · 모으는 정보와 보관 기간 · 개인정보 처리방침 · 데이터 출처 · AI 사용 방식 · 머리줄의 동네 · 알림.
- **확인 대화상자** `?confirm=logout|consent-withdraw|withdraw`:
  - 메뉴 행(로그아웃 · 건강정보 동의 철회 · 회원 탈퇴)이 기록을 쌓아 엽니다(`useModalParam`). 취소 · 닫기 · Esc · 바깥 누르기 · 휴대폰 뒤로 가기로 닫힙니다.
  - 주소로 바로 들어온 값이 회원 상태와 맞지 않으면 열지 않고(첫 그림부터) 주소에서 지웁니다(effect 가 끝난 뒤 `setTimeout(0)`): 비회원의 `logout` · `withdraw` · `consent-withdraw`, 미동의 회원의 `consent-withdraw`. 모르는 값은 그대로 둡니다(아무 것도 열지 않음).
  - 보내는 중에는 두 버튼과 다른 확인 행(로그아웃 · 건강정보 동의 철회 · 회원 탈퇴)이 꺼지고(`aria-disabled`, 눌러도 아무 일 없음) 닫기 · Esc · 바깥 누르기를 막습니다. 실패하면 대화상자 안 빨강 상자(`role=alert`)로 알리고 다시 누를 수 있습니다. 보내는 중에 휴대폰 뒤로 가기로 대화상자를 닫은 뒤 실패하면 같은 문구를 내 정보 알림(토스트)으로 띄웁니다.
  - 성공하면 목 세션이 먼저 바뀌고(화면과 무관), 화면이 떠 있으면 홈 `/`(region 만 남김)으로 **기록을 바꿔** 갑니다 — 뒤로 가기로 대화상자에 돌아오지 않습니다. 이동한 주소에는 `?mock-auth=` · `?mock-provider=` 가 없어 결과(로그아웃 → 비회원 홈 등)가 그대로 보입니다. 세션이 먼저 바뀌어도 이동할 때까지 대화상자는 열린 채 꺼져 있습니다.
  - 동의 철회 뒤 이동할 곳은 원래 "동의 철회 직후 홈"(Home-purging, 다음 이슈)입니다. 지금은 홈으로 가고, Home-purging 이 생기면 `me-screen.tsx` 의 이동을 바꿉니다.
- **목 프로필** (`features/auth/auth-client.ts` 의 `MockProfile`): 로그인 방법 · 이메일 · 닉네임 · 비밀번호가 있는지(`hasPassword` — 이메일 회원 true, 카카오 가입 false, 비밀번호 설정에 성공하면 true)만 둡니다. 이메일 로그인은 입력한 이메일(닉네임은 그 이메일로 가입할 때 받은 값, 없으면 예시 `동네지기`), 카카오 가입은 예시 `dong@kakao.com` · `동네지기` 입니다. 로그아웃 · 탈퇴하면 지웁니다. 동의 철회는 동의한 회원 세션일 때만 `member-no-consent` 로 바꿉니다 — `?mock-auth=member` 덮어쓰기로 비회원 세션에서 철회하면 세션은 비회원 그대로이고 홈은 비회원 홈입니다. QA 덮어쓰기 `?mock-provider=email|kakao`: 세션 프로필의 방법이 같으면 그 프로필, 다르거나 세션이 없으면(`?mock-auth=` 만 있을 때) 그 방법의 예시 프로필(시안 값)입니다.
- 목 재현 입력(프로필 이메일로 가립니다 — 그 이메일로 이메일 로그인한 뒤 엽니다. 동의 철회는 홈에서 동의까지 한 뒤): 로그아웃 `logout-fail@example.com`, 동의 철회 `consent-withdraw-fail@example.com`, 탈퇴 `withdraw-fail@example.com` → 응답을 받지 못함(세션 그대로, 다시 눌러도 계속 실패).
- **연동 요구사항**:
  - 프로필은 `GET /api/v1/members/me`(백엔드 #58)로, 세 동작은 `POST /api/v1/auth/logout`(#57) · 건강정보 동의 철회(#59) · `POST /api/v1/members/me/withdraw`(#59)로 `auth-client.ts` 함수 안만 바꿉니다. 서버 첫 그림은 #81 처럼 비회원이라 연동 때 서버가 세션을 읽어 넘기도록 함께 바꿉니다.
  - `?mock-provider=` 덮어쓰기를 지웁니다(`?mock-auth=` 와 같은 이유).
  - **동의 철회 뒤 세션**: 백엔드 #59 는 철회와 함께 refresh 세션을 모두 폐기하고 요청 기기 access token 도 막습니다(시안 문구도 "모든 기기에서 로그아웃돼요"). 목은 Home-purging(회원으로 보이는 "보고를 지우는 중" 홈)을 위해 `member-no-consent` 로 둡니다. 연동 전에 철회 직후 이 기기가 로그인 상태로 남는지(보고 권한 없는 토큰 재발급 등) 백엔드와 정하고, 로그아웃이면 이동할 곳을 비회원 홈으로 바꿉니다.
- 시안과 다르게 둔 것:
  - 지어낸 수치 · 상태는 비웁니다: 로그인한 기기 `3대` · 관심 동네 `2곳` · 이번 주 보고 수정 `증상 있음` 은 값 없이 화살표만 둡니다(서버 값이 생기면 채웁니다). `52주` · `질병관리청 · SGIS` · `안내문 초안만` 처럼 정해진 사실은 그대로 둡니다.
  - 알림 스위치는 시안(켜짐)과 달리 **꺼진 모양**(Settings-nopush 의 회색)(`aria-checked=false` · `aria-disabled`, 설명은 `aria-describedby`)이고 누르면 "알림 설정 화면은 준비하고 있어요" 입니다. PWA 푸시는 2단계 기능이라 구독하지 않는데 켜진 것처럼 보이면 받지 않는 알림을 받는다고 오해합니다. 미지원 환경 안내(Settings-nopush)는 아래 "홈 화면 추가 · 알림 미지원" 에 있습니다.
  - 미동의 회원(시안 없음)은 회원 화면에서 `내 보고` 섹션(과 데스크톱 메뉴 항목)을 빼고, `건강정보 동의 철회` 자리에 `건강정보 동의하기`(`동의하면 이번 주 보고를 할 수 있어요`)를 두어 홈의 증상 보고 동의 시트 `/?report=health-consent` 로 보냅니다.
  - 데스크톱 설정 메뉴는 시안의 `#` 링크 대신 기록을 쌓지 않는 버튼입니다. 누르면 섹션으로 옮기고 그 제목에 포커스를 줍니다(`#` 링크는 대화상자 닫기를 깨뜨림, `docs/conventions.md`). 시안의 선택 표시(첫 항목 회색 바탕)는 스크롤 위치를 따라가지 않아 두지 않았습니다.
  - 확인 대화상자는 공통 `Modal` 을 써서 태블릿 · 데스크톱에 닫기 버튼(머리줄)이 있고 제목이 24 입니다(시안은 머리줄 없음 · 22). 모바일 시트는 머리줄을 숨깁니다(`compactSheet`). 실패 문구("○○하지 못했어요. 잠시 뒤 다시 시도해 주세요.")는 시안에 없어 더했습니다.
  - 긴 값(긴 이메일)은 제목을 줄이지 않고 값만 한 줄로 자릅니다(`truncate`). 보조기술은 전체를 읽고, 마우스를 올리면 `title` 로 전체가 보입니다.
  - 모바일 머리줄 높이는 56(시안), 태블릿 제목 왼쪽 여백 20(시안)입니다. 홈 머리줄과 다르므로 `AppHeader` 의 `title` 이 있을 때만 이 값을 씁니다.
  - 탈퇴 사유 · 자유 서술 칸은 시안에도 없고 만들지 않습니다. 아동 대리 보고 · 가족 · 그룹 메뉴도 없습니다.

## 로그인한 기기 · 비밀번호 (S10 Settings-devices · Settings-password)

- 회원만 봅니다. 비회원이 주소로 들어오면 아무 것도 그리지 않고 `/login` 으로 기록을 바꿔 갑니다(`features/me/member-gate.ts`). 서버 · 하이드레이션 첫 그림의 회원 상태는 늘 `guest` 라 **하이드레이션을 마친 뒤의 상태로만** 판단합니다(`src/lib/use-hydrated.ts`) — 첫 그림으로 판단하면 연동 뒤 회원이 튕깁니다.
- 셸(`features/me/account-page-layout.tsx`): 모바일은 머리줄 56(뒤로 · 제목 17) + 아래 고정 버튼, 탭바 없음. 태블릿은 머리줄 72(뒤로 · 제목 20 · 알림 · 보고 버튼, 아래 구분선) + 가운데 560 + 탭바. 데스크톱은 홈과 같은 머리줄 + 가운데 560(`내 정보로 돌아가기` · 제목 26 · 본문), 왼쪽 설정 메뉴는 없습니다. 아래 버튼은 태블릿 · 데스크톱에서 본문 바로 아래(위 8)입니다.
- `?region=` 은 `/me` 처럼 받아 탭바 · 메뉴 · 보고 진입 · 돌아가는 주소에 남깁니다. 내 정보 행 · 돌아가기 주소는 QA 덮어쓰기(`?mock-auth=` · `?mock-provider=`)도 남깁니다 — 빠지면 하위 화면에서 비회원으로 보여 로그인으로 튕깁니다(연동 때 함께 지웁니다).
- **뒤로**(모바일 · 태블릿 머리줄, 데스크톱 `내 정보로 돌아가기`): 앱 안에서 `/me` 를 거쳐 왔으면 `router.back()`, 주소로 바로 들어왔으면 `/me`(동네 · 덮어쓰기를 남김)로 `router.replace`. 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 `/me` — `MeTrailProvider` 의 `goBack` 이 감쌈, docs/conventions.md "화면의 뒤로"). 기록이 루트에 있어 `/me/devices` → 탭바 홈 → 휴대폰 뒤로 → 머리줄 뒤로에서도 기록을 되돌립니다.
- 머리줄의 동네 · 알림은 내 정보처럼 "준비하고 있어요" 알림입니다.

**로그인한 기기 `/me/devices`**

- 안내 "모르는 기기가 있으면 로그아웃해 주세요." → 목록(이 기기를 맨 위, 나머지는 마지막 사용이 최근인 순서) → `다른 기기에서 모두 로그아웃`. 이 기기는 배지 `이 기기` · "지금 사용 중" 이고 로그아웃 버튼이 없습니다(이 기기 로그아웃은 내 정보의 `로그아웃`). 다른 기기는 "마지막 사용 11월 20일 21:14"(한국 시각, `formatMonthDayTime`) · `로그아웃`.
- **기기 이름 · 마지막 사용 시각만 보입니다.** IP · 접속 지역 · 위치는 받지도 그리지도 않습니다(시안에도 없음).
- 불러오는 중: 늘 그려 둔 안내 영역(`role=status`)에 "기기 목록을 불러오고 있어요". 불러오지 못함: 빨강 상자 "기기 목록을 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요." + `다시 시도`.
- 시안에 확인 단계가 없어 누르면 바로 보냅니다. 보내는 중에는 로그아웃 버튼이 모두 꺼집니다(`aria-disabled`, 한 번에 하나). 성공하면 목록에서 빼고 알림 "○○에서 로그아웃했어요" · "다른 기기에서 모두 로그아웃했어요" 를 띄운 뒤 목록으로 포커스를 옮깁니다(누른 버튼이 사라짐). 실패하면 목록 아래 빨강 상자 "로그아웃하지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다. 응답 전에 화면을 떠나면 늦은 응답은 버립니다(서버 · 목 서버에서는 이미 끝난 일).
- 다른 기기가 없으면 `다른 기기에서 모두 로그아웃` 을 숨깁니다(시안에 없는 상태).
- 목 데이터(`auth-client.ts` 의 `EXAMPLE_DEVICE_SESSIONS`)는 시안의 예시 기기(iPhone · Safari 이 기기, Mac · Chrome, Galaxy · 삼성 인터넷)입니다. **기기 이름 · 시각은 예시 값**이고 지금 쓰는 기기와 무관합니다. 로그아웃 · 탈퇴로 비회원이 되면 목록을 지워 다음 로그인은 예시 목록부터입니다.
- 목 재현 입력(프로필 이메일 — 그 이메일로 이메일 로그인한 뒤 엽니다): 목록 `sessions-fail@example.com` → 불러오지 못함, 로그아웃(한 기기 · 모두) `session-revoke-fail@example.com` → 로그아웃하지 못함(목록 그대로, 다시 눌러도 계속 실패).

**비밀번호 변경 · 설정 `/me/password`**

- 비밀번호가 있는 회원(이메일 회원 · 설정을 마친 카카오 회원): `비밀번호 변경` — 현재 비밀번호 · 새 비밀번호(도움말) · 새 비밀번호 확인 · `비밀번호 바꾸기` · `비밀번호를 잊었어요`(→ `/password/reset`).
- 비밀번호가 없는 카카오 회원: `비밀번호 설정` — 안내 "비밀번호를 정하면 이메일로도 로그인할 수 있어요." · 비밀번호 · 비밀번호 확인 · `비밀번호 설정하기`. 현재 비밀번호 칸과 `비밀번호를 잊었어요` 는 없습니다.
- 규칙 · 문구는 S13-4 · S13-6 과 같습니다 — 도움말 "8~20자 · 영문과 숫자 포함 · 띄어쓰기 없이", 오류 "영문과 숫자를 함께 8~20자로, 띄어쓰기 없이 써 주세요." · "비밀번호가 서로 달라요." 오류는 버튼을 누를 때 처음 보이고 그 뒤 고칠 때마다 다시 판단합니다. 빈 칸이 있으면 버튼이 꺼져 있습니다. 새 비밀번호가 현재와 같아도 막지 않습니다(백엔드 계약에 없음).
- 현재 비밀번호가 맞지 않으면 그 칸 아래 "현재 비밀번호가 맞지 않아요." 를 보이고 그 칸으로 포커스를 옮깁니다(칸을 고치면 지움). 보내지 못하면 빨강 상자 "비밀번호를 바꾸지(설정하지) 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다.
- 보내는 중에는 칸이 읽기 전용, 버튼 · 뒤로 · `비밀번호를 잊었어요` 가 꺼집니다(`aria-disabled`). 응답 전에 화면을 떠나면 늦은 응답으로 이동하지 않습니다(설정 성공은 목 프로필에 먼저 남습니다).
- 성공하면 칸을 비우고 알림(`password-changed` · `password-set`)을 내 정보 레이아웃에 남긴 뒤 내 정보로 갑니다. `/me` 에서 왔으면 `router.back()`(기록에 `/me` 가 두 번 남지 않아 휴대폰 뒤로 가기가 헛돌지 않음), 주소로 바로 들어왔거나 레이아웃이 다시 마운트됐으면 `/me`(동네 · 덮어쓰기를 남김)로 **기록을 바꿔** 갑니다. 어느 쪽이든 뒤로 가기로 이 화면에 돌아오지 않습니다. 설정에 성공하면 목 프로필이 먼저 바뀌지만 이동할 때까지 화면은 설정 모양 그대로입니다.
- **비밀번호는 그 화면 상태에만 둡니다**(Provider · 목 세션 · 주소 · 로그 · 브라우저 저장소 금지). 내 정보에 넘기는 알림에는 무슨 일을 마쳤는지만 넣습니다.
- 목 재현 입력: 현재 비밀번호 `wrong` → 맞지 않음(로그인 목과 같은 값). 프로필 이메일 `password-fail@example.com` 이거나 새 비밀번호 `fail2026` 이면 보내지 못함(카카오 예시 프로필은 이메일이 정해져 있어 설정 실패는 `fail2026` 으로 재현합니다). `?mock-provider=kakao` 덮어쓰기로 연 카카오 화면은 설정에 성공해도 내 정보 행이 `비밀번호 설정` 그대로입니다(덮어쓰기의 예시 프로필은 바뀌지 않음) — 행이 바뀌는 것은 카카오 가입으로 만든 목 세션에서 확인합니다.

**연동 요구사항 · 백엔드와 정할 점**

- 기기: `GET /api/v1/auth/sessions` · `DELETE /api/v1/auth/sessions/{sessionId}`(#57). 응답에 세션 id · 기기 이름(User-Agent 로 만든 `Mac · Chrome` 꼴) · 마지막 사용 시각 · 이 기기인지(`current`)가 있어야 합니다. **IP · 지역은 응답에 넣지 않기를 요청합니다**(화면은 쓰지 않음). `current` 는 늘 포함해 주기를 요청합니다(이 기기를 가리고 로그아웃 버튼을 빼는 데 씀). 이미 없는 세션 삭제는 성공으로 봅니다.
- `다른 기기에서 모두 로그아웃`: #57 에 한 번에 지우는 API 가 없습니다. 한 번에 지우는 엔드포인트(예: 이 기기를 뺀 세션 전부 폐기)를 요청합니다 — 없으면 화면이 기기마다 `DELETE` 를 보내야 하고 일부만 실패할 수 있습니다(지금 화면은 전부 성공 · 전부 실패만 다룹니다).
- 비밀번호: 변경 `POST /api/v1/members/me/password`(현재 + 새 비밀번호), 설정 `POST /api/v1/members/me/password/setup`(#58). 현재 비밀번호 틀림 오류 코드, 틀림 횟수 제한 여부, 이미 비밀번호가 있는데 설정을 부르면 어떤 응답인지, `GET /me` 가 `hasPassword`(또는 같은 뜻의 값)를 주는지 정해야 합니다.
- 비밀번호를 바꾸거나 정한 뒤 **다른 기기 세션을 폐기할지** 정해야 합니다(재설정은 api-contract-draft 에서 검토 중). 폐기하면 화면에 "다른 기기에서는 로그아웃돼요" 같은 안내를 더해야 합니다 — 지금 시안 · 화면에는 없습니다.
- `비밀번호를 잊었어요` 는 로그인한 상태에서 비로그인용 재설정 흐름(`/password/reset`)으로 가고, 마치면 이메일 로그인 화면에 닿습니다. 회원용 재설정이 따로 필요한지 정합니다.

**후속 후보**

- 비회원 가드가 로그인 뒤 돌아올 곳(returnTo)을 넘기기. 지금은 `/login` 으로만 보내 로그인 뒤 홈으로 갑니다.

**시안과 다르게 둔 것**

## 약관 재동의 · 폐지된 동네 다시 고르기 (S02-3 Setup-3-reconsent · S02-1 Setup-1-reselect)

- 다시 들어온 **회원**이 홈(`/`) · 내 정보(`/me` · `/me/devices` · `/me/password`)에 들어오면 조건을 보고 먼저 보냅니다. 순서는 **약관 재동의 → 동네 다시 고르기**입니다(법적 동의가 먼저). 비회원은 보내지 않습니다. 홈은 `HomeScreen`, 내 정보는 `app/me/layout.tsx` 가 같은 가드(`features/me/member-gate.ts` 의 `useRequiredStepsGate`)를 씁니다.
- 가드는 **하이드레이션을 마친 뒤**에만 판단하고 Next 라우터로 기록을 바꿔 갑니다(앱 안 이동 기록을 거치는 `useNavTrail().replace`). 조건이 남아 있으면 뒤로 가기로 홈에 돌아와도 다시 보냅니다. 두 화면도 하이드레이션 뒤에 판단해, 비회원이거나 그 화면의 조건이 없으면 그리지 않고 남은 조건 화면이나 돌아갈 곳으로 보냅니다(동네 화면에 왔는데 재동의가 남았으면 재동의로).
- **쿼리**
  - `?reselect=1`: `/setup/region` 을 가입 동네 선택 대신 다시 고르기로 엽니다(`?from=kakao` 와 함께 오면 다시 고르기가 먼저).
  - `?next=<경로>`: 마친 뒤 돌아갈 곳. **허용 목록**(`/` · `/me` · `/me/devices` · `/me/password`)과 정확히 같을 때만 따르고 그 밖(쿼리가 붙음 · `//evil` · `https://…` 등)은 홈입니다(`features/auth/required-steps.ts` 의 `safeNextPath`, 오픈 리다이렉트 방지). 홈이면 붙이지 않습니다.
  - 넘기는 쿼리는 둘러보기 동네(`region`)와 목 덮어쓰기(`mock-auth` · `mock-provider` · `mock-required`)뿐입니다. 열린 시트(`report` 등)는 버립니다.
  - `?mock-required=terms|region|terms,region`: QA 용 조건 덮어쓰기입니다. 있으면 목 프로필의 조건 대신 이 값을 씁니다(회원일 때만 — 비회원은 `?mock-auth=` 와 함께 엽니다). 동네 조건의 옛 동네는 프로필에 폐지된 동네가 없으면 시안 예시 `○○1동` 입니다. 한 화면을 마치면 그 조건을 이 쿼리에서 빼고 이동합니다(다 빠지면 쿼리를 지움) — 남기면 마친 화면으로 다시 돌아옵니다.
- 가드가 보낼 곳이 있으면 같은 그림에서 주소 정리(홈의 맞지 않는 `?report=` · 내 정보의 맞지 않는 `?confirm=`)를 하지 않습니다. 원시 history 를 바꾸면 Next 가 대기 중인 가드 이동을 버려 조건 화면을 건너뜁니다(프로덕션 빌드에서 재현, `docs/conventions.md`). 정리는 조건을 마치고 돌아온 뒤에 합니다.
- 재동의를 마쳤는데 동네 조건이 남았으면 다시 고르기로 이어 가고, 다 마치면 `next` 로 갑니다. 다음 화면은 목 프로필을 바로 읽어 정합니다(`targetAfter`). 모든 이동은 기록을 바꿔 가서(replace) 뒤로 가기로 두 화면에 돌아오지 않습니다.

**약관 재동의 `/terms/reconsent`**

- `바뀐 약관을 확인해 주세요` · `12월 1일부터 아래 내용이 바뀌어요.` · 회색 상자(`[필수] 서비스 이용약관` · `전문 보기` · 바뀐 내용) · 체크 `바뀐 서비스 이용약관에 동의해요` · `동의하고 계속하기`. 단계 표시 · 뒤로가 없습니다. 데스크톱 오른쪽 문구는 "바뀐 내용만 다시 여쭤볼게요".
- 시행일 · 바뀐 내용은 `features/auth/legal.ts` 의 `TERMS_REVISION` 이고 **시안 예시 문구**입니다(52주는 확정 값). 실제 개정 때 `TERMS_VERSION` 을 올리고 함께 바꿉니다. 동의는 지금 버전(`TERMS_OF_SERVICE` + `LEGAL_VERSIONS.TERMS_OF_SERVICE`)으로 보냅니다(`agreeTermsReconsent`).
- `전문 보기` 는 본문이 없어 "약관 본문을 준비하고 있어요" 알림입니다(가입 동의와 같음).
- 아래 보조 버튼 `동의하지 않고 로그아웃`(**시안에 없는 기본안 — 기획 확인 필요**): 로그아웃(`logout`, #92 목)을 보내고, 성공하면 목 세션이 먼저 비회원이 된 뒤 화면이 떠 있으면 홈 `/`(넘길 쿼리 중 `region` 만 남김)으로 기록을 바꿔 갑니다. 체크와 무관하게 누를 수 있습니다. 실패하면 빨강 상자 "로그아웃하지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다(재현: `logout-fail@example.com` 로 로그인한 뒤 `?mock-required=terms`).
- 체크 전에는 버튼이 꺼져 있습니다(`aria-disabled`, 포커스는 남음). 동의 · 로그아웃은 한 번에 하나만 보냅니다(보내는 중이면 두 버튼 모두 꺼짐). 보내는 중에는 버튼이 꺼지고 체크를 바꾸지 않습니다(한 번만 보냄). 실패하면 빨강 상자(`role=alert`) "약관 동의를 보내지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다. 성공하면 목 프로필의 재동의 표시가 먼저 꺼지고(화면과 무관), 화면이 떠 있을 때만 이동합니다.

**폐지된 동네 다시 고르기 `/setup/region?reselect=1`**

- `동네를 다시 골라 주세요` · 안내 상자 "고르셨던 ○○1동이 행정구역 개편으로 바뀌었어요. 지금 사는 행정동을 다시 골라 주세요."(옛 동네 이름, 조사 이/가는 받침으로) · 검색 칸 · 목록 · `이 동네로 바꾸기`. 단계 표시 · 뒤로가 없습니다. 데스크톱 오른쪽 문구는 "행정구역이 바뀌면 다시 여쭤볼게요". **위치 권한을 요청하지 않습니다.**

- 후보를 불러오는 중 "후보 동네를 불러오고 있어요", 불러오지 못하면 "후보 동네를 불러오지 못했어요 / 동 이름으로 검색해 주세요.", 후보가 없으면 같은 자리 · 모양으로 "후보 동네가 없어요 / 동 이름으로 검색해 주세요." 를 늘 그려 둔 안내 영역에 보입니다.
- 후보 목 데이터(`features/region/mock.ts` 의 `ABOLISHED_DISTRICT_EXAMPLE` · `RESELECT_CANDIDATE_MOCKS`)는 **시안 예시 값**(옛 `○○1동`, 후보 `○○새1동` · `○○새2동` · `○○2동`)이고 코드는 실제와 겹치지 않게 지어낸 값입니다. 검색 목에는 넣지 않았습니다.

**목 상태 · 재현 입력** (`features/auth/auth-client.ts`)

- 목 프로필에 `region`(내 동네 — 가입 마무리의 동네 저장이 채움, 가입 없이 이메일 로그인하면 모름 `null`) · `regionAbolished` · `termsReconsentRequired` 를 더했습니다. 동네를 모르는 회원은 다시 고르게 하지 않습니다.
- 프로필 이메일로 조건을 켭니다(그 이메일로 `/login/email` 에서 로그인하면 홈이 바로 보냄): `reconsent@example.com` → 재동의, `reselect@example.com` → 동네 폐지(옛 동네 `○○1동`). 실패 재현: `reconsent-fail@example.com` → 재동의 거부, `reselect-fail@example.com` → 동네 저장 거부(조건도 켜짐, 다시 눌러도 계속 실패. 이 이메일로 가입하면 S02-3 의 동네 저장도 실패).
- 조건은 로그인할 때 이메일로 켜므로 `reconsent@` · `reselect@` · `*-fail@` 로 **가입해도 가입 직후 조건이 켜집니다**(이메일 가입은 가입 뒤 같은 이메일로 로그인한다). 동네 조건은 가입 마무리의 동네 저장이 바로 끕니다(`reselect-fail@` 은 그 저장이 실패).
- 덮어쓰기만으로 보기: `/?mock-auth=member&mock-required=terms,region`, `/me/devices?mock-auth=member&mock-required=region` 등. **`?mock-required=` 는 프로필 조건을 대신합니다(합치지 않음)** — 예를 들어 `reconsent@` 로 로그인한 뒤 `?mock-required=region` 이면 재동의 없이 동네 다시 고르기만 거칩니다. 조건을 마쳐 쿼리가 다 빠지면 그때부터 프로필 조건을 따릅니다.

**연동 요구사항 · 백엔드와 정할 점**

- **조건을 어디서 받는지**(#59 · #60): 회원의 동의 버전이 지금 `legal.*-version` 보다 낮은지, 내 동네 코드가 폐지됐는지를 로그인 응답 또는 `GET /api/v1/members/me` 가 알려 주기를 요청합니다(예: `requiredConsents: ['TERMS_OF_SERVICE']`, `region: { code, name, abolished }`). 화면은 이 두 값과 옛 동네 이름만 씁니다.
- **재동의 API**(#59): 요청에 `{ type, documentVersion }`(가입과 같은 모양)을 보냅니다. 경로 · 응답 · 이미 최신 버전이면 성공으로 볼지 정해야 합니다. `AGE_OVER_19` 는 이용약관 버전을 같이 쓰므로(`legal.ts`) 이용약관을 올리면 성인 확인도 다시 받아야 하는지 정합니다 — 지금 화면은 이용약관만 다시 받습니다.
- **재선택 후보**(#60): "폐지된 코드면 재선택 유도 응답" 이 이어 받은 동네 후보(코드 · 이름 · 시군구 · 옛 동네 일부인지)를 함께 주는지, 따로 묻는 API 가 있는지 정합니다. 시안의 `○○2동` 처럼 이어 받지 않은 후보를 줄 기준도 정합니다. 동네 다시 저장은 가입과 같은 설정 API 를 쓰고, 고른 코드가 또 폐지된 코드면 오류로 돌려주기를 요청합니다.
- **기획 · 법무와 정할 점**: 재동의 화면의 출구를 `동의하지 않고 로그아웃` 으로 둘지(지금 기본안). 탈퇴 · 건강정보 동의 철회는 로그인 상태가 필요한 내 정보 안에 있어 **재동의를 마친 뒤에만 갈 수 있습니다** — 개정 약관에 동의하지 않는 회원이 동의 없이 탈퇴 · 보고 파기를 요청할 길이 필요한지(예: 재동의 화면에서 탈퇴로 가기, 가드가 탈퇴 대화상자만은 통과시키기) 정해야 합니다.
- `?mock-required=` 덮어쓰기는 실제 세션 연동 때 `?mock-auth=` 와 함께 지웁니다(남기면 주소만으로 조건 화면을 열거나 건너뛸 수 있음).

**시안과 다르게 둔 것**

- 두 화면 모두 시안처럼 뒤로 버튼이 없지만, 머리줄 자리(44)는 동네 선택처럼 비워 둡니다. 태블릿에서 서비스명이 그 칸 뒤에 놓입니다(시안은 맨 왼쪽).
- 시안의 동네 목록은 `aria-pressed` 버튼이지만 동네 선택처럼 라디오입니다(하나만 고름). 시안의 검색 칸에 미리 들어 있는 `○○` 은 넣지 않고, 빈 검색어일 때 후보를 보입니다.
- 시안의 `전문 보기` 는 `#terms` 링크지만 본문이 없고 같은 문서 `#` 링크를 쓰지 않아 버튼입니다(`docs/conventions.md`).
- 버튼은 고르기 · 체크 전에 꺼진 모양(`aria-disabled`)입니다(시안은 켜진 장면만 있음). 보내지 못함 · 후보를 불러오는 중 · 불러오지 못함은 시안에 없어 더했습니다.
- 재동의 화면 아래 `동의하지 않고 로그아웃` 은 시안에 없는 기본안입니다(**기획 확인 필요**). 다시 고르기에는 나가는 길이 없습니다(동네가 없으면 보고를 셀 수 없음). 둘 다 마쳐야 홈 · 내 정보를 씁니다.
- 후보 없음 안내는 시안에 없어 더했습니다.

## 공식 정보 (S08)

- `/official` 은 비회원도 봅니다. 화면 조립은 `features/official/official-screen.tsx`, 데이터 모양은 `features/official/types.ts` 입니다. **질병관리청 자료만 그립니다** — 시민 자가보고 값(참여 · 증상 비율 · 상태)은 타입에도 화면에도 없고, 차이 안내 상자가 두 정보가 다르다는 것만 알립니다.
- 출처 · 집계 단위 · 기준 주: 본문 맨 위 줄에 `공식` 배지 + "전국 · 47주 · 11월 21일 발표"(모바일) / "전국 · 11월 17일~23일 · 11월 21일 발표"(태블릿 · 데스크톱)를 둡니다. 출처는 제목 "질병관리청 발표" 가 밝힙니다. 기준 주 표기는 시안대로 폭마다 다릅니다(주차 · 기간).
- 구성: 모바일은 머리줄 56(뒤로 · 제목 17) → 출처 줄 → 단계(감염병 · 발표 단계) → 쉬운 요약 → 짧은 차이 안내 → `원문 보기`, 탭바 · 아래 버튼이 없습니다. 태블릿은 머리줄 72(뒤로 · 제목 20 · 알림 · 보고 버튼) → 가운데 640(출처 줄 → 제목 28 → 단계 → 요약 → `원문 보기` → 긴 차이 안내 "시민 자가보고와 무엇이 다른가요?") → 탭바. 데스크톱은 홈과 같은 머리줄 → 가운데 1080(뒤로 → 왼쪽 본문 + 오른쪽 360 차이 안내)입니다.
- `원문 보기` 는 바깥 주소를 새 창으로 엽니다(`rel="noopener noreferrer"`, 이름 "원문 보기 (새 창)").
- **받은 발표가 없을 때**(시안 없음): 출처 줄은 집계 단위(전국)만 두고, 단계 · 요약 자리에 "아직 받은 발표가 없어요" · "질병관리청이 주간 발표를 내면 여기에서 보여 드려요." 를 둡니다. `원문 보기` 는 없고, 차이 안내는 조사 방식(표본감시 등)을 빼고 "질병관리청 발표는 … 달라요." 로 씁니다. 기준 주 · 단계 · 요약 필드는 이 상태의 타입에 없습니다.
- **목 데이터**(`features/official/mock.ts`, 연동 이슈에서 지웁니다): `?mock=published` 는 시안의 예시 발표, `?mock=empty` 와 값이 없거나 모르는 값은 받은 발표 없음입니다 — 실제 자료가 없는 지금 발표를 지어내 보이지 않는 쪽이 기본값입니다. 홈의 두 진입점(공식 정보 행 · 동네 안내의 `공식 예방수칙 보기`)은 홈 목 데이터의 예시 발표("전국 인플루엔자 유행주의보")와 맞게 `/official?mock=published` 로 갑니다(홈 목 `OFFICIAL.href`). 예시 값의 날짜 · 주차는 지금과 무관하고, 원문 주소는 질병관리청 감염병포털 첫 화면입니다.
- 홈과 이음: 홈의 공식 정보 행(모바일 띠 사이 · 태블릿 이상 머리줄 아래)과 동네 안내가 발행 전일 때의 `공식 예방수칙 보기` 가 **같은 주소**(`features/home/official.tsx` 의 `officialHref` — 공식 정보 주소 + 둘러보기 동네 `?region=`)로 이 화면에 갑니다. 이 화면도 `?region=` 을 받아 머리줄 동네 이름 · 탭바 · 메뉴 · 뒤로 · 보고 진입 주소에 남깁니다(공식 자료는 동네와 무관합니다).
- **뒤로**(모바일 · 태블릿 머리줄, 데스크톱 `질병관리청 발표` — 이름 "뒤로, 질병관리청 발표"): 앱 안에서 다른 화면(홈 · 동네 안내 등)을 거쳐 왔으면 `router.back()`, 주소로 바로 들어왔으면 홈(동네를 남김)으로 `router.replace` 합니다. 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 없음 — docs/conventions.md "화면의 뒤로"). 바깥 사이트에서 링크로 들어오거나 새로고침 · 새 탭으로 열면 앞 기록이 없어 뒤로가 사이트 밖으로 나가지 않습니다. 바로 연 뒤 홈을 거쳐 가드 · 로그인 만료로 다른 화면에 replace 됐다가 휴대폰 뒤로로 돌아와도 같습니다(앱 안 replace 가 모두 기록을 거침).
- 머리줄 보고 버튼은 내 정보와 같이 회원 상태로 갈 곳을 고릅니다(`reportHrefFor` — 비회원 `/login` · 회원은 홈의 보고 진입). 비회원은 버튼 글자가 `로그인하고 보고하기` 입니다. 동네 · 알림은 "준비하고 있어요" 알림입니다. 재동의 · 동네 다시 고르기 가드(`useRequiredStepsGate`)는 걸지 않습니다 — 공개 정보라 비회원과 같은 내용을 봅니다.

**연동 요구사항 · 백엔드와 정할 점**

- 초안 `GET /api/official/latest`(docs/api-contract-draft.md)에 화면이 쓰는 값: 집계 단위(지역 이름) · 기준 주(질병관리청 주차와 기간 시작 · 끝 날짜) · 발표일 · 감염병 이름 · 조사 방식(표본감시 · 전수신고) · 발표 단계 · 쉬운 요약 문장 · 원문 주소. 백엔드 #83~#85 의 `official_surveillance` 는 수치(분율 · 신고 수)와 기간 · 수집 시각만 담습니다 — **발표 단계("유행주의보 발령 중")와 쉬운 요약의 출처가 스키마에 없습니다.** 단계는 질병관리청 발표 원문의 값(주의보 발령 · 해제)을 어디서 받을지, 요약은 누가 쓰는지(AI 는 출처가 확인된 집계값을 옮기는 초안에만 쓰고 운영자가 검토해야 합니다 — 루트 CLAUDE.md) 정해야 합니다. 정하기 전에는 단계 · 요약 없이 수치만 보이는 모양(시안 없음)이 필요할 수 있습니다.
- 받은 발표가 없을 때의 응답(204 · `null` · 빈 목록)을 정합니다. 화면은 `empty` 하나로 받습니다.
- 표본감시(인플루엔자 분율) · 전수신고(발생 수)가 함께 오면 화면에 무엇을 몇 개 보일지 정합니다. 지금 화면은 감염병 하나 · 단계 하나입니다. 공공누리 제4유형이라 원값을 그대로 보이고, 파생값(전주 대비 등)을 보이면 파생값임을 밝혀야 합니다(backend entity-design §3-2).
- 수집 시각(`synced_at`)을 화면에 보일지 정합니다(시안에는 없음).

**시안과 다르게 둔 것**

- 태블릿 · 데스크톱의 단계 글자와 `쉬운 요약` 제목은 19px 대신 20px(`text-screen-title`)입니다 — 19px 토큰이 없습니다. 동네 안내(Guide-*-T · -D)의 h2 도 19px 라 함께 토큰을 둘지 정합니다.

- 받은 발표가 없을 때 · 데스크톱 뒤로의 이름은 시안에 없어 더했습니다.

## 동네 안내 (S07 · Guide-published · Guide-corrected · Guide-none)

- 주소 `/notice/[region]/[week]`: `[region]` 은 행정동 코드(SGIS 8자리, `features/region` 과 같음), `[week]` 는 기준 주 ISO 주 `YYYY-Www`(월요일 시작, 백엔드 `iso_week` 와 같은 모양, 예: `2025-W47`)입니다. 모양이 틀리거나 그 해에 없는 주(`W00` · `W54` · 53주가 없는 해의 `W53`)이거나 모르는 동네면 404 입니다(`features/notice/paths.ts` 의 `parseNoticeRoute`) — 안내 없음으로 보이면 그런 동네 · 주가 있는 것처럼 읽힙니다.
- 기준 주 문구는 주소의 주로 만듭니다(`src/lib/iso-week.ts`): 모바일 `11월 3주 기준`(그 주 목요일이 든 달의 몇째 주), 태블릿 이상 `11월 17일~23일 기준`(달이 바뀌면 `10월 27일~11월 2일`). 발행일 · 정정일은 `YYYY-MM-DD` 로 받아 `formatMonthDay` 로 적고, 읽지 못하면 그 조각을 빼고 그립니다.
- 폭별 구성: 모바일은 머리줄 56(뒤로 · `○○동 이번 주 안내`) + 본문 + 아래 고정 `야간·휴일 문 연 곳 찾기`(발행된 안내만, 탭바 없음). 태블릿은 머리줄 72(뒤로 · 제목 · 알림 · 보고 버튼) + 가운데 640 + 탭바(홈). 데스크톱은 홈과 같은 머리줄 + 가운데 1080(뒤로 · 제목 → 왼쪽 본문 · 오른쪽 360 집계 상자 · 공식 정보 상자 · 버튼). 집계는 모바일(본문 안 칸 · 증상별 변화)과 태블릿 이상(`이번 주 ○○동 집계` 상자)의 자리 · 모양이 달라 두 번 그리고 폭에 따라 하나만 보입니다.
- **발행된 안내**: `운영자 검토` 배지 · `11월 18일 발행 · 기준 주` · 제목 · 집계(참여 · 증상 보고 · 지난 4주 평균) · 증상별 변화 · `이렇게 해 주세요`(번호 목록) · `근거: …` · `공식 질병관리청 발표 보기`(→ `/official`) · AI 초안 고지 "안내문 초안은 AI가 쓰고 운영자가 검토해 발행해요. 진단이 아닌 참고 정보예요. 증상이 심하면 의료기관에 문의하세요." **AI 고지는 발행된 안내를 보일 때 늘 함께 보입니다**(`AI_DRAFT_DISCLOSURE`). 수치는 운영자가 검토할 때 인용한 값입니다(백엔드 advisory `cited_*`).
- **정정된 안내**: 배지 줄의 기준 주 자리에 마지막 정정일(`11월 19일 정정`)을 적고, 제목 위 회색 테두리 상자(`정정 이력`)에 정정을 **최근 것부터 모두** 보입니다(`11월 19일 정정 · 사유`).
- **안내 없음**: `시민 자가보고` 배지 · 기준 주 · `이번 주는 발행된 안내가 없어요` · "운영자가 표본 규모와 반복·이상 보고를 확인한 변화가 있을 때만 동네 안내를 발행해요." · 집계 · `공식 예방수칙 보기`(→ `/official`, 홈 안내 섹션과 같음) · `질병관리청 발표 보기`. AI 고지 · 할 일은 없습니다. **자료 부족**이면 수치 · 상태색 없이 홈 상태 카드와 같은 참여 진행 막대(`우리 동네 자료를 채우는 중 64 / 100명`)만 보입니다. 데이터 타입이 `자료 부족` 주에 안내 · 수치를 둘 수 없게 막습니다(`features/notice/types.ts` — 백엔드도 `자료 부족` 집계로는 초안을 만들지 않음).
- 공식 정보(질병관리청)는 집계와 다른 요소(`공식` 배지가 달린 링크)로만 잇고 집계 안에 섞지 않습니다.
- **뒤로**(모바일 · 태블릿 머리줄, 데스크톱 제목 앞): 앱 안에서 들어왔으면(홈의 `안내 전체 보기`) `router.back()`, 주소로 바로 들어왔으면 홈 `/` 로 기록을 바꿔 갑니다. 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 없음 — docs/conventions.md "화면의 뒤로"). 진입 링크는 그냥 `Link` 입니다. 주소로 연 안내 → 홈 → 링크로 같은 안내 → 휴대폰 뒤로 두 번이면 앞 기록이 없어 홈으로 replace 합니다(앱 밖으로 나가지 않음). 새로고침 · 새 탭도 홈으로 replace 합니다.
- 머리줄 보고 버튼은 내 정보와 같습니다(`reportHrefFor`): 비회원 `로그인하고 보고하기` → `/login`, 회원 → `/?report=health-consent` · `/?report=start`. 동네 · 알림 · `야간·휴일 문 연 곳 찾기` 는 "○○ 화면은 준비하고 있어요" 알림입니다.
- **홈에서 잇기**: 홈 안내 섹션의 `안내 전체 보기` 가 `notice.href` 로 갑니다. 홈 목(`?mock=high`)은 안내 예시 동네 `○○동`(지어낸 코드 `99990100`, `NOTICE_EXAMPLE_DISTRICT`) · `2025-W47` · `?mock=published` 로 잇습니다. 둘러보기 동네(`?region=`)는 이 링크에 넣지 않습니다 — 목 안내는 예시 동네 하나뿐이고, 연동 때 매핑 계층이 그 동네 코드 · 기준 주로 href 를 만듭니다. 홈의 안내 없음은 지금처럼 `공식 예방수칙 보기` 로 갑니다.
- **도메인 사이 import**: 홈 목의 안내 링크는 notice 를 import 하지 않고 문자열로 둡니다(목이라 연동 때 사라짐, 같은 값인지는 `notice-client.test.ts` 가 확인). 안내 화면 → 홈의 증상 조각(`TrendBars` · `GROUP_LABEL` · `TREND_*`)은 import 하는 채로 둡니다 — 후속으로 증상 조각을 두 화면이 같이 쓰는 위치(데이터 도메인)로 옮깁니다.
- **목 상태** `?mock=published|corrected|none|insufficient`(`features/notice/mock.ts`). 모르는 값 · 없으면 `insufficient`(자료 부족의 안내 없음)입니다 — 수치 · 안내를 지어내지 않는 쪽이 기본값입니다. 목은 행정동 목(`findDistrict`)과 예시 동네만 알고, 주소의 주는 모양만 봅니다(어느 주든 같은 목). 값은 시안 예시 값이고 증상군 비율은 전체 증상 보고 비율을 넘지 않게 맞췄습니다.

**연동 요구사항 · 백엔드와 정할 점**

- `GET /api/notices/{admCd}?week=`(api-contract-draft)가 주는 것: 동네 이름, 발행된 안내(제목 · 할 일 목록 · 근거 · 발행일), 인용 집계(참여 · 증상 보고 비율 · 지난 4주 평균 · 증상군별 변화), 정정 이력(정정일 · 사유, 최근 것부터). 안내가 없으면 그 주 집계만(자료 부족이면 참여 · 공개 기준만). 함수 안만 바꿉니다(`features/notice/notice-client.ts` 의 `getRegionNotice`). 모르는 동네는 404 로 돌려주기를 요청합니다.
- **정정 모델이 어긋납니다**: 시안 · api-contract-draft 는 발행된 안내를 정정(`correct`)하고 정정 이력을 보이지만, 백엔드 `entity-design.md` §2-5 는 "PUBLISHED 본문은 고치지 않는다 — 철회하고 새 안내를 만든다" 입니다. 정정을 철회 + 새 발행으로 볼지(그때 화면이 이전 안내의 정정 사유를 어디서 받는지), PUBLISHED 에 정정 전이를 더할지 정해야 합니다. 화면은 정정 이력 목록(`corrections`)만 받으면 됩니다.
- 할 일 목록 · 근거는 advisory 의 `title` · `body` 한 덩어리로는 나오지 않습니다. 목록 · 근거를 따로 주거나 본문 형식을 정해야 합니다.
- **철회된 안내**: api-contract-draft 는 철회 이력을 포함한다고 적지만 시안이 없어 만들지 않았습니다. 철회된 주를 안내 없음으로 볼지, "철회됨" 을 따로 보일지 정합니다.
- 미래 주 · 아직 집계가 없는 주를 어떻게 줄지(404 · 자료 부족) 정합니다. 목은 모양만 보고 어느 주든 그립니다.
- 지난 주를 열어도 머리줄 · 집계 제목이 `이번 주 안내` · `이번 주 ○○동 집계` 이고, 기준 주 문구에 연도가 없습니다(`11월 3주` · `11월 17일~23일`). 지난 주 안내를 열 길(알림 · 이력)이 생기면 문구와 연도 표기를 정합니다.

**시안과 다르게 둔 것**

- 태블릿 · 데스크톱 안내 없음의 두 번째 문장 "우리 동네는 지난주보다 조금 늘었어요. 다만 안내를 낼 만큼 큰 변화는 아니었어요." 는 넣지 않았습니다. 운영자가 발행하지 않은 이유처럼 읽히는데 백엔드에 그 판단을 남기는 값이 없습니다. 변화는 집계 상자의 증상별 변화가 보입니다.
- 태블릿 · 데스크톱 집계 상자의 `왜 이렇게 보나요?` 는 넣지 않았습니다. 판단 기준 시트(S11)는 홈 데이터 모양(`MeasuredHomeWeekly`)을 받아 이 화면에서 열 수 없습니다 — 후속 후보입니다.
- 태블릿 · 데스크톱 집계 상자에 증상군을 모두(시안은 발열·기침·인후통 하나), 변화 문구(`많이 늘었어요` 등)와 함께 보입니다. 상태는 색과 글자를 함께 보인다는 규칙을 따릅니다. 막대는 홈 증상별 변화와 같은 `TrendBars`(폭 6 · 높이 24, 시안 10 · 26)이고 안내 없음의 늘어난 증상군도 홈과 같은 상태색입니다.
- 데스크톱 뒤로는 시안의 `#back` 링크 대신 뒤로 버튼 + 제목(`h1`)입니다. 링크는 기록을 쌓아 뒤로 가기가 이 화면으로 돌아옵니다.
- 화면 제목(`h1`)은 `○○동 이번 주 안내` 이고(모바일 · 태블릿 머리줄, 데스크톱 뒤로 옆 — 폭마다 하나만 읽힘), 안내 제목은 `h2` 입니다(시안은 모바일 `p` · 태블릿 이상 `h1`). 정정 상자는 시안의 `role=status` 대신 이름 있는 영역(`정정 이력`)입니다 — 처음부터 있는 내용이라 알림으로 읽히지 않게 했습니다.
- 할 일 제목 `이렇게 해 주세요` 의 태블릿 이상 글자 크기는 20 입니다(시안 19 — 토큰 없음). 행 높이는 `ListRow` 의 56 입니다(시안 52 · 48). 제목은 낱말 단위로 줄을 바꿉니다(시안은 모바일에 줄바꿈을 직접 넣음).

## 홈 화면 추가 · 알림 미지원 (S12 · Settings-nopush · State-push-inapp)

- **알림 권한을 묻지 않습니다.** 푸시 구독 · 서비스 워커 등록은 2단계 기능이라 아직 없습니다. 화면은 이 기기에서 푸시를 받을 수 있는지만 읽습니다(`src/lib/push-support.ts`).
- **푸시 지원 판단** (`detectPushSupport`): iPhone · iPad 이고 홈 화면 앱으로 열리지 않았으면 `needs-install`(API 가 보여도 iOS 는 홈 화면에 추가한 앱에서만 알림을 받음), 그 밖에는 `PushManager` · 서비스 워커 · `Notification` 이 모두 있으면 `supported`, 아니면 `unsupported` 입니다. 홈 화면 앱인지는 `display-mode: standalone` 또는 iOS 의 `navigator.standalone` 으로 봅니다.
- 기기 종류(`detectPlatform`)는 UA 로 가립니다: iPhone · iPad(iPadOS 13 이상은 Mac UA 라 터치 지점 2 이상이면 iPad) · Android · Chromium(Chrome · Edge, Mac Safari 보다 먼저) · Mac Safari · 그 밖. 설치 안내 묶음 · 문구를 고르는 데만 씁니다.
- 서버는 기기를 몰라 **서버 · 하이드레이션 첫 그림은 판단 전(null)** 이고, 그때는 미지원 안내 · 홈 상단 안내를 그리지 않습니다(`usePushSupport` · `useDevicePlatform`, `src/lib/use-push-support.ts`).
- **QA 덮어쓰기** `?mock-push=supported|needs-install|unsupported`: 기기 판단 대신 이 값을 씁니다(하이드레이션 뒤에만 따름, 모르는 값은 무시). 실제 푸시 구독을 붙일 때 지웁니다. 예: `/me?mock-auth=member&mock-push=needs-install`, `/?mock=high&mock-auth=member&mock-push=unsupported`.

**홈 화면 추가 안내 `/install`** (Install · -T · -D)

- 모바일은 전체 화면(머리줄 56 · 오른쪽 닫기 → 제목 두 줄 · 설명 두 문장 → 방법 묶음 → 아래 고정 `알림 켜기` · 회색 글자 `나중에 할게요`)입니다. 태블릿 · 데스크톱은 회색 바탕 가운데 패널(520 · 480, 제목 한 줄 · 설명 둘째 문장만 · 버튼 한 줄 `나중에 할게요` · `알림 켜기`)입니다. 한 DOM 으로 폭마다 모양만 바꿉니다(`features/install/install-screen.tsx`).
- 방법 묶음은 하이드레이션 뒤 기기로 하나만 보입니다: iPhone → iPhone (Safari), Android → Android (Chrome), iPad · Mac Safari → iPad·Mac (Safari), Chrome · Edge → Chrome·Edge. 판별 전 · 모르는 기기는 모바일에 iPhone · Android, 태블릿부터 iPad·Mac · Chrome·Edge 두 묶음을 보입니다(`install-guides.ts`).
- `알림 켜기` 는 "알림 켜기는 준비하고 있어요" 알림(토스트)만 띄웁니다.
- 닫기 · `나중에 할게요`: 앱 안에서 왔으면(내 정보 · 보고 완료의 진입 링크 등) `router.back()`, 주소로 바로 들어왔으면 홈 `/` 로 기록을 바꿔 갑니다(`region` · `mock-auth` · `mock-push` 만 남김). 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 없음 — docs/conventions.md "화면의 뒤로"). 진입 링크는 따로 표시를 남기지 않습니다. 새로고침 · 새 탭이면 앞 기록이 없어 홈으로 갑니다.
- 들어오는 길은 내 정보 알림 섹션의 `홈 화면에 추가하는 방법 보기`(아래)와 보고 완료(S06)의 `다음 주 월요일에 알려드릴까요?`(아래) 두 곳입니다. 둘 다 표시를 남기지 않는 보통 `Link` 입니다.

**보고 완료에서 잇기** (S06 Report-done · -T · -D → S12)

- 완료 화면의 `다음 주 월요일에 알려드릴까요? / 홈 화면에 추가하면 알림을 받을 수 있어요` 행은 **푸시가 `needs-install` 인 기기에만** 그리고, 누르면 `/install` 로 갑니다(`features/report/report-flow.tsx`). 링크는 동네 · 덮어쓰기(`region` · `mock-auth` · `mock-push`)만 넘기고 `report` 는 넘기지 않습니다.

  | 푸시 | 완료 화면의 행 | 이유 |
  | --- | --- | --- |
  | `needs-install` | 보임 → `/install` | 홈 화면에 추가해야 알림을 받는 기기라 행 문구가 그대로 맞습니다 |
  | `supported` | 숨김 | 설치가 필요 없어 "홈 화면에 추가하면" 이 맞지 않고, 알림 켜기(푸시 구독)는 2단계라 갈 곳이 없습니다. 2단계에서 알림 켜기로 잇습니다 |
  | `unsupported` | 숨김 | 설치해도 받지 못합니다(내 정보 미지원 상자가 링크를 두지 않는 것과 같음) |
  | 판단 전(null) | 숨김 | 기기를 모릅니다. 완료는 보낸 뒤에만 보여 실제로는 늘 판단이 끝나 있습니다 |

- 설치 안내의 닫기 · `나중에 할게요` 는 앱 안 진입이라 `router.back()` 으로 `/?report=done` 에 돌아오고, **보고 완료 화면이 그대로 남습니다.** 보고 흐름이 쌓은 기록 한 칸도 남아 `우리 동네 변화 보기` 가 홈으로 닫습니다.
- **보낸 보고는 홈 상태가 아니라 `features/report/report-client.ts` 의 목 모듈 메모리에 둡니다.** 홈 상태에 두면 설치 안내로 가며 홈이 사라져 돌아왔을 때 `?report=done` 이 시작 단계로 풀렸습니다. 서버가 이번 주 보고를 아는 흉내라 연동 때 서버 값으로 바뀌고, 화면은 `useSyncExternalStore` 로 읽어 서버 · 하이드레이션 첫 그림은 보낸 보고가 없습니다.
  - 같은 사람의 같은 주 보고는 하나라 값도 하나만 둡니다. 고치면 바뀌고 되돌리면 지웁니다.
  - 브라우저 저장소(`localStorage` 등)에 남기지 않습니다(증상은 민감정보). 새로고침 · 새 탭이면 사라져 `?report=done` 은 시작 단계로 보입니다 — 목 회원 세션이 새로고침하면 `guest` 로 돌아가는 것과 같습니다.
  - 목 회원 상태가 바뀌면(로그아웃 · 탈퇴 · 동의 철회 · 로그인 만료 · 다른 로그인) 지웁니다. 같은 기기에서 다음에 로그인한 사람에게 지난 보고 · 고른 증상이 보이지 않게 합니다. 프로필만 바뀌면(동네 · 비밀번호) 그대로 둡니다.
- **연동 요구사항**: 이번 주 보고를 읽는 API(로그인한 회원의 이번 주 보고 — 응답 모양 미정)가 필요합니다. 그때 `getSubmittedReport` 를 그 값으로 바꾸고, 새로고침한 `?report=done` 도 완료로 보이게 할지 정합니다.

**내 정보 알림 미지원 안내** (Settings-nopush · -T · -D)

- 회원 화면 알림 섹션 제목 아래 회색 상자(`role=status`, `features/me/push-unavailable.tsx`)입니다. 지원되거나 판단 전이면 그리지 않습니다.

  | 푸시 | 굵은 줄 | 이어지는 문장 | 링크 |
  | --- | --- | --- | --- |
  | `needs-install` (iPhone · 그 밖) | 이 기기에서는 알림을 받을 수 없어요 | 같은 내용은 홈 상단에서 확인할 수 있어요. iPhone은 Safari 공유 버튼 → 홈 화면에 추가 후 알림을 켤 수 있어요. | `홈 화면에 추가하는 방법 보기` → `/install` |
  | `needs-install` (iPad) | 이 브라우저에서는 알림을 받을 수 없어요 | 같은 내용은 홈 상단에서 확인할 수 있어요. 앱으로 설치하면 알림을 켤 수 있어요. | 같음 |
  | `unsupported` | 이 브라우저에서는 알림을 받을 수 없어요 | 같은 내용은 홈 상단에서 확인할 수 있어요. | 없음 |

- 미지원이면 두 스위치는 꺼진 회색 그대로이고 눌러도 아무 일이 없습니다(지원되는 기기는 전처럼 "알림 설정 화면은 준비하고 있어요").
- 링크는 동네 · 덮어쓰기(`region` · `mock-auth` · `mock-push`)를 남기고, 터치 영역이 44 입니다.

**알림 대신 홈 표시** (State-push-inapp · -T · -D)

- **회원이고, 이번 주 동네 안내가 발행됐고(`week.notice`), 이 기기에서 푸시를 받을 수 없을 때** 홈 상단에 회색 안내 "○○동 이번 주 안내가 발행됐어요 · 알림 대신 여기서 알려드려요"(`Callout tone="neutral"` + 안내 아이콘)를 띄웁니다(`features/home/push-inapp-notice.tsx`). 미지원 환경에서도 알림과 같은 내용을 서비스 안에서 보게 하려는 것입니다(루트 `CLAUDE.md` "알림").
- 자리: 모바일은 주차 줄 아래(좌우 20 · 위 12), 태블릿 · 데스크톱은 공식 정보 행 아래(좌우 24 · 32 · 위 12). 오프라인 띠와 함께면 그 아래에 놓입니다(아래 "공통 상태" 오프라인).
- **주소로 처음 열 때 하이드레이션 뒤 레이아웃이 한 번 움직입니다.** 서버는 기기를 몰라 `/install` 은 두 묶음으로 그렸다가 하이드레이션 뒤 기기 묶음 하나로 줄고, 홈 상단 안내는 하이드레이션 뒤에 나타나 아래 본문을 밉니다. 앱 안 이동으로 열면 첫 그림부터 맞습니다.

**연동 요구사항 · 후속 후보**

- 푸시 구독(2단계): 권한 요청 · 구독 · 서비스 워커 등록은 사용자가 `알림 켜기` · 알림 스위치를 누를 때만 하고, 구독 정보 저장 API 와 알림 동의 기록을 백엔드와 정합니다. 그때 `?mock-push=` 를 지우고 `supported` 인 기기의 스위치를 실제 상태로 바꿉니다.
- **기획 확인 후보**: ① 둘러보기(`?region=`)로 다른 동네를 볼 때도 그 동네 안내가 발행됐으면 "알림 대신 여기서 알려드려요" 가 뜹니다(알림은 내 동네 기준일 텐데 문구가 같음). ② 내 정보 미지원 상자의 "같은 내용은 홈 상단에서 확인할 수 있어요" 는 동네 안내에만 맞고, 주간 보고 요청 알림에는 홈 상단 대응 표시가 없습니다.
- 홈 상단 안내는 지금 "이번 주 안내가 발행된 주" 전체에 늘 보입니다. 이미 본 안내를 다시 띄우지 않을지(읽음 기록)는 서버 값이 생기면 정합니다.

**시안과 다르게 둔 것**

- 시안의 태블릿 · 데스크톱은 홈 위 대화상자(뒤에 홈이 흐리게 보임)지만, 단독 주소라 뒤에 홈을 그리지 않고 회색 바탕 가운데 패널로 둡니다. 제목은 폭과 무관하게 `h1`, 묶음 제목은 `h2` 입니다(시안 태블릿 · 데스크톱은 `h2` · `h3`).
- 시안은 늘 두 묶음을 보이지만, 기기를 알면 그 묶음 하나만 보입니다.
- 내 정보 미지원 상자의 문구는 시안처럼 폭이 아니라 기기 · 푸시 판단으로 고릅니다(모바일 시안 = iPhone, 태블릿 시안 = iPad). 푸시 API 가 없는 브라우저(`unsupported`)는 설치해도 받지 못해 "앱으로 설치하면 알림을 켤 수 있어요." 를 뺐습니다. `홈 화면에 추가하는 방법 보기` 링크는 시안에 없어 더했습니다.
- 시안 Settings-nopush 의 스위치는 `disabled` 이지만 포커스를 잃지 않게 `aria-disabled` 그대로 둡니다(기존 스위치와 같음).
- 홈 상단 안내의 줄 높이는 공통 `Callout` 값(1.5, 시안 1.45)입니다.

## 공통 상태 (불러오는 중 · 오류 · 오프라인 · 로그인 만료)

- **불러오는 중** (State-loading · -T · -D): `components/loading-state.tsx` 를 홈(`app/(home)/loading.tsx`)과 내 정보(`app/me/loading.tsx`)의 로딩 경계에 붙였습니다. 다른 화면에서 홈 · 내 정보(와 그 아래 계정 화면)로 올 때 보입니다. 홈 모양의 회색 막대만 그리고 숫자 · 상태 라벨 · 상태색은 미리 보이지 않습니다.
  - 지금 메뉴를 표시한 탭바(모바일 · 태블릿)와 머리줄(태블릿: 동네 · 보고 버튼 자리 막대, 데스크톱: 서비스명 · 동네 자리 막대 · 메뉴 · 보고 버튼 자리 막대)을 그립니다. 모바일 하단 보고 버튼 자리는 홈에만 둡니다.
  - **경계를 루트에 두지 않습니다.** 루트 `app/loading.tsx` 는 모든 경로를 Suspense 로 감싸 `notFound()` 가 404 대신 200 이 됩니다. 그래서 홈 페이지를 괄호 폴더로 옮겼습니다(`app/page.tsx` → `app/(home)/page.tsx`, 주소는 그대로 `/`). 지도(`/map`)는 라우트가 생길 때 같은 방법으로 경계를 둡니다. 로그인 · 첫 진입 화면에는 경계가 없어 이동 중에는 앞 화면이 그대로 보입니다.
- **오류** (State-error · -T · -D): `app/error.tsx` → `components/error-state.tsx`. 안내 아이콘 · "정보를 불러오지 못했어요" · "잠시 후 다시 시도해 주세요. 보고는 연결되면 다시 보낼 수 있어요." · `다시 시도` 만 보이고, 지난 값 · 예시 값을 대신 보이지 않습니다. 오류 내용(`error.message`)은 보이지 않습니다.
  - `다시 시도` 는 Next 16 의 `retry` 입니다(서버에서 화면을 다시 받아 그림). `reset` 은 다시 받지 않아 서버 자료 오류에 소용이 없습니다.
  - 오류 경계는 루트(`app/error.tsx`)라 모든 화면을 받습니다(`notFound()` 는 오류 경계가 아니라 404 로 갑니다). 주요 메뉴 화면이면 탭바(모바일 · 태블릿)와 데스크톱 머리줄(서비스명 · 메뉴)을 그려 다른 메뉴로 갈 수 있고(`lib/nav.ts` 의 `mainNavKeyFor`), 메뉴 밖 화면은 안내만 둡니다. 루트 레이아웃 자체의 오류(`global-error`)는 이 범위가 아닙니다.
  - 개발 서버 확인: `/dev/states?show=loading|error|offline&nav=home|map|me|none`, 실제 오류 경계는 `/dev/states/throw`(늘 오류를 던짐). 둘 다 프로덕션에서는 404 입니다.
- **오프라인** (State-offline · -T · -D): 시안은 화면 전체가 아니라 홈 알림 줄(Home 의 `notice`, 위 12 · 좌우 20)에 띠 "오프라인이에요. 11월 19일 09:00에 받은 정보예요" 를 띄우고 아래 홈은 받은 정보를 그대로 둡니다. `components/offline-notice.tsx` 가 그 띠이고, 연결 상태는 `lib/use-online.ts` 의 `useOnline()`(`navigator.onLine` + online · offline 이벤트)이 정합니다.
  - 하이드레이션 전(서버 그림 · 첫 그림)에는 늘 온라인으로 봅니다. 오프라인이면 그다음 그림에서 띠가 나옵니다.
  - 받은 시각(`receivedAt`)은 지금 보이는 정보를 받은 시각입니다. 모르거나 읽을 수 없으면 "오프라인이에요" 만 보이고 시각을 지어내지 않습니다.
  - 띠의 바깥 영역(`aria-live`)은 온라인일 때도 늘 그려 둡니다(토스트와 같은 이유).
  - **홈에 붙였습니다** (`features/home/home-screen.tsx`). 알림 대체 안내(State-push-inapp)와 같은 홈 상단 안내 줄 · 같은 여백(`HOME_TOP_NOTICE_CLASS`: 모바일은 주차 줄 아래 좌우 20 · 위 12, 태블릿 · 데스크톱은 공식 정보 행 아래 좌우 24 · 32 · 위 12)입니다. 다른 화면에는 아직 붙이지 않았습니다.
  - **받은 시각**은 `app/(home)/page.tsx` 가 그 요청에서 홈 자료(지금은 목)를 다 구한 시각을 ISO 로 넘깁니다. 화면 자료(RSC 결과)와 함께 실려 가므로 앞뒤 이동으로 같은 결과를 다시 보여도 시각이 자료와 맞습니다. API 연동 때는 응답을 받은 시각으로 바꿉니다. `receivedAt` 없이 홈을 그리면(미리보기 · 테스트) "오프라인이에요" 만 보입니다.
  - **두 띠가 함께면 오프라인 띠가 위, 알림 대체 안내가 아래**입니다(둘 사이 12). 연결이 끊겼다는 건 아래 모든 정보 — 알림 대체 안내도 — 가 받아 둔 그대로라는 뜻이라 먼저 읽혀야 하고, 시안 State-offline 도 띠를 알림 줄 첫 자리에 둡니다. 다시 연결되면 오프라인 띠만 사라지고 알림 대체 안내는 그대로입니다.
- **로그인 만료** (auth 캔버스 State-session-expired · -T · -D): 로그인 화면(S13-1) `?reason=expired` 의 "다시 로그인해 주세요" 토스트입니다.
  - 진입점은 하나입니다: 만료를 알아챈 쪽은 `lib/session-expiry.ts` 의 `notifySessionExpired()` 만 부릅니다. 루트 레이아웃의 `features/auth/session-expiry-watcher.tsx` 가 받아 목 세션을 비우고(`guest`) `/login?reason=expired` 로 기록을 바꿔(`useNavTrail().replace` — 그래서 감시는 루트 레이아웃의 `NavTrailProvider` 안에 있습니다) 갑니다. 뒤로 가기로 만료된 화면에 돌아와 다시 튕기지 않게 합니다.
  - 회원 화면의 가드(`member-gate.ts` 의 `useMemberGate` · 재동의 · 동네 다시 고르기)는 세션이 비회원이 되는 순간 함께 움직입니다. 만료를 알리면 `lib/session-expiry.ts` 가 만료 진행 표시(`isSessionExpiring`)를 켜고, 가드는 그동안 `useMemberGate` 면 `/login?reason=expired` 로 보내고 재동의 · 동네 다시 고르기는 이동하지 않습니다(그대로면 토스트 없는 `/login` 이나 홈에 닿음). 표시는 로그인 화면에 닿으면 끕니다.
  - 만료 진행 표시는 로그인 화면에 닿거나, 거치지 않고 다시 회원이 되면(목 세션이 비회원이 아니게 되면) 끕니다.
  - 목 재현 입력: 어느 화면이든 `?mock-session=expired` 를 붙여 열면(예: `/me?mock-auth=member&mock-session=expired`) 하이드레이션 뒤 바로 만료 흐름을 탑니다. 모르는 값은 무시합니다. 이동한 주소에는 덮어쓰기가 없어 다시 만료되지 않습니다.
  - **연동 요구사항**: `src/lib/api/` 의 401 처리(토큰 갱신까지 실패했을 때)가 토큰을 지우고 `notifySessionExpired()` 를 부릅니다. 화면 코드는 401 을 따로 다루지 않습니다. `?mock-session=` 은 `?mock-auth=` 와 함께 지웁니다(QA 덮어쓰기라 남기면 링크 하나로 로그인을 끊을 수 있습니다).
  - 후속 후보: 다시 로그인한 뒤 만료 전 화면으로 돌아오기(`?next=`, 허용 목록 `NEXT_PATHS`). 지금 로그인 화면은 `?next=` 를 받지 않아 홈으로 갑니다.
