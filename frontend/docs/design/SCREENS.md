## 첫 진입 (S01 · S02 · S13) 메모

- 단계 표시는 `n / 4` 입니다. 시안은 `/ 3` 이지만 S02-4 증상 보고 동의가 더해질 예정입니다.
- 둘러보기 변형: S01 `보고 없이 둘러보기` → `/browse/region` (Setup-1-browse). 단계 표시가 없고 버튼이 `이 동네 보기` 이며, 고르면 `/?region=<행정동 코드>` 홈으로 갑니다.
  - 머리줄 동네 이름에서 열면 `?next=<화면>` 이 붙습니다(아래 "머리줄 · 탭바 공통 규칙"). 고르면 그 화면에 `?region=<새 코드>` 를 붙여 **기록을 바꿔** 가고(뒤로 가기로 고르기 화면에 다시 오지 않음), 뒤로는 앞 화면을 따지지 않고 기록을 되돌립니다(앞 기록이 없으면 둘러보던 동네의 그 화면). `next` 가 없거나 허용 목록 밖이면 위처럼 홈에 쌓아 가고 뒤로는 시작 화면입니다.
- S02-1 동네 선택 · 결과 없음 · 둘러보기와 S02-2 성인 확인은 새 캔버스 `auth/screens/` 의 Setup-1 · Setup-1-empty · Setup-1-browse · Setup-2 가 정본입니다. 이 폴더의 `screens/Setup-1*` · `Setup-2*` 와 다르면 새 쪽을 따릅니다.
- 흐름: S01 `시작하기` → `/login`(S13-1) → 카카오 인가 화면 → 콜백 `/login/kakao/callback` → 신규 회원이면 `/setup/region?from=kakao`(아래 "카카오 로그인"). 로그인 화면은 단계 표시가 없습니다.
- **처음 온 사람은 시작 화면으로 보냅니다**(#127, `proxy.ts` → `features/onboarding/first-visit.ts`). 화면을 그리기 전에 서버(Next 16 Proxy)가 판단해 홈이 먼저 비치지 않습니다.
  - 처음 온 사람은 이 브라우저에서 서비스 화면을 한 번도 연 적이 없는 사람입니다. 1st-party 쿠키 `sc_visited=1` 로 가립니다 — 브라우저 저장소는 린트로 막혀 있고 서버가 읽지 못해 깜빡임 없이 보낼 수 없습니다.
  - 쿠키: 값은 고정값 `1`(개인을 알아보는 값 · 시각 · 경로를 담지 않음, 개인정보 아님), `Path=/` · `SameSite=Lax` · `HttpOnly`(서버만 읽음) · `Max-Age` 1년 · HTTPS 면 `Secure`. 개인정보 처리방침의 쿠키 항목에 "처음 방문 여부 표시" 로 적습니다.
    - 쿠키 목록의 다른 하나 `sc_data_source=api|mock`(데이터 출처 토글, docs/conventions.md "데이터 출처")는 **개발용**입니다. 전환을 허용한 사이트(dev 웹 · 로컬)만 쓰고 읽으며 운영 사이트는 쓰지도 읽지도 않으므로 처리방침 쿠키 항목에는 넣지 않습니다.
    - 세션 힌트 `sc_session=1`(docs/conventions.md "세션 저장소")은 운영에서도 씁니다. 로그인 · 재발급에 성공하면 심고 로그아웃 · 만료 때 지우며, 새로고침할 때 세션을 되살려 볼지만 정합니다. 값은 고정값 `1`(토큰 · 회원 아이디 · 시각을 담지 않음), `Path=/` · `SameSite=Lax` · HTTPS 면 `Secure` · 14일, 화면이 읽어야 해 `HttpOnly` 가 아닙니다. 처리방침 쿠키 항목에 "로그인 유지 여부 표시" 로 적습니다.
  - **표시하는 때**: 쿠키 없이 화면을 처음 열 때(어느 화면이든) 응답에 심습니다. 시작 화면으로 보내는 응답에도 심어 시작 화면은 한 번만 봅니다. 시작 화면에서 버튼을 고를 때 표시하는 방식은 고르지 않았습니다 — 고르지 않고 나가면 `/` 를 열 때마다 시작 화면으로 돌아가고, 쿠키를 쓰는 클라이언트 코드가 따로 필요합니다. 공유 링크로 하위 화면을 먼저 연 사람은 이미 서비스를 봤으므로 다음에 `/` 를 열면 홈입니다.
  - **보내는 때**: 쿠키가 없고 홈 `/` 를 쿼리 없이 문서로(GET, `Sec-Fetch-Dest: document` 또는 헤더 없음) 열 때만 `307 → /start` 입니다. 공유 링크로 바로 연 하위 화면(`/notice/…` · `/official` · `/map` 등)과 쿼리가 있는 홈(`?region=` · `?report=` · `?explain=` · QA 덮어쓰기 `?mock-auth=` · `?mock=` 등)은 보내지 않습니다. 앱 안 이동(RSC 요청 · 미리 받기)도 보내지 않아 쿠키를 막은 브라우저도 둘러보기 · 로그인 뒤 홈에 들어갑니다(그 경우 주소로 `/` 를 열 때마다 시작 화면입니다).
  - 회원은 보내지 않습니다. 회원이 되려면 로그인 · 가입 화면을 열어야 해 그때 쿠키가 생깁니다(목 세션은 서버가 모르지만 이 순서로 맞습니다). **연동 요구사항**: 세션 쿠키가 생기면 세션이 있는 요청도 보내지 않게 `first-visit.ts` 에 더합니다.
  - 한계: iOS 홈 화면 앱(PWA)은 Safari 와 쿠키를 같이 쓰지 않아 설치 뒤 처음 열면 시작 화면을 한 번 봅니다. 쿠키를 보내지 않는 검색 로봇은 `/` 에서 `/start` 로 갑니다.
- **회원이 연 시작 · 로그인 · 가입 화면은 홈으로 보냅니다**(#127, `features/auth/guest-only-gate.tsx` 를 첫 진입 레이아웃 `app/(onboarding)/layout.tsx` 에 둠). 내 정보 가드(비회원 → 로그인)의 반대 방향입니다.
  - 대상: `/start` · `/login` · `/login/email` · `/signup/email` · `/signup/code` · `/signup/account`. 회원(건강정보 동의 전 포함)이면 `?next=`(허용 목록 `safeNextPath` 안) 또는 홈 `/` 으로 **기록을 바꿔** 갑니다(`useNavTrail().replace`). 둘러보기 동네 `?region=` 과 QA 덮어쓰기(`?mock-auth=` 등)는 남깁니다 — 세션을 바꾸는 이동이 아니라 같은 회원으로 보여야 합니다. 보내는 동안은 화면을 바탕색으로 덮어 로그인 화면이 비치지 않습니다.
  - 로그인 → 홈 → 브라우저 뒤로 하면 로그인 화면이 다시 보이던 문제(점검 F3)도 이 가드로 홈에 갑니다. 기록은 `[…, /, /(앞으로)]` 가 되고, 보낼 곳이 대상 화면이 아니어서 반복 이동이 없습니다.
  - 빼는 것: 비밀번호 재설정 `/password/reset*`(회원도 비밀번호 변경 `/me/password` 의 "비밀번호를 잊었어요" 로 들어옵니다), 재설정을 마친 이메일 로그인 `/login/email?reason=reset-done`(재설정의 끝 화면이라 홈으로 보내면 "비밀번호를 바꿨어요" 안내를 잃습니다. 재설정에 성공하면 서버가 그 계정의 모든 기기를 로그아웃하고, 재설정한 계정이 이 탭 계정이면 이 탭 세션도 비워(#166) 비회원으로 닿습니다. 다른 계정을 재설정한 회원은 회원인 채 닿고 그대로 보입니다), 가입 마무리 `/setup/*` · 약관 재동의 `/terms/reconsent` · 동네 다시 고르기 `/setup/region?reselect=1` · 둘러보기 `/browse/region`(회원이 거치는 화면).
  - **화면에 닿을 때의 회원 상태로 한 번만 판단합니다.** 그 화면에 있는 동안 회원이 되는 것(이메일 로그인 성공)은 화면이 스스로 이동하므로 끼어들지 않습니다. 첫 진입 레이아웃은 화면 사이를 오가도 다시 그려지지 않아 경로가 바뀔 때마다 새로 닿은 것으로 봅니다 — 가입을 마친 뒤 뒤로 가기로 가입 화면에 돌아오면 홈으로 갑니다.
  - 하이드레이션을 마친 뒤에만 판단합니다(첫 그림은 늘 비회원). 로그인 만료 `/login?reason=expired` 는 만료 감시가 세션을 먼저 비우고 보내 비회원으로 닿으므로 그대로 보입니다.
- `/login` 상태는 주소 쿼리로 받습니다: `?error=kakao-fail`(+ 사유 `&kakao=`) · `?reason=expired`. 카카오 콜백 · 세션 만료가 같은 쿼리로 돌려보냅니다. `?error=kakao-exists` 는 #167 에서 없앴습니다(계정 연결 확인 화면으로 바뀜 — 옛 주소는 알리지 않음). `/login/email?reason=reset-done` 은 비밀번호를 바꾼 뒤입니다.
- **카카오 로그인** (#167, 백엔드 #61 — 계약 · 오류 매핑은 [api-contract-draft.md](../api-contract-draft.md) "인증" 의 "프론트 연동 (#167)"):
  - 진입: 로그인 방법 고르기 · 홈의 로그인 안내 시트의 `카카오로 계속하기` 가 실데이터면 `GET /api/v1/auth/kakao/authorize` 로 받은 카카오 인가 주소로 문서를 옮깁니다(https · `kauth.kakao.com/oauth/authorize` 일 때만 — 아니면 "카카오 로그인을 시작하지 못했어요"). 이동하는 동안 버튼은 꺼진 채이고, 카카오 화면에서 브라우저 뒤로로 돌아와 다시 보이면 켭니다. 요청이 많으면(`AUTH_028`) "요청이 많아 잠시 막혔어요. 잠시 뒤 다시 시도해 주세요." 입니다(로그인 화면은 토스트, 시트 · 연결 확인은 빨강 상자).
  - 콜백 `/login/kakao/callback`(백엔드 `KAKAO_REDIRECT_URI` 에 등록하는 주소): 기다리는 동안 "카카오 로그인을 확인하고 있어요 · 잠시만 기다려 주세요." 만 보입니다(**시안 없음**). `code` · `state` 를 읽자마자 주소에서 지우고 로그인 요청을 한 번만 보냅니다 — 새로고침하면 값이 없어 실패로 갑니다. 결과: 로그인됨 → 카카오로 떠나기 전에 둔 돌아갈 곳(없으면 홈, 기록을 바꿔 감 — 아래 "내 정보"의 "로그인 뒤 돌아오기", #140), 가입 필요 → `/setup/region?from=kakao` → S02-2 → S02-3, 연결 필요 → `/login/kakao/link`, 실패 · 사용자 취소 · 값 없음 → `/login?error=kakao-fail`(둔 돌아갈 곳을 `&next=` · `&region=` · `&intent=` 로 다시 실음). 첫 진입 가드는 콜백을 보내지 않습니다(화면이 스스로 이동). 회원(세션 힌트가 있음)이 닿아도 실데이터면 새로고침 복원(재발급)이 끝난 뒤에 카카오 로그인을 보내 카카오 계정으로 바꿉니다 — 둘이 동시에 나가면 늦게 온 재발급 응답의 refresh 쿠키가 카카오 로그인의 쿠키를 덮어 계정이 뒤섞일 수 있습니다. 콜백 문서에는 `Referrer-Policy: no-referrer` 를 붙입니다(`next.config.ts`, 주소의 인가 코드가 리퍼러로 새지 않게). 카카오가 붙여 온 쿼리는 proxy 가 fragment 로 옮겨 같은 경로로 303 리다이렉트하고(`/login/kakao/callback#code=…&state=…`, #176), 화면은 hash 에서 읽어 바로 지웁니다 — 모든 화면이 동적 렌더링이라 쿼리를 단 채 그리면 인가 코드가 문서 HTML 에 실리기 때문입니다(`docs/conventions.md` "보안 헤더 · CSP" 의 "카카오 콜백"). 303 이라 `?code=` 주소는 방문 기록에 남지 않습니다.
  - 계정 연결 확인 `/login/kakao/link`(시안 Login-kakao-exists 자리): 로그인 방법 고르기와 같은 제목 · 설명 아래 파랑 상자 "이 이메일로 가입된 계정이 있어요. 카카오 로그인을 연결할까요?" + 가린 이메일(`d***@example.com`) + `연결하고 계속하기`, 상자 아래 "연결해도 이메일과 비밀번호로 계속 로그인할 수 있어요.", 아래 버튼 `다른 카카오 계정으로 계속하기`(카카오 계정 고르기로 처음부터) · "카카오에서는 이메일과 닉네임만 받아요." 상자 문장 · 버튼은 백엔드 계약 문장이고 **시안 없음**입니다(시안의 `이메일로 로그인` 버튼은 없앰). 연결하면 로그인된 채 홈으로 기록을 바꿔 갑니다. 확인표가 지났거나(10분) 연결할 수 없으면 `/login?error=kakao-fail` 로 갑니다. 서비스가 그 밖의 업무 오류(저장소 장애 등)로 답해도 백엔드가 확인표를 먼저 지우므로 같게 보냅니다. 응답을 받지 못했을 때(네트워크 · 타임아웃 · 게이트웨이 오류 — 확인표가 남았을 수 있음)만 빨강 상자 "연결하지 못했어요. 잠시 뒤 다시 시도해 주세요." 로 다시 누르게 합니다. 가린 이메일은 첫 진입 Provider 메모리에만 두어(주소에 싣지 않음) 새로고침 · 바로 들어오면 `/login` 으로 돌려보냅니다. 회원이 닿으면 첫 진입 가드가 홈으로 보냅니다. 뒤로는 `/login` 입니다.
  - 실패 사유별 문장(`/login?error=kakao-fail&kakao=<사유>`, **시안 없음** — 백엔드 오류 문구를 화면 말투로 옮김. 사유가 없으면 시안 Login-kakao-fail 문장 "카카오 로그인을 마치지 못했어요. 다시 시도해 주세요."):
    - `email-required`(`AUTH_023`): "카카오 계정의 이메일을 받지 못했어요. 다시 시도할 때 이메일 제공에 동의해 주세요."
    - `email-unverified`(`AUTH_024`): "카카오 계정의 이메일이 인증되지 않았어요. 카카오에서 이메일을 인증한 뒤 다시 시도해 주세요."
    - `expired`(`AUTH_025` · `026` — 가입표 30분 · 확인표 10분이 지남): "시간이 지나 카카오 로그인을 마치지 못했어요. 카카오 로그인부터 다시 해 주세요."
    - `suspended`(`MEMBER_003`): "이용이 정지된 계정이에요."(이메일 로그인과 같은 문장)
    - 탈퇴(`MEMBER_002`) · state 무효(`AUTH_020`) · 카카오 장애 등은 사유 없이 알립니다 — 탈퇴는 이메일 로그인처럼 따로 드러내지 않습니다.
  - 목 재현(목데이터 모드): `카카오로 계속하기` 는 지금처럼 카카오를 다녀오지 않고 `/setup/region?from=kakao` 로 갑니다. 콜백은 주소로 열어 재현합니다 — `/login/kakao/callback?code=link&state=x` → 계정 연결 확인(`d***@example.com`, 연결하면 이메일 계정 `dong@example.com` 이 카카오 · 비밀번호 있음), `?code=login&state=x` → 카카오 회원 로그인(홈), `?code=AUTH_023&state=x` 처럼 서버 오류 코드 모양이면 그 오류(`AUTH_024` · `MEMBER_003` 은 사유별 문장, 그 밖은 사유 없음), 그 밖의 code → 가입 필요(S02-1), `?error=access_denied` · code 없음 → 실패.
  - 한계: FE 로컬(`http://localhost`)은 교차 사이트라 state 쿠키가 실리지 않아 콜백이 사유 없는 실패(`AUTH_020`)로 끝납니다 — dev 웹에서 확인합니다. **iOS 홈 화면(standalone) PWA 는 실기기 확인이 필요합니다** — 카카오 인가 화면(`kauth.kakao.com`)이 앱 안 Safari 시트로 열리면 PWA 와 쿠키 저장소가 달라 state 쿠키가 없을 수 있습니다(→ `AUTH_020`). 연동 뒤 iOS Safari · PWA 에서 먼저 확인합니다. 확인 목록: ① 카카오 로그인이 끝까지 되는지(`AUTH_020` 없이) ② 카카오 시트를 닫고 돌아왔을 때 `카카오로 계속하기` 버튼이 다시 켜지는지(문서가 그대로 남으면 `pageshow` 가 오지 않아 꺼진 채일 수 있음).
- 이메일 로그인 목(`features/auth/auth-client.ts`)에서 상태를 재현하는 입력: 이메일 `locked@example.com` → 잠김(locked), `limit@example.com` → 요청 많음(limited), `suspended@example.com` → 정지(suspended), 비밀번호 `wrong` → 맞지 않음(wrong), 그 밖 → 성공(홈으로).
- 이메일 로그인(S13-5)에서 시안에 없어 더한 상태 (#163, 실데이터 오류 코드에 맞춤):
  - limited(`AUTH_013` — 이 기기(IP)의 로그인 시도 상한): locked 와 같은 회색 상자(`role=alert`)에 "로그인 시도가 많아 잠시 막혔어요. 잠시 뒤 다시 시도해 주세요." 남은 시간을 서버가 주지 않아 시간을 못 박지 않습니다. 계정이 아니라 기기에 걸린 제한이라 로그인 버튼은 끄지 않고, 칸을 고치면 지웁니다.
  - suspended(`MEMBER_003` — 이용 정지, 비밀번호가 맞을 때만 옴): 빨강 상자 "이용이 정지된 계정이에요." 칸을 고치면 지웁니다. 문의 · 해제 안내는 기획과 정할 점입니다.
  - 탈퇴(`MEMBER_002`)는 따로 보이지 않고 wrong 입니다 — 탈퇴 회원은 미가입과 같게 보입니다(백엔드 #154 방향).
- 이메일 가입 흐름: `/login` 이메일로 가입하기 → `/signup/email` → `/signup/code` → `/signup/account` → `/setup/region`. 단계 표시는 없습니다. 입력값은 메모리(Provider)에만 두고, 중간 단계에 바로 들어오면 `/signup/email` 로 돌려보냅니다.

  - 한계(#163): 코드 확인의 IP 상한(`AUTH_010`)은 코드 단계에 따로 상태가 없어 locked("시도 횟수를 넘겼어요. 이메일부터 다시 진행해 주세요.")로 보입니다. 같은 네트워크에서는 이메일부터 다시 해도 잠시 동안 풀리지 않습니다. 문구 분리("요청이 많아 잠시 막혔어요" 류)는 후속입니다.

- 가입 목(`features/auth/auth-client.ts`)에서 상태를 재현하는 입력:
  - 코드 받기: 이메일 `limit@example.com` → 요청 많음(limit), 형식이 틀리면 invalid(보낼 때 판단). 그 밖은 이미 가입한 이메일이어도 보냄
  - 코드 확인: `000000` → 틀림(남은 시도 4번부터 1씩 줄고 5번째에 locked), `999999` → 잠김(locked), 잠긴 뒤 · 5분이 지나면 expired, 그 밖 6자리 → 성공
  - 비밀번호 · 닉네임: 8자 미만 · 20자 초과이거나 영문 · 숫자 중 하나가 없거나 공백이 있으면 pw-rule, 확인이 다르면 pw-mismatch, 닉네임 2~10자 밖이면 nick-long(다음을 누를 때 판단)
- 가입 마무리: 성인 확인 `다음` → `/setup/terms`(S02-3) → 가입 요청 → (이메일 가입만) 로그인 → 내 동네 저장 → `/setup/health-consent`(S02-4, 기록을 바꿔 감) → `동의하고 시작하기` 또는 `나중에 할게요` → 홈 `/`(기록을 바꿔 감).
  - 가입 응답에 토큰이 없어 이메일 가입은 가입 뒤 이메일 · 비밀번호로 로그인합니다. 카카오 가입(`POST /api/v1/auth/kakao/signup`, #167)은 응답이 로그인 응답이라 그 세션으로 바로 동네를 저장합니다. 카카오 가입표가 없거나 30분이 지났으면(`AUTH_025`) · 그사이 같은 이메일로 가입됐으면(`MEMBER_001`) · 서비스가 그 밖의 업무 오류로 답했으면(가입표를 먼저 지움) `/login?error=kakao-fail` 로 기록을 바꿔 가 카카오 로그인부터 다시 합니다. 응답을 받지 못했을 때(네트워크 · 타임아웃 · 게이트웨이 오류)와 필수 동의 검증 오류만 "가입하지 못했어요" 상자로 다시 누르게 합니다.
  - 가입 종류는 Provider 초안의 `method` 로 가립니다: 이메일 화면이 코드를 보내면 `email`, 로그인 화면에서 카카오로 시작하거나 S02-1 이 `?from=kakao` 로 열리면 `kakao`, `/login` 에 들어오면 지웁니다. 모르면 S02-3 이 `/login` 으로, 이메일 가입인데 인증 · 비밀번호가 없으면 `/signup/email` 로 돌려보냅니다.
  - 가입 · 로그인 · 동네 저장 중 하나가 실패하면 다시 누를 때 끝난 단계는 보내지 않습니다(가입 두 번 금지). 응답을 기다리는 동안 화면을 떠나도 서버에서 끝난 단계는 Provider 에 남깁니다. 비밀번호는 로그인을 마친 뒤 지웁니다.
  - 동네 저장은 실데이터면 `PUT /api/v1/members/me/region`(#164)입니다. 서버가 고른 동네를 받지 않으면(없는 코드 · 폐지) 빨강 상자 "고른 동네를 저장할 수 없어요. 앞 단계에서 동네를 다시 골라 주세요." 이고 다음 단계로 가지 않습니다 — 앞 단계(S02-1)에서 다시 고르고 돌아와 누르면 동네 저장만 보냅니다.
  - 이 진행은 가입 시도 하나에만 딸립니다. `/login` 에 들어오거나 카카오로 시작하면(`resetSignup`), 이메일 화면이 코드를 보내면 비웁니다.
  - 카카오 신규 회원은 콜백이 `?from=kakao` 로 S02-1(`/setup/region?from=kakao`, `paths.ts` 의 `SETUP_REGION_FROM_KAKAO_PATH`)에 보냅니다. 카카오를 다녀오면 페이지를 새로 열어 메모리가 비므로, S02-1 이 이 표시를 보고 가입 종류가 카카오가 아니면 가입 초안 · 마무리 진행을 비우고(`resetSignup`) `method: 'kakao'` 로 둡니다. ## 머리줄 · 탭바 공통 규칙 (#123)

주요 메뉴 화면(홈 · 지도 · 내 정보 · 계정 화면 · 공식 정보 · 동네 안내 · 불러오는 중 · 오류)의 머리줄 · 탭바는 같은 규칙을 따릅니다. 조각은 `components/app-header.tsx` · `tab-bar.tsx` 이고, 데스크톱 서비스명 · 메뉴는 `components/header-nav.tsx` 하나를 `AppHeader` 와 불러오는 중 · 오류 머리줄(`StateHeader`)이 같이 씁니다.

| 항목 | 모바일 | 태블릿 | 데스크톱 |
| --- | --- | --- | --- |
| 서비스명 `우리동네체온계` | 없음(시안) | 없음(시안) | 맨 왼쪽, **홈 `/` 링크**(둘러보기 동네 `?region=` 유지) |
| 주요 메뉴 | 탭바 홈 · 지도 · 내 정보(내 정보 오른쪽 끝) | 탭바(모바일과 같음) | 가운데 홈 · 지도(`주요 메뉴`) + **머리줄 오른쪽 끝 `내 정보`**(`계정 메뉴`) |
| 알림(종) | 회원만 | 회원만 | 회원만 |

- **알림(종)은 비회원에게 그리지 않습니다.** 회원(건강정보 동의 전 포함)은 지금처럼 보입니다. `AppHeader` 는 `onNotificationClick` 을 넘기지 않으면 종을 그리지 않고, 화면이 따로 그리는 모바일 · 태블릿 머리줄(공식 정보 · 동네 안내)도 같은 값으로 가립니다. 계정 화면(로그인한 기기 · 비밀번호)은 회원만 그려 늘 보입니다. 하이드레이션 첫 그림은 늘 비회원이라 회원은 처음 연 그림에서 종이 한 번 늦게 나타납니다(보고 버튼 글자와 같음).
- **데스크톱 오른쪽 묶음 순서는 알림 · 보고 버튼 · 내 정보**입니다. 탭바에서 내 정보가 오른쪽 끝인 것과 자리를 맞췄고, 계정 진입을 맨 오른쪽에 두는 흔한 배치를 따랐습니다. 보고 버튼은 화면의 주 동작이라 알림 옆 가운데 자리를 지킵니다. 비회원은 종이 빠져 `로그인하고 보고하기` · `내 정보` 입니다. 키보드 순서도 보이는 순서와 같습니다(DOM 순서 그대로, CSS `order` 를 쓰지 않음).
- **태블릿은 탭바를 그대로 씁니다.** 태블릿 시안(Tablet · Home-guest-T · Official-T 등)의 머리줄에는 메뉴가 없고 탭바(홈 · 지도 · 내 정보)가 있어 내 정보는 이미 탭바 오른쪽 끝입니다. 머리줄에 내 정보를 더하면 탭바와 겹칩니다.
- **비회원의 `내 정보`**: 링크는 회원 상태와 무관하게 `/me`(+ `?region=`)이고, 내 정보 화면의 가드가 비회원을 `/login?next=/me`(둘러보기 동네 유지)로 기록을 바꿔 보냅니다. 로그인을 마치면 `/me` 로 돌아옵니다(아래 "내 정보"). 주소로 `/me` 를 바로 연 비회원도 같은 가드로 갑니다.
  - 링크를 비회원일 때 로그인 주소로 바꾸지 않고 가드로 보낸 이유: ① 탭바 · 데스크톱 메뉴 · 불러오는 중 · 오류 머리줄 · 주소 직접 열기를 가드 하나가 맡습니다(링크마다 회원 상태를 알게 하면 서버 컴포넌트인 불러오는 중 경계의 탭바까지 회원 상태를 읽어야 합니다). ② 서버 · 하이드레이션 첫 그림은 늘 비회원이라 링크를 바꾸면 회원도 첫 그림에서 로그인 주소를 갖습니다(연동 뒤 하이드레이션 전에 누르면 회원이 로그인으로 감). ③ 뒤로 규칙은 같습니다 — 가드가 `useNavTrail().replace` 로 바꿔 가므로 기록은 `[앞 화면, /login]` 이고, 로그인의 뒤로(아래)는 앞 화면으로 돌아갑니다. 비용은 로그인으로 가기 전에 내 정보 경계의 불러오는 중이 잠깐 보이는 것입니다.
- **동네 이름(동네 바꾸기)은 둘러보기 동네(`?region=`)만 바꿉니다**(#141). 회원 · 비회원 같고, 회원의 내 동네(보고 동네)는 내 정보의 `/me/region` 에서만 바꿉니다. 누르면 `/browse/region?next=<지금 화면>` 으로 갑니다(`features/onboarding/browse-return.ts` · `use-browse-region.ts`).
  - `next` 허용 목록: `/` · `/map` · `/official` · `/me` · `/me/devices` · `/me/password` · `/me/region` · `/me/nickname` · `/me/reports` · `/me/interest-regions` · `/me/notifications`. 동네 안내(`/notice/…`)는 안내가 경로의 동네 것이라 홈(`/`)을 돌아갈 곳으로 엽니다. 함께 넘기는 쿼리는 지금 둘러보기 동네와 QA 덮어쓰기(`mock-auth` · `mock-provider` · `mock-required`, 알림 덮어쓰기 `mock-push` — #195)뿐이고, 열린 시트 · 목 자료(`?mock=`)는 버립니다.
  - 보이는 이름: 둘러보기 동네가 있으면 그 동네, 없으면 회원의 내 동네(목 프로필), 그것도 없으면 목 예시입니다(`features/me/member-region.ts`). 동네 안내는 안내의 동네입니다. 하이드레이션 첫 그림은 늘 비회원이라 회원은 처음 연 그림에서 목 예시가 보였다가 내 동네로 바뀝니다(종과 같음). 지도의 머리줄도 같은 규칙이고(#145), 지도의 처음 고른 동네(둘러보기 · 목 예시)를 회원의 내 동네로 두는 것은 집계 API 연동 뒤입니다(아래 "지도").
  - 회원도 `?region=` 으로 다른 동네를 둘러봅니다. **보고는 늘 내 동네로** 합니다 — 홈의 보고 흐름은 내 동네 이름을 쓰고, 다른 동네를 둘러보는 중이면 시작 단계에 `보고는 내 동네 ○○동 기준이에요. 둘러보는 동네와 달라요.` 를, 확인 단계의 동네 앞에 `보고 동네` 를 붙입니다(시안에 없음). 내 동네를 모르는 회원은 지금처럼 보이는 동네 이름입니다.
- 시안과 다르게 둔 것: 비회원 시안(Home-guest-T · -D · Settings-guest-D)에 있는 종을 뺐습니다. 데스크톱 시안의 `내 정보` 는 가운데 메뉴의 셋째 항목이지만 오른쪽 끝으로 옮겼습니다. 서비스명은 시안에서 링크가 아닙니다.
- 첫 진입 · 로그인 화면(`OnboardingLayout`)의 태블릿 · 데스크톱 서비스명은 이 규칙 밖입니다(링크가 아님).

## 홈 보고 진입 · 목 회원 상태 (S03 · Login-sheet · Consent-health-sheet)

- 보고는 건강정보 동의를 한 회원만 합니다. 홈의 보고 버튼(모바일 하단 · 태블릿 · 데스크톱 머리줄)은 모두 같은 함수를 부르고 회원 상태로 나뉩니다 (`features/home/report-gate.ts`).

  | 회원 상태 | 보고 버튼 | 열리는 것 |
  | --- | --- | --- |
  | 비회원 `guest` | `로그인하고 보고하기` | 로그인 안내 시트 `?report=login` |
  | 동의 안 한 회원 `member-no-consent` | `이번 주 건강 보고하기` | 증상 보고 동의 시트 `?report=health-consent` |
  | 동의한 회원 `member` | `이번 주 건강 보고하기` | 보고 흐름 `?report=start` (S05) |
  | 동의한 회원 · 이번 주 보고를 보낸 뒤 | `이번 주 보고 완료 · 수정하기` | 보고 흐름 `?report=start` — 보낸 보고가 있어 수정 안내로 열림 |

- **보고 버튼 글자는 한 함수가 정합니다**(#146, `report-gate.ts` 의 `reportButtonLabel`). 홈 하단 버튼과 모든 머리줄(홈 · 지도 · 동네 안내 · 공식 정보 · 내 정보 · 로그인한 기기 · 비밀번호 · 내 동네 바꾸기)이 같은 글자입니다. 보낸 보고는 `features/report/use-submitted-report.ts` 의 `useSubmittedReport()` 로 읽습니다(실데이터: 이번 주 보고 저장소 `GET /api/v1/reports/current`, 목데이터: `report-client` 목 메모리 — #165).
  - 보낸 뒤 홈 하단 버튼은 회색 보조 버튼(`secondary`, 시안 Flow 의 reported)입니다. 머리줄 버튼은 글자만 바뀌고 네이비 그대로입니다(태블릿 · 데스크톱 시안에 보낸 뒤 머리줄이 없음).
  - 보낸 보고는 동의한 회원에게만 보여, 미동의 회원(덮어쓰기 `?mock-auth=member-no-consent`)은 보낸 보고가 남아 있어도 `이번 주 건강 보고하기` 입니다(누르면 동의 시트).
  - 서버 그림 · 하이드레이션 첫 그림은 보낸 보고가 없습니다(회원 상태와 같은 이유). 목데이터는 새로고침하면 목 보낸 보고가 비어 `이번 주 건강 보고하기` 로 돌아갑니다. 실데이터는 세션을 되살린 뒤 이번 주 보고를 다시 읽어 완료로 바뀝니다.
  - **실데이터에서 이번 주 보고를 읽는 중 · 읽지 못함이면 `이번 주 건강 보고하기` 입니다** — 모르는 채로 완료를 보이지 않습니다. 누르면 보고 흐름이 열리고 아래 "주간 건강 보고" 의 확인 중 · 불러오지 못함 안내가 보입니다. 동의 전 회원(`reportWritable` false)은 이번 주 보고를 읽지 않습니다(요청 없음).

- 두 시트는 보고 흐름의 앞 단계라 같은 쿼리 `?report=` 의 값으로 둡니다. 버튼으로 열 때는 기록을 쌓고(`push`) 닫기 · 휴대폰 뒤로 가기로 닫힙니다. 동의 시트에서 동의하면 값만 `start` 로 바꿔(`replace`) 뒤로 가기가 동의 시트를 건너뛰어 홈으로 갑니다. 다른 쿼리(`region` · `mock` 등)는 열고 닫아도 남습니다.
- 주소로 바로 들어온 값이 회원 상태에 맞지 않으면 기록을 쌓지 않고 맞는 시트로 바꿉니다: 비회원의 `?report=start`(보고 흐름 어느 단계든) · `health-consent` → `login`, 동의 안 한 회원의 보고 흐름 · `login` → `health-consent`, 동의한 회원의 `login` · `health-consent` → `start`. 보고 흐름과 보낸 보고 표시는 동의한 회원에게만 그립니다.
- 비회원 홈(Home-guest)은 동네 현황(상태 카드 · 공식 정보 · 증상별 변화 · 동네 안내)이 회원 홈과 같고, 자료 부족이면 수치 · 상태색을 숨기는 규칙도 같습니다. 모바일은 하단 버튼 위에 `로그인하면 이번 주 보고를 할 수 있어요`, 태블릿 · 데스크톱은 본문 맨 위(태블릿 격자 위 · 데스크톱 오른쪽 패널 맨 위)에 안내 상자 `로그인하면 이번 주 보고를 할 수 있어요. 동네 현황은 지금처럼 볼 수 있어요.` 를 둡니다.
- 둘러보기에서 온 `?region=<코드>` 는 `app/(home)/page.tsx` 가 아는 코드일 때 홈에 넘기고, 홈이 탭바 · 데스크톱 메뉴 링크 뒤에 붙입니다(`/?region=` · `/map?region=` · `/me?region=`).
- 로그인 안내 시트: `카카오로 계속하기` 는 로그인 방법 고르기와 같습니다 — 실데이터는 카카오 인가 화면, 목은 `/setup/region?from=kakao`(보내는 중 꺼짐, 시작하지 못하면 · 요청이 많으면 시트 안 빨강 상자, 위 "카카오 로그인"). 떠나기 전에 보고하려던 로그인(둘러보던 동네 포함)을 두어, 카카오 로그인 · 계정 연결 · 가입 마무리를 마치면 같은 동네 홈의 보고 진입으로 돌아옵니다(#140). `이메일로 시작하기` 는 보고하려던 이메일 로그인 `/login/email?region=…&intent=report` 로 갑니다(#136, 아래 "내 정보"의 "로그인 뒤 돌아오기") — 홈을 둘러보다 보고하려는 사람은 이미 회원인 경우가 많고, 이메일 로그인 화면에 `이메일로 가입하기` 링크가 있어 처음인 사람도 바로 가입으로 갈 수 있습니다. 로그인하면 같은 동네 홈의 보고 진입으로 돌아오고, 이메일 로그인의 뒤로는 기록을 되돌려 이 시트로 돌아옵니다.
- 증상 보고 동의 시트: S02-4 와 같은 고지 표 · 체크 · 버튼(`features/auth/health-consent.tsx`)을 쓰고, 동의 값도 같습니다(`SENSITIVE_HEALTH_INFO` + 문서 버전). 체크해야 `동의하고 보고하기` 가 켜지고, 보내지 못하면 빨강 상자로 알린 뒤 다시 누를 수 있습니다. `나중에 할게요` 는 닫기입니다. 응답 전에 시트가 닫히면 늦은 응답으로 보고 흐름을 열지 않습니다(동의는 서버 · 목 세션에 남습니다).
- **목 회원 상태** (API 연동 전, `features/auth/auth-client.ts` · `use-mock-auth.ts`):
  - 정하는 순서: ① 주소 `?mock-auth=guest|member|member-no-consent`(QA 용 덮어쓰기, 모르는 값은 무시) ② `auth-client` 모듈 메모리의 목 세션 ③ 기본 `guest`.
  - 목 세션이 바뀌는 때: 카카오 가입 성공(S02-3) · 이메일 로그인 성공(S13-5, 이메일 가입 뒤 S02-3 의 로그인 포함) · 목 카카오 콜백 로그인 · 계정 연결 → `member-no-consent`, 건강정보 동의 성공(S02-4 · 동의 시트) → `member`, 내 정보(S10)의 동의 철회 · 로그아웃 · 탈퇴 → `guest`. 화면 코드는 고치지 않습니다.
  - 새로고침하면 목 세션이 비어 `guest` 로 돌아갑니다(브라우저 저장소에 남기지 않음). 앱 안 이동(가입 · 로그인 · 동의 뒤 홈으로)에서만 이어집니다.
  - 서버는 세션을 몰라 첫 그림(하이드레이션)은 `guest` 로 그립니다. 실데이터 모드(#158)는 새로고침하면 세션 힌트(`sc_session`)가 있을 때 재발급으로 세션을 되살리므로, 회원이 처음 그릴 때 잠깐 비회원 홈이 보입니다. **서버가 세션을 읽어 넘기는 방식은 쓸 수 없습니다** — refresh 쿠키는 게이트웨이 호스트 · `Path=/api/v1/auth` 전용이라 웹 서버에 오지 않습니다. 가드는 복원이 끝난 뒤(`useAuthSettled`) 판단하므로 회원을 로그인으로 튕기지 않습니다.
  - 동의 시트에서 동의하면 `?mock-auth=` 덮어쓰기를 주소에서 지웁니다. 남겨 두면 동의한 뒤에도 미동의로 보여 보고 흐름이 다시 동의 시트로 바뀝니다. 지운 뒤에는 목 세션(`member`)을 따릅니다.
  - 목 로그인은 동의 여부를 몰라 이전에 동의했어도 `member-no-consent` 가 됩니다. 연동 때 서버 세션이 동의 상태를 알려 줍니다.
  - QA 덮어쓰기 `?mock-auth=`(와 내 정보의 `?mock-provider=` · `?mock-required=` · `?mock-session=`)는 지우지 않고 **목데이터 모드에서만 듣습니다**(#158). 실데이터 모드 · 운영에서는 무시합니다 — 들으면 주소만으로 회원 · 동의 확인을 건너뛰는 인가 우회가 됩니다.
- 후속 후보: 둘러보기에서 고른 `?region=` 을 로그인 안내 시트 → 가입 흐름의 S02-1 초기 선택으로 넘기기 (지금은 S02-1 에서 다시 고릅니다).
- 시안과 다르게 둔 것:
  - 두 시트는 공통 `Modal` 을 그대로 써서 모바일 시트의 줄 간격이 16(시안 14), 태블릿 · 데스크톱 대화상자 제목이 24(시안 22)입니다. 보고 흐름 · 판단 기준 시트와 같은 값입니다.
  - 태블릿 비회원 안내 상자는 격자 첫 줄(두 칸)이라 아래 간격이 28 입니다(시안은 본문 간격 24).
  - 카카오 버튼은 보내는 중 `disabled` 로 끕니다(S13-1 과 같음).

## 주간 건강 보고 (S05 Report-symptom)

- 시안과 다르게 둔 것: 증상 고르기에서 `그 외 증상만 있었어요` 선택지를 뺐습니다. 백엔드 증상군(`SymptomGroup` 호흡기 · 장관)과 맞추려는 사용자 결정입니다(#128). 선택지는 `발열·기침·인후통` · `구토·설사` 둘이고 함께 고를 수 있습니다.
- **실데이터 연동 (#165)**: 보내기 · 고치기는 `PUT /api/v1/reports/current`, 되돌리기는 `DELETE`(계약은 [api-contract-draft.md](../api-contract-draft.md) "주간 보고"). 보고 동네는 늘 **내 동네**(`useMemberRegion()`)이고 둘러보는 동네가 아닙니다. 보고 주는 서버가 정합니다(화면의 주 라벨은 아직 홈 집계 목의 예시 값).

  | 상태 | 보이는 것 |
  | --- | --- |

## 보고 완료 · 함께 채우기 (S06 · #151)

- 완료 화면의 `우리 동네 자료 함께 채우기` 는 완료 위에 공유 시트를 엽니다(`features/report/share-sheet.tsx`). 모바일은 바텀시트, 태블릿 · 데스크톱은 가운데 대화상자입니다(공통 `Modal`). 아래 완료 대화상자는 그대로 두고 그 위에 하나 더 엽니다 — Flow 시안도 완료 위에 시트를 띄웁니다.
- **열림 상태는 보고 흐름 단계 `?report=share` 입니다**(별도 쿼리가 아님). 완료 다음에만 열 수 있는 화면이라 완료와 같은 가드를 그대로 받습니다: 보낸 보고가 없으면 시작 단계로 풀리고(`resolveStep`), 비회원 · 미동의 회원이 주소로 열면 로그인 · 동의 시트로 바뀝니다(`guardReportEntry`). 완료와 동시에 있을 수 없어 쿼리가 남아 보낸 뒤 시트가 튀어나오는 일도 없습니다.
  - 열 때 기록을 쌓아(`push`) 휴대폰 뒤로 가기 · 닫기 · Esc · 바깥 누르기가 완료로 돌아옵니다. 주소로 바로 열어 쌓은 기록이 없으면 닫기가 값만 `done` 으로 바꿉니다(사이트를 떠나지 않음).
- 내용은 Flow 시안의 공유 시트(`isShare`)를 따릅니다: 제목 `이렇게 공유돼요` · 미리보기 카드(앱 이름 · `우리 동네 건강을 같이 살펴요` · `일주일에 한 번 10초면 돼요. 이름·주소·위치는 받지 않아요.`) · `내 보고 내용은 공유되지 않아요` · 한 줄 버튼 `링크 복사`(보조) + `메신저로 보내기`(주).
  - `메신저로 보내기`: 기기 공유 창(`navigator.share`)으로 링크를 보냅니다. 브라우저에 공유 기능이 없으면 그리지 않고 `링크 복사` 가 주 버튼(네이비)으로 한 줄을 채웁니다. 서버 · 하이드레이션 첫 그림은 공유 기능 없음으로 그리고 하이드레이션 뒤에 판단합니다. 공유 창을 취소하면 알리지 않고, 그 밖의 실패는 `메신저로 보내지 못했어요. 링크 복사를 눌러 주세요.` 입니다.
  - `링크 복사`: 클립보드에 쓰고 시트 안 알림 `링크를 복사했어요` 를 띄웁니다. 시안에 링크 칸이 없어 평소에는 링크를 보이지 않습니다. 클립보드가 없거나(보안 연결이 아님) 막히면 그때 읽기 전용 링크 칸 `공유 링크` 를 보여 골라 두고, 칸 아래에 `복사하지 못했어요. 링크를 길게 눌러 복사해 주세요.` 를 보입니다(칸의 설명이라 포커스와 함께 읽힘). 닫으면 칸을 다시 숨깁니다.
- **공유 링크**(`features/report/share-link.ts` 의 `buildShareLink`): 사이트 주소(`clientEnv.siteUrl`) + `/` + `?region=<동네 코드>` 뿐입니다. 동네는 보고 동네(회원의 내 동네) → 모르면 둘러보기 동네 → 그것도 없으면 동네 없는 홈입니다. 이름 · 건강 · 보고 내용 · 추적 파라미터(utm 등) · QA 덮어쓰기(`mock-*`) · 데이터 출처는 싣지 않습니다. 공유 문구는 제목 `우리동네체온계`(앱 이름) · 글 `우리 동네 건강을 같이 살펴요`(Flow 미리보기 제목)로 보낸 사람의 건강 상태를 암시하지 않습니다.
  - 로컬 개발은 `NEXT_PUBLIC_SITE_URL` 이 없으면 링크가 `http://localhost:3000/…` 입니다(다른 포트로 띄워도 같음).
- 시안과 다르게 둔 것:
  - `메신저로 보내기` 는 카카오톡이 아니라 기기 공유 창입니다. 카카오톡 공유는 #61(카카오 연동) 뒤에 이 버튼으로 붙입니다. 공유 창이 없는 브라우저(데스크톱 일부)는 버튼을 숨깁니다.
  - 복사하지 못했을 때만 링크 칸 · 안내가 나타납니다(시안에 없는 대체 동작).
  - 공통 `Modal` 을 그대로 써서 손잡이가 있고, 닫기가 제목 위 머리줄에 있으며(시안은 제목 줄 오른쪽), 제목이 22(시안 17) · 버튼 글자가 17(시안 15)입니다. 다른 시트와 같은 값입니다.
  - 태블릿 · 데스크톱은 시안이 없어 공통 `Modal` 의 가운데 대화상자입니다. 완료 대화상자와 크기 · 위치가 같아 그 위를 덮습니다.
- 후속 후보: 카카오톡 공유(#61 카카오 로그인 연동 뒤, 카카오 JavaScript SDK 키 · 도메인 등록 필요) · 공유 링크의 미리보기(OG 이미지 · 제목 · 설명 — 지금은 루트 메타데이터 그대로).

## 내 정보 (S10 · Settings · Confirm-*)

- `/me` 는 홈과 같은 셸(머리줄 · 탭바, 현재 `내 정보`)입니다. **회원만 봅니다**(#123). 로그인 방법(`useMockProfile`)으로 화면이 둘입니다: 이메일 회원 Settings · 카카오 회원 Settings-kakao. 카카오로만 로그인하는 회원(`hasPassword` false)에게는 시안의 `비밀번호 설정` + `이메일로도 로그인할 수 있어요` 행을 그리지 않습니다 — 비밀번호 최초 설정 API 를 백엔드 #61 에서 없앴습니다(#166). 비로그인 Settings-guest 는 그리지 않습니다.
- **비회원 가드**(`features/me/member-gate.ts` 의 `useMemberGate({ next: '/me' })`): 하이드레이션 뒤 비회원이면 본문 없이 `/login?next=%2Fme`(둘러보기 동네 `&region=` 를 붙임)로 기록을 바꿔 갑니다. QA 덮어쓰기(`?mock-auth=` · `?mock-provider=` · `?mock-required=`)는 넘기지 않습니다 — 로그인은 세션을 바꾸는 동작이라 로그아웃 뒤처럼 결과가 그대로 보여야 하고, `?mock-auth=guest` 를 넘기면 돌아와 다시 튕깁니다. 로그인 만료로 비회원이 되면 계정 화면처럼 `/login?reason=expired&next=%2Fme` 입니다(만료 감시와 같은 주소, #140). `next` 는 생략할 수 없습니다 — 회원 화면은 모두 자기 경로를 넘깁니다(로그인한 기기 · 비밀번호 · 내 동네).
  - 머리줄 · 탭바(셸)는 판단 전에도 그리고 본문 · 데스크톱 설정 메뉴만 회원으로 판단된 뒤 그립니다.
  - 로그아웃 · 탈퇴에 성공하면 세션이 먼저 비회원이 됩니다. 보내는 중(`pending`)에는 가드를 멈춰(`paused`) 로그인이 아니라 홈으로 갑니다(그동안 본문은 비고 대화상자는 열린 채 꺼져 있음).
  - 비회원이 `?confirm=` 으로 들어와도 주소 정리(원시 history)를 하지 않고 로그인으로만 보냅니다 — 정리가 대기 중인 로그인 이동을 버리게 합니다.
- **로그인 뒤 돌아오기**(`features/auth/login-return.ts`): 로그인 방법 고르기(S13-1)가 `?next=` · `?region=` · `?intent=` 를 받아 `이메일로 로그인` 링크(카카오 겹침 상자의 버튼 포함)에 이어 넘기고, 이메일 로그인(S13-5)이 성공하면 `/me?region=…` 으로 기록을 바꿔 갑니다. `next` 는 허용 목록(`safeNextPath`)만 따릅니다. 내 정보에 조건(재동의 · 동네 다시 고르기)이 남았으면 내 정보 레이아웃의 가드가 이어서 보냅니다.
  - **보고하려던 로그인**(#136): 비회원의 머리줄 보고 버튼(`reportHrefFor` → `/login?region=…&intent=report`)과 홈 로그인 안내 시트의 `이메일로 시작하기`(→ `/login/email?region=…&intent=report`)가 `?intent=report` 를 붙입니다. 이메일 로그인이 성공하면 같은 동네 홈의 보고 진입 `/?region=…&report=start` 로 기록을 바꿔 가고, 홈이 회원 상태에 맞게 고칩니다(목 로그인은 늘 미동의 회원이라 동의 시트 `?report=health-consent`). `intent` 는 `report` 하나만 받고 돌아갈 곳이 홈일 때만 받습니다(`?next=/me&intent=report` 면 버림).
  - 회원이 보고하려던 로그인 화면에 닿으면(사실상 로그인 성공 뒤 브라우저 뒤로) 첫 진입 가드는 같은 동네 홈(`next` · 동네 · QA 덮어쓰기)으로만 보내고 보고 진입은 붙이지 않습니다 — 뒤로 가려는 사람을 보고 시트로 붙잡지 않습니다. 가드는 닿을 때의 상태로 한 번만 판단해 로그인 성공 이동과 겹치지 않습니다.
  - 돌아갈 곳이 있는 로그인(보고하려던 로그인 포함)의 뒤로는 앞 화면을 따지지 않고 되돌립니다(`useNavTrail().goBack('/start')`, 앞 기록이 없으면 시작 화면). 가드가 기록을 바꿔 보내 바로 앞이 내 정보를 누른 화면이고, 머리줄 보고 버튼은 여러 화면에 있어 앞 화면이 정해져 있지 않습니다. 돌아갈 곳이 없으면 지금처럼 시작 화면에서 왔을 때만 되돌립니다. 단, 바로 앞 기록이 가입 · 재설정 · 카카오 · 조건 화면 흐름의 단계(`/setup/*` · `/signup/*` · `/password/*` · `/login/*` · `/terms/*`, `isFlowStepPath`)면 되돌리지 않고 시작 화면으로 바꿔 갑니다(#140) — 흐름 중간에 돌려보낸 로그인(S02-3 의 카카오 가입표 만료 · 가입된 이메일, 재설정 완료 뒤 이메일 로그인의 뒤로)은 돌아갈 곳을 다시 실어 오지만 바로 앞은 그만둔 단계입니다. 주소 표시(`reason` · `error`)가 아니라 앱 안 이동 기록의 바로 앞 경로로 가립니다 — 이메일 로그인의 뒤로가 `/login?next=…` 로 바꿔 오면 표시가 사라지기 때문입니다. 이메일 로그인의 뒤로는 로그인 방법 고르기에서 왔으면(보고하려던 로그인은 홈의 로그인 안내 시트에서 왔어도) 되돌리고, 아니면 돌아갈 곳을 붙인 `/login?next=…` 로 바꿔 갑니다.

  - 프로필 · 보고 동네는 실데이터 모드에서 회원 API 로 읽습니다(#164, 아래 "실데이터 (#164)"). 세 동작은 `POST /api/v1/auth/logout`(#57) · 건강정보 동의 철회(#59) · `POST /api/v1/members/me/withdraw`(#59)로 `auth-client.ts` 함수 안만 바꿉니다. 서버 첫 그림은 #81 처럼 비회원입니다(서버는 세션을 읽을 수 없음 — 위 "목 회원 상태", 새로고침 복원은 #158 세션 저장소).
  - `?mock-provider=` 덮어쓰기는 목데이터 모드에서만 듣습니다(`?mock-auth=` 와 같은 이유, #158).
  - **동의 철회 뒤 세션**: 백엔드 #59 에 "건강정보 동의 철회 시 모든 기기 로그아웃(refresh 세션 폐기 + 요청 기기 access token 차단)" 을 요청합니다(시안 문구도 "모든 기기에서 로그아웃돼요"). 프론트 목은 철회 성공을 이미 로그아웃과 같은 결과(비회원 · 프로필 없음 · 보낸 보고 없음 · 비회원 홈 + 알림)로 다룹니다. 연동 때 철회 응답 뒤 이 기기의 세션이 폐기되는지 맞추고, Home-purging("보고를 지우는 중" 홈)은 다음 단계입니다.
- **실데이터 (#164)**: 프로필은 `GET /api/v1/members/me`, 보고 동네는 `GET /api/v1/members/me/region` 을 회원 정보 저장소(`features/auth/member-info.ts`)가 세션이 회원이 될 때 한 번씩 읽습니다. 로그인 방법은 `provider`(`EMAIL` → 이메일, `KAKAO` → 카카오)입니다. **예시 프로필(`dong@example.com` · `동네지기`)로 채우지 않습니다.**
  - 읽는 동안: 계정 섹션 맨 위에 "내 정보를 불러오고 있어요"(`role=status`), 닉네임 · 로그인 방법 · 보고 동네 값은 비웁니다.
  - 읽지 못함(둘 중 하나라도 — 내 동네는 행정동 확인 장애 `REGION_004` 로 따로 실패할 수 있음): 같은 자리에 빨강 상자 "내 정보를 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요." + `다시 시도`(실패한 쪽만 다시 읽음). 받은 값은 그대로 보입니다(로그인한 기기 목록과 같은 모양).
  - 비밀번호 화면(`/me/password`)은 프로필을 읽는 동안 그리지 않고, 읽지 못하면 공통 오류 화면(`ErrorState`, `다시 시도`)입니다. `hasPassword` 가 false 면 비밀번호 행이 없고 화면은 내 정보로 돌려보냅니다(#166, 설정 API 없음).
  - 회원 행이 없으면(`MEMBER_004`) 세션을 비워 비회원이 되고 가드가 로그인으로 보냅니다(만료 토스트 없음). 탈퇴 · 정지(`MEMBER_002` · `003`)면 재발급과 같게 로그인 만료(`/login?reason=expired`)로 끝냅니다.
- 시안과 다르게 둔 것:
  - 지어낸 수치 · 상태는 비웁니다: 로그인한 기기 `3대` · 이번 주 보고 수정 `증상 있음` 은 값 없이 화살표만 둡니다(서버 값이 생기면 채웁니다). 관심 동네 `2곳` 은 목데이터 모드에서만 목 목록의 수(`N곳`)를 보이고 실데이터는 비웁니다(관심 동네 API 가 없음, #198). `52주` · `질병관리청 · SGIS` · `안내문 초안만` 처럼 정해진 사실은 그대로 둡니다.
  - 시안의 알림 스위치는 내 정보에 두지 않고 알림 설정 화면(`/me/notifications`, #195)으로 옮겼습니다. 내 정보의 두 행은 같은 이름 · 설명(`월요일 아침` · `운영자가 발행했을 때`)에 화살표가 있는 링크입니다 — 값(켜짐 · 꺼짐)은 두지 않습니다. 한 화면에서 켜고 끄면 보내는 중 · 실패 · 실데이터 · 미지원 상태를 한곳에서만 다룹니다. 미지원 환경 안내(Settings-nopush)는 시안대로 알림 섹션에 남깁니다(아래 "홈 화면 추가 · 알림 미지원").
  - 미동의 회원(시안 없음)은 회원 화면에서 `내 보고` 섹션(과 데스크톱 메뉴 항목)을 빼고, `건강정보 동의 철회` 자리에 `건강정보 동의하기`(`동의하면 이번 주 보고를 할 수 있어요`)를 두어 홈의 증상 보고 동의 시트 `/?report=health-consent` 로 보냅니다.
  - 데스크톱 설정 메뉴는 시안의 `#` 링크 대신 기록을 쌓지 않는 버튼입니다. 누르면 섹션으로 옮기고 그 제목에 포커스를 줍니다(`#` 링크는 대화상자 닫기를 깨뜨림, `docs/conventions.md`). 시안의 선택 표시(첫 항목 회색 바탕)는 스크롤 위치를 따라가지 않아 두지 않았습니다.
  - 확인 대화상자는 공통 `Modal` 을 써서 태블릿 · 데스크톱에 닫기 버튼(머리줄)이 있고 제목이 24 입니다(시안은 머리줄 없음 · 22). 모바일 시트는 머리줄을 숨깁니다(`compactSheet`). 실패 문구("○○하지 못했어요. 잠시 뒤 다시 시도해 주세요.")는 시안에 없어 더했습니다.
  - 긴 값(긴 이메일)은 제목을 줄이지 않고 값만 한 줄로 자릅니다(`truncate`). 보조기술은 전체를 읽고, 마우스를 올리면 `title` 로 전체가 보입니다.
  - 모바일 머리줄 높이는 56(시안), 태블릿 제목 왼쪽 여백 20(시안)입니다. 홈 머리줄과 다르므로 `AppHeader` 의 `title` 이 있을 때만 이 값을 씁니다.
  - 탈퇴 사유 · 자유 서술 칸은 시안에도 없고 만들지 않습니다. 아동 대리 보고 · 가족 · 그룹 메뉴도 없습니다.

- **문구의 근거**: 앱이 이미 보여 준 동의 · 안내 문구와 구현된 백엔드 코드로 확인한 사실만 씁니다. 백엔드 설계 문서에만 있는 사실은 쓰지 않습니다. 문장마다 근거를 `info-pages.ts` 에 주석으로 달았고, 동의 문구를 고치면 함께 고칩니다. 테스트(`info-screen.test.tsx`)가 건강정보 동의 고지(모으는 것 · 모으지 않는 것 · 52주) · 가입 동의 항목(`PRIVACY_CONSENT_DETAIL`) · 철회 · 탈퇴 대화상자 · 동네 안내 AI 고지(`AI_DRAFT_DISCLOSURE`)와 맞춰 봅니다.
  - 모으는 정보와 보관 기간: 가입 동의 `개인정보 수집·이용`(이메일 · 닉네임 · 행정동), 성인 확인(S02-2 — 백엔드가 가입 필수 확인 `AGE_OVER_19` 로 남김), 비밀번호(이메일 가입만 — `PasswordEncoder` 로 바꿔 저장), 로그인한 기기(User-Agent 를 줄인 기기 이름 · 로그인 시각 · 마지막 사용 시각 — `DeviceLabelResolver` · `RedisRefreshSessionStoreAdapter`, 로그아웃하면 지우고 refresh 만료를 TTL 로 둠 — `AuthSessionProcessor`), 건강정보 동의 고지(모으는 것 · 모으는 이유 · 보관 기간 · 모으지 않는 것), 철회 · 탈퇴 대화상자(모두 지움 · 모든 기기 로그아웃 · 계정 30일 뒤 삭제), 내 동네 바꾸기의 위치 정보 안내.
  - 데이터 출처: 루트 `CLAUDE.md` "보고와 집계" · "공식 정보와 안내", 판단 기준(1인 1주 1회 · 같은 주 수정은 마지막 보고 · 참여 100명 공개 조건 · 진단 아님), 공식 정보 화면(행정동 단위 아님 · 조사 대상 · 지역 단위 · 발표 시점 차이 · 출처 줄 · 원문 기준), 행정동 코드 SGIS · 폐지된 동네 다시 고르기.
  - AI 사용 방식: 루트 `CLAUDE.md` "공식 정보와 안내", 동네 안내의 AI 고지 · `운영자 검토` 배지, 내 정보 행 값 `안내문 초안만`.
- **문구 확인 필요**(PR 검토 · 백엔드와 정할 점):
  - 게이트웨이 접근 로그의 IP · User-Agent 는 보관 기간이 정해지지 않아 화면에 쓰지 않았습니다. auth 는 로그인 · 인증 메일 · 카카오 시작의 시도 횟수 제한에 IP 를 키로 둡니다(Redis, 제한 시간만큼 TTL — `RedisLoginAttemptStoreAdapter` 등). 로그인 기기에는 User-Agent 원문 · IP 를 저장하지 않습니다(`AuthWebController` 로그인 설명). 보관 기간이 정해지면 `로그인할 때 모으는 것` 에 더할지 정합니다.
  - 카카오 로그인은 카카오 프로필 닉네임(`profile_nickname`)을 받습니다(`KakaoOAuthAdapter` · `OAuthMemberProcessor`). 카카오 닉네임이 실명일 수 있어 "이름을 모으지 않아요" 와 부딪칠 수 있습니다. 문구는 건강정보 동의 고지와 같게 두었습니다.
  - 철회 · 탈퇴 뒤 "이미 마감된 주의 동네 집계값은 남아요" 는 쓰지 않았습니다. 마감 집계를 다시 계산하지 않는다는 근거가 설계 문서(entity-design §2-2)뿐이고 집계는 아직 구현 전입니다.
  - 설계 문서에만 있어 뺀 사실: 가입 정보 보관 기간 · 동네 집계값의 익명성 · 질병관리청 자료의 시도 단위 · 자료가 충분한 주에만 AI 초안 · AI 입력이 집계값뿐(entity-design §2-2 · §2-3 · §3-2 · §8, architecture-guide ④). 구현되면 근거와 함께 더합니다.
  - **공식 정보의 쉬운 요약을 누가 쓰는지 정해지면 `AI 사용 방식` 의 첫 문장("AI는 동네 안내문의 초안을 쓰는 데에만 써요.")을 함께 고칩니다**(아래 "공식 정보" 의 연동 요구사항). AI 가 요약 초안을 쓰게 되면 이 문장이 틀립니다.
  - `바로 지워요` 는 기존 동의 문구를 따랐고 실제 파기는 재시도 스케줄러가 끝까지 처리합니다(백엔드 #155). `탈퇴 30일 뒤` 도 대화상자 문구를 따랐고 백엔드는 보고 파기가 끝난 뒤에만 계정을 지웁니다(entity-design §1-1).
  - 공개 조건 `100명` 은 화면에 고정한 값입니다. 백엔드 최소 표본 설정이 바뀌면 함께 고칩니다. 개인정보 처리방침 · 법무 검토는 아직입니다.
- 시안과 다르게 둔 것: 시안이 없습니다. Settings-guest 의 `개인정보 처리방침` 행은 회원 화면(Settings)에 없고 문서도 없어 만들지 않았습니다.

## 로그인한 기기 · 비밀번호 (S10 Settings-devices · Settings-password)

- 회원만 봅니다. 비회원이 주소로 들어오면 아무 것도 그리지 않고 `/login?next=%2Fme%2Fdevices`(비밀번호는 `%2Fme%2Fpassword`, 둘러보기 동네 `&region=` 를 붙임)로 기록을 바꿔 가고, 로그인 뒤 그 화면으로 돌아옵니다(`features/me/member-gate.ts` 의 `useMemberGate({ next })`, #140). 서버 · 하이드레이션 첫 그림의 회원 상태는 늘 `guest` 라 **하이드레이션을 마친 뒤의 상태로만** 판단합니다(`src/lib/use-hydrated.ts`) — 첫 그림으로 판단하면 연동 뒤 회원이 튕깁니다.
- 셸(`features/me/account-page-layout.tsx`): 모바일은 머리줄 56(뒤로 · 제목 17) + 아래 고정 버튼, 탭바 없음. 태블릿은 머리줄 72(뒤로 · 제목 20 · 알림 · 보고 버튼, 아래 구분선) + 가운데 560 + 탭바. 데스크톱은 홈과 같은 머리줄 + 가운데 560(`내 정보로 돌아가기` · 제목 26 · 본문), 왼쪽 설정 메뉴는 없습니다. 아래 버튼은 태블릿 · 데스크톱에서 본문 바로 아래(위 8)입니다.
- `?region=` 은 `/me` 처럼 받아 탭바 · 메뉴 · 보고 진입 · 돌아가는 주소에 남깁니다. 내 정보 행 · 돌아가기 주소는 QA 덮어쓰기(`?mock-auth=` · `?mock-provider=`)도 남깁니다 — 빠지면 하위 화면에서 비회원으로 보여 로그인으로 튕깁니다(연동 때 함께 지웁니다).
- **뒤로**(모바일 · 태블릿 머리줄, 데스크톱 `내 정보로 돌아가기`): 앱 안에서 `/me` 를 거쳐 왔으면 `router.back()`, 주소로 바로 들어왔으면 `/me`(동네 · 덮어쓰기를 남김)로 `router.replace`. 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 `/me` — `MeTrailProvider` 의 `goBack` 이 감쌈, docs/conventions.md "화면의 뒤로"). 기록이 루트에 있어 `/me/devices` → 탭바 홈 → 휴대폰 뒤로 → 머리줄 뒤로에서도 기록을 되돌립니다.
- 머리줄의 동네 이름은 둘러볼 동네 고르기(`?next=<그 화면>`)로 가고, 알림은 내 정보처럼 "준비하고 있어요" 알림입니다.

**내 동네 바꾸기 `/me/region`** (#141, 시안 없음 — 기존 계정 화면 구조를 따름)

- 내 정보 `내 동네` 섹션의 `보고 동네` 행(값은 늘 회원의 내 동네, 모르면 비움)이 동네 · 덮어쓰기를 남긴 채 엽니다. 비회원이면 `/login?next=%2Fme%2Fregion` 으로 기록을 바꿔 갑니다(`useMemberGate({ next })`).
- 안내 "보고와 알림은 내 동네를 기준으로 해요. 행정동을 직접 골라 주세요. 위치 정보는 사용하지 않아요." → `지금 내 동네`(모르면 "아직 정하지 않았어요") → 동네 선택과 같은 검색 칸 · 결과 목록(`district-picker.tsx`) → `이 동네로 바꾸기`. **위치 권한 · GPS · 현재 위치를 쓰지 않습니다.**
- 고르지 않았거나 지금 내 동네와 같으면 버튼이 꺼져 있습니다(`aria-disabled`). 검색어를 고치면 선택을 지웁니다. 저장하는 중에는 검색 칸이 읽기 전용, 버튼 · 뒤로가 꺼집니다. 실패하면 빨강 상자 "내 동네를 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다.
- 성공하면 알림(`region-changed` "내 동네를 바꿨어요")을 내 정보 레이아웃에 남기고 비밀번호와 같게 내 정보로 갑니다(`/me` 에서 왔으면 `router.back()`, 아니면 `/me` 로 기록을 바꿈). 이동할 때까지 `지금 내 동네` 는 처음 그린 값입니다.
- 저장은 가입 마무리 · 다시 고르기와 같은 `saveRegion`(실데이터 `PUT /api/v1/members/me/region`, 코드만 보냄)입니다. 서버가 그 동네를 받지 않으면(없는 코드 · 폐지 — `invalid`) 선택을 지우고 빨강 상자 "이 동네는 고를 수 없어요. 다른 동네를 골라 주세요." 입니다. 행정동 확인 장애(`REGION_004`) · 일시 장애는 "바꾸지 못했어요" 입니다.
- 실데이터는 `지금 내 동네` 를 회원 정보 저장소에서 읽습니다. 읽는 동안 "불러오고 있어요", 읽지 못하면 "불러오지 못했어요" + `다시 시도` 이고, 그동안에도 새 동네를 골라 저장할 수 있습니다. 이동할 때까지 보이는 값은 저장을 보낼 때의 값입니다.
- 목 재현: 프로필 이메일 `reselect-fail@example.com` → 저장하지 못함. `?mock-auth=` 덮어쓰기만 있으면(세션 프로필 없음) 저장해도 보고 동네가 바뀌지 않습니다 — 이메일 로그인한 목 세션에서 확인합니다.

**닉네임 바꾸기 `/me/nickname`** (#192, 시안 없음 — Settings-password 구조를 따름)

- 내 정보 `계정` 섹션의 `닉네임` 행이 동네 · 덮어쓰기를 남긴 채 엽니다. 비회원이면 `/login?next=%2Fme%2Fnickname` 으로 기록을 바꿔 갑니다(`useMemberGate({ next })`).
- 닉네임 칸 하나(지금 닉네임으로 채움) → `이 닉네임으로 바꾸기`. 도움말 · 글자 수 · 오류 문구는 가입(S13-4 Signup-account)과 같습니다 — 도움말 "내 정보에서만 보여요. 다른 사람에게는 보이지 않아요.", 오류 "닉네임은 2~10자로 써 주세요."(앞뒤 공백을 지운 뒤 2~10자, 이모지도 한 글자 — `signup-rules` 의 `nicknameProblem`). 오류는 버튼을 누를 때 처음 보이고 그 뒤 고칠 때마다 다시 판단합니다.
- 비었거나(공백만 포함) 지금 닉네임과 같으면(앞뒤 공백을 지우고 비교) 버튼이 꺼져 있습니다(`aria-disabled`). 칸에서 Enter 로도 보냅니다.
- 보내는 중에는 칸이 읽기 전용, 버튼 · 뒤로가 꺼집니다. 보내지 못하면 빨강 상자 "닉네임을 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다(칸을 고치면 지움). 서버가 규칙 위반으로 거절하면(`MEMBER_101` · `102` — 화면 규칙과 어긋났을 때만) 칸 아래 규칙 문구를 보이고 고칠 때까지 버튼을 끕니다. 응답 전에 화면을 떠나면 늦은 응답으로 이동하지 않습니다.
- 성공하면 프로필이 먼저 바뀌고(목 프로필 · 실데이터 회원 정보 저장소, 화면과 무관), 알림(`nickname-changed` "닉네임을 바꿨어요")을 내 정보 레이아웃에 남긴 뒤 비밀번호 · 내 동네와 같게 내 정보로 갑니다(`/me` 에서 왔으면 `router.back()`, 아니면 `/me` 로 기록을 바꿈).
- 실데이터는 `PATCH /api/v1/members/me {nickname}`(앞뒤 공백을 지워 보냄)이고 응답(내 정보)을 저장소에 바로 넣습니다(다시 읽지 않음). 프로필을 읽는 동안은 그리지 않고(지금 닉네임을 모름), 읽지 못하면 공통 오류 화면(`ErrorState`, `다시 시도`)입니다. 오류 매핑은 `docs/api-contract-draft.md` "회원" 의 "프론트 연동 (#192)".
- 목 재현: 프로필 이메일 `nickname-fail@example.com` → 바꾸지 못함. 바꾼 닉네임은 같은 이메일로 다시 이메일 로그인해도 남습니다(목 서버 흉내). `?mock-auth=` 덮어쓰기만 있거나 `?mock-provider=` 로 세션과 다른 로그인 방법의 예시 프로필을 보면 바꿔도 보이는 닉네임이 바뀌지 않습니다 — 이메일 로그인한 목 세션에서 확인합니다.

**최근 보고 내역 `/me/reports`** (#194, 시안 없음 — Settings-devices 구조를 따름)

- 내 정보 `내 보고` 섹션의 `최근 보고 내역` 행이 엽니다. 비회원이면 `/login?next=%2Fme%2Freports` 로 기록을 바꿔 갑니다(`useMemberGate({ next })`). **건강정보에 동의하지 않은 회원에게는 이 화면이 없습니다** — 보낸 보고가 없고(철회하면 지움) 내 정보에도 `내 보고` 섹션이 없습니다. 그리지 않고 내 정보로 돌려보냅니다(비밀번호가 없는 회원의 `/me/password` 와 같음, 알림 없음).
- 안내 "보낸 보고는 52주 동안 보관해요. 52주가 지나면 지워요. 같은 주에 고쳐 보낸 보고는 마지막 보고만 남아요." → 보낸 보고 목록(`보낸 보고 목록`, 최근 주부터). 한 줄은 위에 주(`이번 주` · `10월 1주` 와 기간 `9월 28일~10월 4일`, KST ISO 주 — `formatIsoWeekOfMonth` · `formatIsoWeekRange`), 아래에 보고(`증상 없음` · `증상 있음 · 발열·기침·인후통, 구토·설사` — 보고 흐름의 `summarizeAnswer`)입니다. 올해가 아닌 주는 `2025년 12월 4주` 처럼 연도를 붙입니다(52주를 보관하면 같은 `10월 2주` 가 두 번 나올 수 있음). 보고하지 않은 주는 줄이 없습니다. 실데이터 이번 주 보고의 주는 서버가 정한 주(`/reports/current` 응답 `isoWeek` — 저장소 `week`, `useSubmittedReportWeek`)이고 목은 지금 주입니다. `이번 주` 라는 이름은 그 주가 화면을 연 때의 KST 주와 같을 때만 붙입니다.
- 고친 주 표시는 두지 않았습니다 — 같은 주는 하나만 남아 목록에서 가릴 것이 없고, 이번 주 보고 저장소가 고쳤는지(`updatedAt`)를 들고 있지 않습니다.
- 이번 주 보고는 보고 버튼 · 내 정보와 같은 값입니다(`useSubmittedReport` — 실데이터는 `GET /api/v1/reports/current` 저장소, 목은 목 보고). 실데이터에서 읽는 동안은 "이번 주 보고를 불러오고 있어요", 읽지 못하면 빨강 상자 "이번 주 보고를 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요." + `다시 시도`(`retryCurrentReport`)입니다.
  - 주 경계: 저장소 값이 지난 주 것이면(앱을 연 채 월요일 00:00 KST 를 넘긴 뒤 화면이 다시 보이기 전에 이 화면을 엶) 화면을 열 때 다시 읽습니다(`refreshCurrentReportIfWeekChanged` — 화면이 다시 보일 때 쓰는 것과 같은 함수, 같은 주면 요청 없음). 그동안은 읽는 중이라 지난 주 보고가 `이번 주` 로 보이지 않습니다. 이 화면만 따로 규칙을 두지 않으려고 "그리지 않기" 대신 다시 읽기를 골랐습니다 — 다시 읽으면 이번 주 보고가 있을 때 바로 보입니다.
- 보낸 보고가 하나도 없으면 빈 상태 "아직 보낸 보고가 없어요" · "주간 보고를 보내면 여기에서 볼 수 있어요." 입니다.
- **지난 보고는 BE 미정입니다**(`features/report/report-history.ts` 의 `listPastReports`, 가정한 API 는 `docs/api-contract-draft.md` "BE 미정"). **실데이터는 지어낸 이력을 보이지 않습니다** — 요청 없이 회색 상자 "지난 보고는 아직 불러올 수 없어요. 지금은 이번 주 보고만 보여요." 를 두고, 이번 주도 보내지 않았으면 빈 상태 제목이 "이번 주에는 아직 보고하지 않았어요" 입니다(docs/conventions.md "데이터 출처" 의 예외).
- 목: 지금 KST 주의 앞 주들 예시 다섯 줄(지난 주 `증상 없음` · 2주 전 호흡기 · 3주 전 `증상 없음` · 4주 전 보고 없음 · 5주 전 두 증상군 · 6주 전 `증상 없음`)이고, 이번 주에 보냈으면 맨 위에 `이번 주` 가 더해집니다. 목 재현 `?mock-reports=empty` 면 지난 보고가 없습니다(이번 주에 보냈으면 `이번 주` 한 줄, 아니면 빈 상태). 실데이터에서는 듣지 않습니다.
- 연동 요구사항: 백엔드에 본인 지난 보고 조회(이번 주 제외, 보관 52주 안 — `GET /api/v1/reports/me` 초안)를 요청합니다. 응답이 생기면 `listPastReports` 의 실데이터 갈래만 바꾸고 화면은 불러오는 중 · 실패 상태를 더합니다.

**관심 동네 `/me/interest-regions`** (#198, 시안 없음 — Settings-devices 구조 + 내 동네 바꾸기의 검색)

- 내 정보 `내 동네` 섹션의 `관심 동네` 행이 동네 · 덮어쓰기를 남긴 채 엽니다. 비회원이면 `/login?next=%2Fme%2Finterest-regions` 로 기록을 바꿔 갑니다(`useMemberGate({ next })`). 건강정보 동의와 무관하게 회원이면 봅니다.
- 안내 "내 동네 말고 지켜볼 동네를 3곳까지 고를 수 있어요. 행정동을 직접 골라 주세요. 위치 정보는 사용하지 않아요." → 관심 동네 목록(`관심 동네 목록`, 고른 순서 — 이름 · 시군구 · `삭제`) → 동네 선택과 같은 검색 칸 · 결과 목록(`district-picker.tsx`) → 아래 버튼 `관심 동네로 더하기`. **위치 권한 · GPS · 현재 위치를 쓰지 않습니다.** 관심 동네는 보고 · 알림의 기준(내 동네)을 바꾸지 않습니다.
- **상한 3곳은 임시 결정입니다**(`INTEREST_REGION_LIMIT` — 기획서 · 시안에 없어 시안 예시 `2곳` 보다 하나 많게, 백엔드와 맞출 때 바꿈). 3곳이 차면 검색 칸 · 버튼 대신 회색 상자 "관심 동네를 3곳 모두 골랐어요. 다른 동네를 더하려면 하나를 삭제해 주세요." 입니다.
- 결과 목록의 내 동네 · 이미 고른 동네는 시군구 뒤에 `· 내 동네` · `· 관심 동네` 를 붙입니다. 고르면 버튼이 꺼지고(`aria-disabled`) 이유를 보입니다: "내 동네는 이미 지켜보고 있어요. 다른 동네를 골라 주세요." · "이미 고른 관심 동네예요. 다른 동네를 골라 주세요." 고르지 않았으면 버튼이 꺼져 있고, 검색어를 고치면 선택을 지웁니다. 관심 동네로 고른 뒤 내 동네를 그 동네로 바꿨으면 목록 줄에 `· 내 동네` 를 붙입니다(지우지 않음).
- 더하면 목록 끝에 붙고 검색어 · 선택을 지운 뒤 알림 "○○동을 관심 동네에 더했어요" 입니다. `삭제` 는 로그인한 기기의 `로그아웃` 처럼 확인 없이 바로 보내고, 성공하면 알림 "○○동을 관심 동네에서 뺐어요" 와 함께 목록 자리로 포커스를 옮깁니다(더해서 3곳이 차 버튼 · 검색 칸이 사라질 때도 같음). `삭제` 의 이름은 `○○동 삭제` 이고 시군구 줄을 설명(`aria-describedby`)으로 이어 이름이 같은 동(신사동 강남구 · 관악구)을 가립니다. 보내는 중에는 모든 `삭제` · 버튼이 꺼지고 검색 칸이 읽기 전용입니다. 실패하면 빨강 상자 "관심 동네를 더하지 못했어요. 잠시 뒤 다시 시도해 주세요." · "관심 동네를 빼지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 목록 · 선택은 그대로라 다시 누를 수 있습니다. 서버가 상한 · 이미 고름으로 거절하면 받은 목록으로 맞춥니다(위 안내 · 이유가 그대로 보임).
- 하나도 없으면 빈 상태 "아직 고른 관심 동네가 없어요" · "아래에서 동네를 찾아 더해 주세요." 입니다.
- **관심 동네는 BE 미정입니다**(`features/region/interest-region-client.ts`, 가정한 API 는 `docs/api-contract-draft.md` "BE 미정" 의 관심 동네). **실데이터는 저장하지 않습니다** — 서버에 저장된 것처럼 보이지 않게 요청 없이 위 안내 · 목록 · 검색 · 버튼을 두지 않고 회색 상자 "관심 동네는 아직 저장할 수 없어요. 준비되면 여기에서 고를 수 있어요." 만 둡니다. 내 정보 행의 수도 비웁니다(docs/conventions.md "데이터 출처" 의 예외).
- 목: 목 회원의 목록(모듈 메모리, 예시 망원1동 · 삼청동 2곳)이고 목 세션이 비회원이 되면(로그아웃 · 탈퇴 · 동의 철회 · 로그인 만료) 지웁니다 — 로그인한 기기 목록과 같은 수명이라 새로고침해도 처음 예시로 돌아갑니다. 목 재현(목데이터 모드에서만): `?mock-interest-regions=empty` 빈 목록 · `full` 3곳(상한) · `fail` 더하기 · 삭제 실패. 이 쿼리가 있는 주소로 화면이 그려질(마운트될) 때마다 목록을 그 상태로 다시 시작합니다 — 더하거나 지운 뒤 같은 주소를 새로고침하면 처음 상태로 돌아갑니다. 쿼리 없이 화면 · 내 정보를 다시 열면 목록은 그대로 두고 `fail` 만 풀립니다. 내 동네 막기는 이메일 로그인 뒤 내 동네를 고른 목 세션에서 확인합니다(`?mock-auth=` 덮어쓰기만 있으면 내 동네가 없음).
- 후속: 관심 동네를 홈 머리줄 · 지도 · 동네 바꾸기에서 고르기 쉽게 쓰는 연결(예: 둘러볼 동네 고르기의 바로가기)은 이 화면 범위 밖입니다. 폐지된 관심 동네 표시 · 내 동네와 겹칠 때 서버 처리는 백엔드와 정합니다(API 초안).

**알림 설정 `/me/notifications`** (#195, 시안 없음 — 계정 화면 구조 + Settings 의 알림 행 모양)

- 내 정보의 머리줄 알림(종) · `알림` 섹션의 두 행이 동네 · 덮어쓰기(`region` · `mock-auth` · `mock-provider` · `mock-push`, `notificationsHref`)를 남긴 채 엽니다. 비회원이면 `/login?next=%2Fme%2Fnotifications` 로 기록을 바꿔 갑니다(`useMemberGate({ next })`). 건강정보 동의와 무관하게 회원이면 봅니다.
- 안내 "켠 알림만 보내요. 알림을 켜지 않아도 검토를 마친 동네 안내는 홈에서 볼 수 있어요." → 시안(Settings) 알림 섹션의 두 항목 스위치: `주간 보고 요청`(`월요일 아침`) · `검토를 마친 동네 안내`(`운영자가 발행했을 때`). 시안에 있는 항목만 둡니다. 스위치 모양은 시안 그대로(켜짐 네이비 · 손잡이 오른쪽, 꺼짐 회색)이고 설명은 `aria-describedby` 로 잇습니다. 아래 버튼은 없습니다.
- 누르면 그 항목만 바로 보냅니다(확인 단계 없음, 한 번에 하나). 보내는 중에는 두 스위치를 누를 수 없고(`aria-disabled`), 실패하면 빨강 상자 "알림 설정을 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 값은 그대로라 다시 누를 수 있습니다. 성공하면 스위치 상태(`aria-checked`)가 바뀌는 것으로 알리고 따로 알림(토스트)은 없습니다.
- **푸시 구독 · 알림 권한 요청은 하지 않습니다**(2단계, 아래 "홈 화면 추가 · 알림 미지원"). 켜고 끄는 것은 알림 설정 값만 바꿉니다. 처음 값은 **모두 꺼짐**입니다 — 알림은 동의한 사용자에게만 보냅니다(루트 `CLAUDE.md`).
- **실데이터는 켜고 끌 수 없습니다.** 알림 설정 API 가 없고(BE 미정, `features/notification/notification-settings-client.ts`) 푸시도 보내지 않아, 켠 모양을 보이면 알림이 오는 줄 압니다. 요청 없이 스위치를 꺼진 모양(`aria-checked=false` · `aria-disabled`, 눌러도 아무 일 없음)으로 두고 회색 상자 "알림은 아직 준비하고 있어요. 지금은 켜고 끌 수 없어요. 검토를 마친 동네 안내는 홈에서 볼 수 있어요." 만 둡니다(위 안내 · 미지원 상자 없음 — "홈 화면에 추가 후 알림을 켤 수 있어요" 가 아직 맞지 않음). 관심 동네 · 최근 보고 내역과 같은 결입니다(docs/conventions.md "데이터 출처" 의 예외). 동네 안내는 홈의 안내 영역에 늘 보여 "홈에서 볼 수 있어요" 가 맞습니다.
- **이 기기에서 알림을 받을 수 없으면**(`needs-install` · `unsupported`, 목데이터) 내 정보와 같은 미지원 상자(`push-unavailable.tsx` — `needs-install` 이면 `홈 화면에 추가하는 방법 보기` → `/install`)를 두고, 스위치는 저장된 값과 무관하게 꺼진 모양(누를 수 없음)입니다(Settings-nopush). 위 안내는 두지 않습니다. 판단 전(서버 · 하이드레이션 첫 그림)에는 상자 없이 누를 수 없는 스위치입니다.
- 머리줄 알림(종)은 그리지 않습니다 — 이 화면으로 오는 버튼입니다.
- **뒤로**: 여러 화면(내 정보 · 머리줄 알림)에서 들어오므로 앞 화면 후보 없이 앱 안 어디서 왔든 되돌립니다(서비스 안내와 같음). 주소로 바로 들어왔으면 `/me`(동네 · 회원 덮어쓰기 · `mock-push`, `meSearchWithPush`)로 기록을 바꿔 갑니다. 머리줄 동네 이름으로 동네 고르기에 다녀와도 `mock-push` 가 남습니다. 데스크톱 돌아가기는 `뒤로`(이름 `뒤로 가기`)입니다.
- 목: 목 회원의 설정(모듈 메모리, 처음 모두 꺼짐)이고 목 세션이 비회원이 되면 지웁니다 — 관심 동네와 같은 수명이라 새로고침하면 처음으로 돌아갑니다. 목 재현(목데이터 모드에서만): `?mock-notifications=on` 모두 켜짐(시안 Settings 모양) · `fail` 바꾸기 실패. 이 쿼리가 있는 주소로 화면이 그려질 때마다 그 상태로 다시 시작하고, 쿼리 없이 다시 열면 값은 그대로 두고 `fail` 만 풀립니다. iPhone · iPad 브라우저나 푸시 API 가 없는 브라우저에서 켜고 끄기를 보려면 `?mock-push=supported` 를 함께 씁니다. 예: `/me/notifications?mock-auth=member&mock-push=supported&mock-notifications=on`.
- 후속(#201): 머리줄 알림(종)을 이 화면으로 잇는 일은 홈 · 지도 · 공식 정보 · 동네 안내 · 서비스 안내 · 계정 화면에 남았습니다(지금은 "알림 설정 화면은 준비하고 있어요"). `검토를 마친 동네 안내` 가 내 동네만인지 관심 동네도인지는 백엔드와 정합니다(API 초안).

**로그인한 기기 `/me/devices`**

- 안내 "모르는 기기가 있으면 로그아웃해 주세요." → 목록(이 기기를 맨 위, 나머지는 마지막 사용이 최근인 순서) → `다른 기기에서 모두 로그아웃`. 이 기기는 배지 `이 기기` · "지금 사용 중" 이고 로그아웃 버튼이 없습니다(이 기기 로그아웃은 내 정보의 `로그아웃`). 다른 기기는 "마지막 사용 11월 20일 21:14"(한국 시각, `formatMonthDayTime`) · `로그아웃`.
- **기기 이름 · 마지막 사용 시각만 보입니다.** IP · 접속 지역 · 위치는 받지도 그리지도 않습니다(시안에도 없음).
- 불러오는 중: 늘 그려 둔 안내 영역(`role=status`)에 "기기 목록을 불러오고 있어요". 불러오지 못함: 빨강 상자 "기기 목록을 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요." + `다시 시도`.
- 시안에 확인 단계가 없어 누르면 바로 보냅니다. 보내는 중에는 로그아웃 버튼이 모두 꺼집니다(`aria-disabled`, 한 번에 하나). 성공하면 목록에서 빼고 알림 "○○에서 로그아웃했어요" · "다른 기기에서 모두 로그아웃했어요" 를 띄운 뒤 목록으로 포커스를 옮깁니다(누른 버튼이 사라짐). 실패하면 목록 아래 빨강 상자 "로그아웃하지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다. 응답 전에 화면을 떠나면 늦은 응답은 버립니다(서버 · 목 서버에서는 이미 끝난 일).
- 다른 기기가 없으면 `다른 기기에서 모두 로그아웃` 을 숨깁니다(시안에 없는 상태).
- **실데이터 (#166)**: 목록 `GET /api/v1/auth/sessions` 의 `deviceLabel`(서버가 User-Agent 를 줄인 "OS · 브라우저", 모르면 "알 수 없는 기기") · `lastUsedAt`(UTC → 한국 시각 라벨) · `current` 만 그립니다. 한 기기 `DELETE /api/v1/auth/sessions/{sessionId}`, 모두 `DELETE /api/v1/auth/sessions`(이 기기는 남음). 다른 기기 모두가 `AUTH_014`(서버가 이 기기 세션을 모름)로 거절되면 로그인 만료로 끝납니다(`/login?reason=expired`). 불러오지 못하면 예시 목록으로 채우지 않습니다.
- 목 데이터(`auth-client.ts` 의 `EXAMPLE_DEVICE_SESSIONS`, **목데이터 모드에서만**)는 시안의 예시 기기(iPhone · Safari 이 기기, Mac · Chrome, Galaxy · 삼성 인터넷)입니다. **기기 이름 · 시각은 예시 값**이고 지금 쓰는 기기와 무관합니다. 로그아웃 · 탈퇴로 비회원이 되면 목록을 지워 다음 로그인은 예시 목록부터이고, 비밀번호를 바꾸면 이 기기만 남습니다(서버와 같음).
- 목 재현 입력(프로필 이메일 — 그 이메일로 이메일 로그인한 뒤 엽니다): 목록 `sessions-fail@example.com` → 불러오지 못함, 로그아웃(한 기기 · 모두) `session-revoke-fail@example.com` → 로그아웃하지 못함(목록 그대로, 다시 눌러도 계속 실패).

**비밀번호 변경 `/me/password`**

- 비밀번호가 있는 회원(이메일 회원 · 카카오를 연결한 이메일 계정): `비밀번호 변경` — 현재 비밀번호 · 새 비밀번호(도움말) · 새 비밀번호 확인 · `비밀번호 바꾸기` · `비밀번호를 잊었어요`(→ `/password/reset`).
- **비밀번호가 없는 회원(카카오로만 로그인, `hasPassword` false)에게는 이 화면이 없습니다**(#166 — 비밀번호 최초 설정 API 를 백엔드 #61 에서 없앴습니다). 주소로 들어오면 아무 것도 그리지 않고 내 정보(동네 · 덮어쓰기를 남김)로 기록을 바꿔 갑니다. 내 정보의 행도 없습니다. 목도 같습니다(카카오 가입 목 세션 · `?mock-provider=kakao`).
- 규칙 · 문구는 S13-4 · S13-6 과 같습니다 — 도움말 "8~20자 · 영문과 숫자 포함 · 띄어쓰기 없이", 오류 "영문과 숫자를 함께 8~20자로, 띄어쓰기 없이 써 주세요." · "비밀번호가 서로 달라요." 오류는 버튼을 누를 때 처음 보이고 그 뒤 고칠 때마다 다시 판단합니다. 빈 칸이 있으면 버튼이 꺼져 있습니다. 새 비밀번호가 현재와 같아도 막지 않습니다(백엔드 계약에 없음).
- 현재 비밀번호가 맞지 않으면 그 칸 아래 "현재 비밀번호가 맞지 않아요." 를 보이고 그 칸으로 포커스를 옮깁니다(칸을 고치면 지움). 보내지 못하면 빨강 상자 "비밀번호를 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다.
- 실데이터에서 더한 상태(#166, 시안 없음): 현재 비밀번호 확인이 잠기면(`MEMBER_006`) 회색 상자 "비밀번호 확인 시도가 많아 잠시 막혔어요. 조금 뒤 다시 시도해 주세요."(잠금 시간은 서버 설정이라 못 박지 않음, 칸을 고치면 지움). 서버가 새 비밀번호를 규칙 위반으로 거절하면 새 비밀번호 칸 아래 규칙 문구(고칠 때까지 버튼 꺼짐). 서버가 비밀번호 없는 계정이라고 하면(`MEMBER_007` — 내 정보와 어긋남) "바꾸지 못했어요" 를 보이고 내 정보를 다시 읽어, `hasPassword` 가 false 면 내 정보로 돌아갑니다(내 정보에서 왔으면 기록을 되돌림).
- 보내는 중에는 칸이 읽기 전용, 버튼 · 뒤로 · `비밀번호를 잊었어요` 가 꺼집니다(`aria-disabled`). 응답 전에 화면을 떠나면 늦은 응답으로 이동하지 않습니다.
- 성공하면 칸을 비우고 알림(`password-changed` "비밀번호를 바꿨어요. 다른 기기에서는 로그아웃됐어요")을 내 정보 레이아웃에 남긴 뒤 내 정보로 갑니다. `/me` 에서 왔으면 `router.back()`(기록에 `/me` 가 두 번 남지 않아 휴대폰 뒤로 가기가 헛돌지 않음), 주소로 바로 들어왔거나 레이아웃이 다시 마운트됐으면 `/me`(동네 · 덮어쓰기를 남김)로 **기록을 바꿔** 갑니다. 어느 쪽이든 뒤로 가기로 이 화면에 돌아오지 않습니다. **이 기기는 로그인 상태로 남고**(세션을 건드리지 않음) 서버가 다른 기기를 로그아웃합니다.
- **비밀번호는 그 화면 상태에만 둡니다**(Provider · 목 세션 · 주소 · 로그 · 브라우저 저장소 금지). 내 정보에 넘기는 알림에는 무슨 일을 마쳤는지만 넣습니다.
- 실데이터는 `POST /api/v1/members/me/password`(access 필요)입니다. 오류 매핑은 `docs/api-contract-draft.md` "회원" 의 "프론트 연동 (#166)".
- 목 재현 입력: 현재 비밀번호 `wrong` → 맞지 않음(로그인 목과 같은 값). 프로필 이메일 `password-fail@example.com` 이거나 새 비밀번호 `fail2026` 이면 보내지 못함.

**연동 (#166) · 남은 정할 점**

- 기기 · 비밀번호는 연동했습니다(위 "실데이터", 계약은 `docs/api-contract-draft.md` "인증" · "회원"). 백엔드가 IP 를 저장하지 않고 응답에 싣지 않으며, `current` 를 늘 주고, 이미 없는 세션 삭제는 성공(멱등)이고, `다른 기기에서 모두 로그아웃` 은 한 번에 지우는 `DELETE /sessions` 입니다. 비밀번호 변경 뒤 다른 기기는 로그아웃됩니다(2026-10-02 결정 — 알림 문구에 반영).
- `비밀번호를 잊었어요` 는 로그인한 상태에서 비로그인용 재설정 흐름(`/password/reset`)으로 가고, 이 계정을 재설정하면 이 탭도 로그아웃된 채 이메일 로그인 화면에 닿습니다(서버가 그 계정의 모든 기기를 로그아웃 — 다른 계정을 재설정하면 이 탭은 회원 그대로). 회원용 재설정이 따로 필요한지 정합니다.

**시안과 다르게 둔 것**

- 비밀번호 도움말 · 규칙 문구는 S13-4 와 같게 바꿨습니다(시안 "8자 이상 · 영문과 숫자 포함").
- Settings-kakao 시안의 `비밀번호 설정` 행 · 설정 화면은 만들지 않습니다 — 비밀번호 최초 설정 API 를 백엔드 #61 에서 없앴습니다(#166).
- 현재 비밀번호 틀림 · 확인 잠김 · 서버 규칙 거절 · 보내지 못함 · 불러오는 중 · 불러오지 못함 · 로그아웃하지 못함 · 성공 알림은 시안에 없어 더했습니다.
- 다른 기기 `로그아웃` 버튼 모서리는 12(`rounded-button`, 시안 10 — 토큰 없음)입니다.
- 데스크톱 `내 정보` 는 시안의 `#me` 링크 대신 뒤로와 같은 버튼(이름 `내 정보로 돌아가기`)입니다 — 링크는 기록을 쌓아 뒤로 가기가 이 화면으로 돌아옵니다.

## 약관 재동의 · 폐지된 동네 다시 고르기 (S02-3 Setup-3-reconsent · S02-1 Setup-1-reselect)

- 다시 들어온 **회원**이 홈(`/`) · 내 정보(`/me` · `/me/devices` · `/me/password`)에 들어오면 조건을 보고 먼저 보냅니다. 순서는 **약관 재동의 → 동네 다시 고르기**입니다(법적 동의가 먼저). 비회원은 보내지 않습니다. 홈은 `HomeScreen`, 내 정보는 `app/me/layout.tsx` 가 같은 가드(`features/me/member-gate.ts` 의 `useRequiredStepsGate`)를 씁니다.
- 가드는 **하이드레이션을 마친 뒤**에만 판단하고 Next 라우터로 기록을 바꿔 갑니다(앱 안 이동 기록을 거치는 `useNavTrail().replace`). 조건이 남아 있으면 뒤로 가기로 홈에 돌아와도 다시 보냅니다. 두 화면도 하이드레이션 뒤에 판단해, 비회원이거나 그 화면의 조건이 없으면 그리지 않고 남은 조건 화면이나 돌아갈 곳으로 보냅니다(동네 화면에 왔는데 재동의가 남았으면 재동의로).
- **쿼리**
  - `?reselect=1`: `/setup/region` 을 가입 동네 선택 대신 다시 고르기로 엽니다(`?from=kakao` 와 함께 오면 다시 고르기가 먼저).
  - `?next=<경로>`: 마친 뒤 돌아갈 곳. **허용 목록**(`/` · `/me` · `/me/devices` · `/me/password` · `/me/region` · `/me/nickname` · `/me/reports` · `/me/interest-regions`)과 정확히 같을 때만 따르고 그 밖(쿼리가 붙음 · `//evil` · `https://…` 등)은 홈입니다(`features/auth/required-steps.ts` 의 `safeNextPath`, 오픈 리다이렉트 방지). 홈이면 붙이지 않습니다.
  - `?intent=report`: 보고하려던 로그인(#140). 홈의 보고 진입(`?report=`)에서 보낼 때 붙이고 조건 화면 사이에 이어 싣습니다. 마지막 조건을 마치면 `/?region=…&report=start` 로 갑니다. 돌아갈 곳이 홈일 때만 받습니다(`reportIntentFrom`).
  - 넘기는 쿼리는 둘러보기 동네(`region`)와 목 덮어쓰기(`mock-auth` · `mock-provider` · `mock-required`)뿐입니다. 열린 시트(`report` 등)는 버립니다.
  - `?mock-required=terms|region|terms,region`: QA 용 조건 덮어쓰기입니다. 있으면 목 프로필의 조건 대신 이 값을 씁니다(회원일 때만 — 비회원은 `?mock-auth=` 와 함께 엽니다). 동네 조건의 옛 동네는 프로필에 폐지된 동네가 없으면 시안 예시 `○○1동` 입니다. 한 화면을 마치면 그 조건을 이 쿼리에서 빼고 이동합니다(다 빠지면 쿼리를 지움) — 남기면 마친 화면으로 다시 돌아옵니다.
- 가드가 보낼 곳이 있으면 같은 그림에서 주소 정리(홈의 맞지 않는 `?report=` · 내 정보의 맞지 않는 `?confirm=`)를 하지 않습니다. 원시 history 를 바꾸면 Next 가 대기 중인 가드 이동을 버려 조건 화면을 건너뜁니다(프로덕션 빌드에서 재현, `docs/conventions.md`). 정리는 조건을 마치고 돌아온 뒤에 합니다.
- 재동의를 마쳤는데 동네 조건이 남았으면 다시 고르기로 이어 가고, 다 마치면 `next` 로 갑니다. 다음 화면은 목 프로필을 바로 읽어 정합니다(`targetAfter`). 모든 이동은 기록을 바꿔 가서(replace) 뒤로 가기로 두 화면에 돌아오지 않습니다.

**약관 재동의 `/terms/reconsent`**

- `바뀐 약관을 확인해 주세요` · `12월 1일부터 아래 내용이 바뀌어요.` · 회색 상자(`[필수] 서비스 이용약관` · `전문 보기` · 바뀐 내용) · 체크 `바뀐 서비스 이용약관에 동의해요` · `동의하고 계속하기`. 단계 표시 · 뒤로가 없습니다. 데스크톱 오른쪽 문구는 "바뀐 내용만 다시 여쭤볼게요".
- 시행일 · 바뀐 내용은 `features/auth/legal.ts` 의 `TERMS_REVISION` 이고 **시안 예시 문구**입니다(52주는 확정 값). 실제 개정 때 `TERMS_VERSION` 을 올리고 함께 바꿉니다. 동의는 지금 버전(`TERMS_OF_SERVICE` + `LEGAL_VERSIONS.TERMS_OF_SERVICE`)으로 보냅니다(`agreeTermsReconsent`).
- `전문 보기` 는 본문이 없어 "약관 본문을 준비하고 있어요" 알림입니다(가입 동의와 같음).
- 아래 보조 버튼 `동의하지 않고 로그아웃`(**시안에 없는 기본안 — 기획 확인 필요**): 로그아웃(`logout`, #92 목)을 보내고, 성공하면 목 세션이 먼저 비회원이 된 뒤 화면이 떠 있으면 홈 `/`(넘길 쿼리 중 `region` 만 남김)으로 기록을 바꿔 갑니다. 체크와 무관하게 누를 수 있습니다. 실패하면 빨강 상자 "로그아웃하지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다(재현: `logout-fail@example.com` 로 로그인한 뒤 `?mock-required=terms`).
- 체크 전에는 버튼이 꺼져 있습니다(`aria-disabled`, 포커스는 남음). 동의 · 로그아웃은 한 번에 하나만 보냅니다(보내는 중이면 두 버튼 모두 꺼짐). 보내는 중에는 버튼이 꺼지고 체크를 바꾸지 않습니다(한 번만 보냄). 실패하면 빨강 상자(`role=alert`) "약관 동의를 보내지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다. 성공하면 목 프로필의 재동의 표시가 먼저 꺼지고(화면과 무관), 화면이 떠 있을 때만 이동합니다.

**폐지된 동네 다시 고르기 `/setup/region?reselect=1`**

- `동네를 다시 골라 주세요` · 안내 상자 "고르셨던 ○○1동이 행정구역 개편으로 바뀌었어요. 지금 사는 행정동을 다시 골라 주세요."(옛 동네 이름, 조사 이/가는 받침으로) · 검색 칸 · 목록 · `이 동네로 바꾸기`. 단계 표시 · 뒤로가 없습니다. 데스크톱 오른쪽 문구는 "행정구역이 바뀌면 다시 여쭤볼게요". **위치 권한을 요청하지 않습니다.**
- 검색어가 비었으면 이어 받은 동네 후보(`listSuccessorDistricts`), 검색어가 있으면 검색 결과입니다. 후보 중 옛 동네 일부를 이어 받은 동은 `○○시 ○○구 · 옛 ○○1동 일부`, 아니면 시군구만 적습니다. 검색어를 고치면 선택을 지웁니다(동네 선택과 같음). 검색 칸 · 목록 · 결과 알림은 동네 선택과 같은 조각(`features/onboarding/district-picker.tsx`)입니다.
- 첫 진입 Provider 의 가입 초안 · 고른 동네를 쓰지 않고 회원 동네를 바로 저장합니다(`saveRegion` — 가입 마무리와 같은 `PUT /api/v1/members/me/region`). 성공하면 내 동네(목 프로필 · 실데이터 저장소)가 바뀌고 폐지 표시가 꺼집니다. 보내는 중에는 버튼이 꺼지고 검색 칸은 읽기 전용입니다. 실패하면 빨강 상자 "동네를 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요." 이고 다시 누를 수 있습니다. 고른 동네를 서버가 받지 않으면(또 폐지된 코드 `REGION_002` · 없는 코드 `001`) 선택을 지우고 "이 동네는 고를 수 없어요. 다른 동네를 골라 주세요." 입니다.
- **실데이터 (#164)**: 동네 조건은 `GET /api/v1/members/me/region` 의 `abolished` 입니다(아직 고르지 않음 `null` 이면 보내지 않음). 내 동네를 읽는 동안에는 이 화면이 다른 곳으로 내보내지 않습니다(읽기 전에는 조건이 없어 보여서) — 읽지 못하면 조건 없이 정해진 것으로 봅니다. 옛 동네 이름을 모르면(행정동 서비스에 코드가 없음 — 이름 `null`) 안내는 "고르셨던 동네가 행정구역 개편으로 바뀌었어요." 입니다. 이어 받은 동네 후보는 BE 미정이라 실제 코드에는 없음("후보 동네가 없어요")으로 보입니다.
- 후보를 불러오는 중 "후보 동네를 불러오고 있어요", 불러오지 못하면 "후보 동네를 불러오지 못했어요 / 동 이름으로 검색해 주세요.", 후보가 없으면 같은 자리 · 모양으로 "후보 동네가 없어요 / 동 이름으로 검색해 주세요." 를 늘 그려 둔 안내 영역에 보입니다.
- 후보 목 데이터(`features/region/mock.ts` 의 `ABOLISHED_DISTRICT_EXAMPLE` · `RESELECT_CANDIDATE_MOCKS`)는 **시안 예시 값**(옛 `○○1동`, 후보 `○○새1동` · `○○새2동` · `○○2동`)이고 코드는 실제와 겹치지 않게 지어낸 값입니다. 검색 목에는 넣지 않았습니다.

**목 상태 · 재현 입력** (`features/auth/auth-client.ts`)

- 목 프로필에 `region`(내 동네 — 가입 마무리의 동네 저장이 채움, 가입 없이 이메일 로그인하면 모름 `null`) · `regionAbolished` · `termsReconsentRequired` 를 더했습니다. 동네를 모르는 회원은 다시 고르게 하지 않습니다.
- 프로필 이메일로 조건을 켭니다(그 이메일로 `/login/email` 에서 로그인하면 홈이 바로 보냄): `reconsent@example.com` → 재동의, `reselect@example.com` → 동네 폐지(옛 동네 `○○1동`). 실패 재현: `reconsent-fail@example.com` → 재동의 거부, `reselect-fail@example.com` → 동네 저장 거부(조건도 켜짐, 다시 눌러도 계속 실패. 이 이메일로 가입하면 S02-3 의 동네 저장도 실패).
- 조건은 로그인할 때 이메일로 켜므로 `reconsent@` · `reselect@` · `*-fail@` 로 **가입해도 가입 직후 조건이 켜집니다**(이메일 가입은 가입 뒤 같은 이메일로 로그인한다). 동네 조건은 가입 마무리의 동네 저장이 바로 끕니다(`reselect-fail@` 은 그 저장이 실패).
- 덮어쓰기만으로 보기: `/?mock-auth=member&mock-required=terms,region`, `/me/devices?mock-auth=member&mock-required=region` 등. **`?mock-required=` 는 프로필 조건을 대신합니다(합치지 않음)** — 예를 들어 `reconsent@` 로 로그인한 뒤 `?mock-required=region` 이면 재동의 없이 동네 다시 고르기만 거칩니다. 조건을 마쳐 쿼리가 다 빠지면 그때부터 프로필 조건을 따릅니다.

**연동 요구사항 · 백엔드와 정할 점**

- **조건을 어디서 받는지**(정해짐): 재동의는 로그인 · 재발급 · `GET /api/v1/members/me` 의 `pendingConsents`, 동네 폐지는 `GET /api/v1/members/me/region` 의 `abolished`(이름은 같은 응답의 `name`, 모르면 null)입니다(#164 연동).
- **재동의 API**(#59): 요청에 `{ type, documentVersion }`(가입과 같은 모양)을 보냅니다. 경로 · 응답 · 이미 최신 버전이면 성공으로 볼지 정해야 합니다. `AGE_OVER_19` 는 이용약관 버전을 같이 쓰므로(`legal.ts`) 이용약관을 올리면 성인 확인도 다시 받아야 하는지 정합니다 — 지금 화면은 이용약관만 다시 받습니다.
- **재선택 후보**(#60): "폐지된 코드면 재선택 유도 응답" 이 이어 받은 동네 후보(코드 · 이름 · 시군구 · 옛 동네 일부인지)를 함께 주는지, 따로 묻는 API 가 있는지 정합니다. 시안의 `○○2동` 처럼 이어 받지 않은 후보를 줄 기준도 정합니다. 동네 다시 저장은 가입과 같은 설정 API 를 쓰고, 고른 코드가 또 폐지된 코드면 오류로 돌려주기를 요청합니다.
- **기획 · 법무와 정할 점**: 재동의 화면의 출구를 `동의하지 않고 로그아웃` 으로 둘지(지금 기본안). 탈퇴 · 건강정보 동의 철회는 로그인 상태가 필요한 내 정보 안에 있어 **재동의를 마친 뒤에만 갈 수 있습니다** — 개정 약관에 동의하지 않는 회원이 동의 없이 탈퇴 · 보고 파기를 요청할 길이 필요한지(예: 재동의 화면에서 탈퇴로 가기, 가드가 탈퇴 대화상자만은 통과시키기) 정해야 합니다.
- `?mock-required=` 덮어쓰기는 `?mock-auth=` 와 같이 목데이터 모드에서만 듣습니다(#158 — 실데이터에서 들으면 주소만으로 조건 화면을 열거나 건너뛸 수 있음). 실데이터 모드는 세션의 `pendingConsents` 가 있으면 약관 재동의로, 내 동네가 `abolished` 면 (재동의 다음에) 동네 다시 고르기로 보냅니다(#164). 다음 화면(`targetAfter`)도 실데이터면 세션 · 회원 정보 저장소를 바로 읽습니다.

**시안과 다르게 둔 것**

- 두 화면 모두 시안처럼 뒤로 버튼이 없지만, 머리줄 자리(44)는 동네 선택처럼 비워 둡니다. 태블릿에서 서비스명이 그 칸 뒤에 놓입니다(시안은 맨 왼쪽).
- 시안의 동네 목록은 `aria-pressed` 버튼이지만 동네 선택처럼 라디오입니다(하나만 고름). 시안의 검색 칸에 미리 들어 있는 `○○` 은 넣지 않고, 빈 검색어일 때 후보를 보입니다.
- 시안의 `전문 보기` 는 `#terms` 링크지만 본문이 없고 같은 문서 `#` 링크를 쓰지 않아 버튼입니다(`docs/conventions.md`).
- 버튼은 고르기 · 체크 전에 꺼진 모양(`aria-disabled`)입니다(시안은 켜진 장면만 있음). 보내지 못함 · 후보를 불러오는 중 · 불러오지 못함은 시안에 없어 더했습니다.
- 재동의 화면 아래 `동의하지 않고 로그아웃` 은 시안에 없는 기본안입니다(**기획 확인 필요**). 다시 고르기에는 나가는 길이 없습니다(동네가 없으면 보고를 셀 수 없음). 둘 다 마쳐야 홈 · 내 정보를 씁니다.
- 후보 없음 안내는 시안에 없어 더했습니다.

## 지도 (S04 · Map-collapsed · Map-expanded · Map-nodata)

- `/map` 은 비회원도 봅니다. 화면 조립은 `features/map/map-screen.tsx`, 데이터 모양은 `features/map/types.ts`(동네 하나의 이번 주는 홈과 같은 `HomeWeekly` — 자료 부족이면 수치 필드가 타입에 없음)입니다. 탭바 · 데스크톱 메뉴의 `지도` 가 이 화면이고 지금 메뉴로 표시합니다.
- **지도 그림만 임시입니다** (`features/map/map-view.tsx`). 색칠한 행정동 대신 같은 동네를 목록(`동네 목록`)으로 보여 고르게 하고, "행정동 지도는 준비하고 있어요" · "지도 대신 목록에서 동네를 골라 보세요" 를 둡니다. 목록 행은 칠하는 색(`lib/status.ts` 의 `STATUS_FILL_CLASS`)과 상태 글자를 함께 보이고, 자료 부족은 회색 · `자료 부족` 글자만입니다. 위 `행정동 이름으로 찾기` · 기준 표시 `시민 자가보고 · 11월 3주`, 아래 범례 4단계(태블릿 · 데스크톱만, 시안)는 시안 자리 그대로입니다.
- 구성: 모바일은 머리줄 없이 지도(화면 폭) → 동네 정보 시트(위 모서리 20, 지도를 20 덮음) → 탭바. 태블릿은 머리줄(동네 · 알림 · 보고 버튼, 아래 구분선) → 지도(테두리 · 모서리 16) → 늘 펼친 동네 정보 → 탭바. 데스크톱은 홈과 같은 머리줄 → 왼쪽 지도 + 오른쪽 400 동네 정보입니다.
- **접힘 · 펼침**(모바일만): 처음에는 처음 고른 동네(내 동네 · 둘러보기 동네)를 접어서 이름 · 상태 · "요약 · 위로 밀어 자세히 보기" 만 보입니다(Map-collapsed). 손잡이 버튼(`aria-expanded`)을 누르거나 시트 윗부분(손잡이 · 이름 · 요약)을 위로 밀면 펼치고, 아래로 밀면 접습니다(24px 이상). 목록에서 다른 동네를 고르면 펼칩니다(Map-expanded). 태블릿 · 데스크톱은 늘 펼친 정보입니다.
- 펼친 정보: 수치가 있는 동네는 `시민 자가보고 · 11월 17일~23일` · 참여 · 증상 보고 · 지난 4주 평균 칸 · 증상군 행(변화 글자 + 작은 막대) · `왜 이렇게 보나요?`(판단 기준 S11 `?explain=1`, 고른 동네 값) · 아래 동작입니다. **자료 부족 동네**(Map-nodata)는 수치 · 상태색 없이 `자료 부족` 글자 · "이번 주 보고가 아직 적어요. 표본이 적을 때는 수치를 표시하지 않아요." · 참여 진행 막대(`41 / 100명`)만 보입니다.
- 아래 동작은 `내 동네로 설정`(내 동네에는 없음 — 아래 "내 동네로 설정") · `이 동네 안내 보기` 입니다. `이 동네 안내 보기` 는 운영자가 발행한 안내가 있는 동네에만 있고 그 동네 · 주의 동네 안내(S07)로 갑니다. 머리줄 동네 이름은 둘러볼 동네 고르기(`?next=/map`)로 가고 고르면 `/map?region=<새 코드>` 로 돌아옵니다. 보이는 이름은 다른 화면과 같습니다(둘러보기 동네 → 회원의 내 동네 → 목 예시, `useShownRegionName`). 알림 · `행정동 이름으로 찾기` 는 "준비하고 있어요" 알림입니다.
- **내 동네로 설정** (#145, 확인 대화상자 시안 없음 — 내 정보의 확인 대화상자 모양 `ConfirmModal` 을 따름):
  - **내 동네**: 회원은 프로필의 내 동네(`useMemberRegion` — 정하지 않았으면 없음), 비회원은 처음 고른 동네(둘러보기 · 목 예시)입니다. 내 동네는 이름 뒤 `(내 동네)`(시트 제목 · 목록 행)로 보이고 `내 동네로 설정` 이 없습니다 — 꺼진 버튼 대신 시안(Map-collapsed)의 상태 표시입니다. 회원은 처음 고른 동네라도 내 동네가 아니면 버튼이 있습니다.
  - **비회원**: 누르면 로그인으로 갑니다(`router.push`, `/login?region=<지도에서 고른 동네>` — 돌아올 곳은 홈, 보고 의도 없음). 그 동네를 내 동네로 하려던 것이라 둘러보기 동네 대신 고른 동네를 싣고(고른 동네가 없으면 둘러보기 동네), 지도는 로그인 `next` 허용 목록 밖이라 로그인 뒤 그 동네 홈입니다.
  - **회원**: 확인 대화상자(`?confirm=set-mine`, 기록을 쌓음 — 내 정보와 같은 키)를 엽니다. 제목 `<동네>을 내 동네로 설정할까요?`(받침에 맞춘 을/를), 회색 상자 "보고와 알림은 내 동네를 기준으로 해요." · "내 정보의 보고 동네에서 다시 바꿀 수 있어요.", 버튼 `취소` · `설정하기`(네이비). 확인하면 고른 동네를 `saveRegion`(`/me/region` 과 같은 `PUT /api/v1/members/me/region`, 출처는 `useDataSource()`)으로 저장하고 대화상자를 닫은 뒤 알림 "<동네>을 내 동네로 설정했어요" 를 띄웁니다. 그 동네는 바로 `(내 동네)` 가 되고 버튼이 사라지며, 내 정보 `보고 동네` 도 그 동네입니다. 버튼이 사라지므로 대화상자가 닫힌 뒤 포커스를 동네 이름 제목(`tabIndex={-1}`, 내 정보 섹션 바로가기와 같은 관례)으로 옮깁니다.
  - 저장하는 중에는 두 버튼(`aria-disabled`) · 닫기 · Esc · 바깥 누르기를 막습니다. 실패하면 대화상자 안 빨강 상자 "내 동네를 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요."(`/me/region` 과 같은 문구)이고 다시 누를 수 있습니다. 저장하는 중에 뒤로 가기로 대화상자를 닫았으면 같은 문구를 알림으로 띄웁니다(내 정보의 확인 대화상자와 같음). 서버가 그 동네를 받지 않으면(`invalid` — 지도 목 자료의 코드처럼 없는 코드 · 폐지) 같은 자리에 "이 동네는 내 동네로 설정할 수 없어요. 다른 동네를 골라 주세요." 입니다.
  - 주소로 바로 들어온 `?confirm=set-mine` 은 회원이 내 동네가 아닌 동네를 골랐을 때만 엽니다(처음 고른 동네 기준). 아니면 열지 않고 주소도 그대로 둡니다(판단 기준 `?explain=` 과 같음). 목 회원은 문서를 새로 읽으면 풀리므로 앱 안 이동으로 확인합니다. 목 재현: 프로필 이메일 `reselect-fail@example.com` → 저장하지 못함.
- **자료 없음**(시안 없음): 이번 주 동네 자료가 하나도 없으면 지도 자리에 "이번 주 동네별 자료가 아직 없어요. 집계가 끝나면 보여 드려요." 만 두고 동네 목록 · 동네 정보를 그리지 않습니다. 자료 부족(동네는 있으나 참여가 적음)과 다릅니다.
- 위치 권한을 묻지 않습니다. 처음 고른 동네는 둘러보기 동네 · 목 예시 동네입니다(회원의 내 동네로 두는 것은 연동 뒤 — 지도 목 자료를 서버 페이지가 만들고, 목 회원 세션은 화면만 압니다). 공식 정보(질병관리청)는 이 화면에 그리지 않습니다.
- `?region=`(둘러보기 동네)은 아는 코드면 처음 고른 동네로 두고 탭바 · 메뉴 · 서비스명 · 보고 진입 · 동네 안내 링크에 남깁니다(다른 화면과 같은 `regionSearch`). 머리줄 보고 버튼은 공식 정보와 같이 `reportHrefFor`(비회원 `/login?region=…&intent=report` — 로그인 뒤 같은 동네 홈의 보고 진입) 입니다. 재동의 · 동네 다시 고르기 가드는 걸지 않습니다(공개 정보 — 공식 정보 · 동네 안내와 같음).
- **목 데이터**(`features/map/mock.ts`, 연동 이슈에서 지웁니다): `?mock=example` 은 시안 예시(내 동네 `○○동` 조금 늘었어요 · 서교동 많이 늘었어요 + 발행 안내 · 합정동 · 망원2동 평소 수준 · 망원1동 자료 부족 41명), `?mock=empty` 는 자료 없음, 값이 없거나 모르면 `insufficient`(모든 동네 자료 부족 — 수치를 지어내지 않음, 홈과 같은 규칙)입니다. 주변 동네는 행정동 목(`DISTRICT_MOCKS`)의 마포구 네 동이라 동네 안내 링크가 열립니다.
- 목 세션: `/map` 이 생겨 탭바 `지도` 가 앱 안 이동이 되었습니다. 로그인 → 지도 → 뒤로 → 내 정보에서 목 회원이 이어집니다(문서를 새로 읽지 않음).

**연동 요구사항**

- **행정동 경계**: SGIS 행정구역 경계 API(출처 · 이용 조건 확인 후, 루트 CLAUDE.md "외부 데이터")에서 처음 고른 동네 주변 행정동의 경계(GeoJSON)를 받습니다. 경계 자료를 앱에 묶을지 · 백엔드가 줄지 · 몇 단계(시군구 단위 등)로 나눠 받을지 정합니다. 코드는 SGIS 8자리로 `features/region` · 백엔드 `district.code` 와 같습니다.
- **지도 라이브러리**: design-guide 의 MapLibre GL 제안 — 핀 없이 행정동 색칠만, 칠은 상태색 0.42 투명도(시안), 자료 부족은 빗금(시안 `hatch`, 상태색 아님), 고른 동네는 네이비 2px 테두리 + 이름 알약. 배경 지도 타일(쓸지 · 출처)을 정합니다. 붙이면 `MapView` 의 목록 자리를 지도로 바꾸고, 목록은 보조기술용 대안으로 남길지 정합니다(색칠 지도만으로는 화면 읽기 프로그램이 동네를 고를 수 없음).
- **집계 API**: 동네별 이번 주 상태를 한 번에 주는 API 가 필요합니다(초안 `GET /api/regions/{admCd}/weekly` 는 동네 하나). 응답에 동네마다 이름 · 상태 · 참여 · (수치가 있을 때만) 증상 보고 비율 · 기준선 · 증상군 변화 · 발행 안내 여부가 있어야 하고, 자료 부족 동네는 수치를 내려 주지 않습니다. 범위(지도 화면에 보이는 경계 · 반경 · 시군구)와 자료 없음 응답(빈 목록)을 정합니다.
- `행정동 이름으로 찾기` 는 행정동 검색(`features/region` 의 `searchDistricts`, 백엔드 #111)으로 찾은 동네로 지도를 옮기는 것으로 붙입니다. `내 동네로 설정` 은 `saveRegion` 으로 백엔드 #60 설정 API 를 부릅니다(#164 — 화면 흐름은 #145 에서 붙임). 회원의 처음 고른 동네 · 지도 범위를 내 동네 기준으로 두려면 집계 API 가 회원 세션(또는 내 동네 코드)을 받아야 합니다.

**시안과 다르게 둔 것**

- 지도 그림 대신 동네 목록(위 "지도 그림만 임시"). 고른 동네 표시는 지도 위 이름 알약 대신 목록 행의 2px 네이비 테두리(`aria-pressed`)입니다.
- 모바일 펼친 정보도 태블릿 · 데스크톱과 같은 내용입니다: 증상군 행 두 줄과 변화 글자 · `왜 이렇게 보나요?` 를 보이고(시안 모바일은 호흡기 한 줄 · 글자 없음), 기간은 `11월 17일~23일`(시안 모바일 `11월 3주 기준`), 칸 이름은 `지난 4주 평균`(시안 태블릿 · 데스크톱 `4주 평균`)으로 맞췄습니다. 모바일 자료 부족 동네에도 참여 진행 막대를 둡니다(시안 모바일은 없음 — 자료 부족에서 보이는 유일한 수치라 폭마다 같게).
- 작은 막대는 홈 증상별 변화와 같은 `TrendBars`(폭 6 · 높이 24 · 최근 7주)입니다(시안 폭 10 · 높이 28 · 4주).
- 손잡이는 터치 영역 44 의 버튼이라 시트 위 여백이 시안(10)보다 조금 넓습니다. 증상군 행은 공통 `ListRow`(최소 56, 시안 52)입니다.
- 범례 모서리는 `rounded-small`(8, 시안 10)입니다. 내 동네 표시는 이름 뒤 `(내 동네)` 로 비회원(둘러보기 — 처음 고른 동네)에게도 같게 둡니다.

## 공식 정보 (S08)

- `/official` 은 비회원도 봅니다. 화면 조립은 `features/official/official-screen.tsx`, 데이터 모양은 `features/official/types.ts` 입니다. **질병관리청 자료만 그립니다** — 시민 자가보고 값(참여 · 증상 비율 · 상태)은 타입에도 화면에도 없고, 차이 안내 상자가 두 정보가 다르다는 것만 알립니다.
- 출처 · 집계 단위 · 기준 주: 본문 맨 위 줄에 `공식` 배지 + "전국 · 47주 · 11월 21일 발표"(모바일) / "전국 · 11월 17일~23일 · 11월 21일 발표"(태블릿 · 데스크톱)를 둡니다. 출처는 제목 "질병관리청 발표" 가 밝힙니다. 기준 주 표기는 시안대로 폭마다 다릅니다(주차 · 기간).
- 구성: 모바일은 머리줄 56(뒤로 · 제목 17) → 출처 줄 → 단계(감염병 · 발표 단계) → 쉬운 요약 → 짧은 차이 안내 → `원문 보기`, 탭바 · 아래 버튼이 없습니다. 태블릿은 머리줄 72(뒤로 · 제목 20 · 알림 · 보고 버튼) → 가운데 640(출처 줄 → 제목 28 → 단계 → 요약 → `원문 보기` → 긴 차이 안내 "시민 자가보고와 무엇이 다른가요?") → 탭바. 데스크톱은 홈과 같은 머리줄 → 가운데 1080(뒤로 → 왼쪽 본문 + 오른쪽 360 차이 안내)입니다.
- `원문 보기` 는 바깥 주소를 새 창으로 엽니다(`rel="noopener noreferrer"`, 이름 "원문 보기 (새 창)").
- **받은 발표가 없을 때**(시안 없음): 출처 줄은 집계 단위(전국)만 두고, 단계 · 요약 자리에 "아직 받은 발표가 없어요" · "질병관리청이 주간 발표를 내면 여기에서 보여 드려요." 를 둡니다. `원문 보기` 는 없고, 차이 안내는 조사 방식(표본감시 등)을 빼고 "질병관리청 발표는 … 달라요." 로 씁니다. 기준 주 · 단계 · 요약 필드는 이 상태의 타입에 없습니다.
- **목 데이터**(`features/official/mock.ts`, 연동 이슈에서 지웁니다): `?mock=published` 는 시안의 예시 발표, `?mock=empty` 와 값이 없거나 모르는 값은 받은 발표 없음입니다 — 실제 자료가 없는 지금 발표를 지어내 보이지 않는 쪽이 기본값입니다. 홈의 두 진입점(공식 정보 행 · 동네 안내의 `공식 예방수칙 보기`)은 홈 목 데이터의 예시 발표("전국 인플루엔자 유행주의보")와 맞게 `/official?mock=published` 로 갑니다(홈 목 `OFFICIAL.href`). 예시 값의 날짜 · 주차는 지금과 무관하고, 원문 주소는 질병관리청 감염병포털 첫 화면입니다.
- 홈과 이음: 홈의 공식 정보 행(모바일 띠 사이 · 태블릿 이상 머리줄 아래)과 동네 안내가 발행 전일 때의 `공식 예방수칙 보기` 가 **같은 주소**(`features/home/official.tsx` 의 `officialHref` — 공식 정보 주소 + 둘러보기 동네 `?region=`)로 이 화면에 갑니다. 이 화면도 `?region=` 을 받아 머리줄 동네 이름 · 탭바 · 메뉴 · 뒤로 · 보고 진입 주소에 남깁니다(공식 자료는 동네와 무관합니다).
- **뒤로**(모바일 · 태블릿 머리줄, 데스크톱 `질병관리청 발표` — 이름 "뒤로, 질병관리청 발표"): 앱 안에서 다른 화면(홈 · 동네 안내 등)을 거쳐 왔으면 `router.back()`, 주소로 바로 들어왔으면 홈(동네를 남김)으로 `router.replace` 합니다. 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 없음 — docs/conventions.md "화면의 뒤로"). 바깥 사이트에서 링크로 들어오거나 새로고침 · 새 탭으로 열면 앞 기록이 없어 뒤로가 사이트 밖으로 나가지 않습니다. 바로 연 뒤 홈을 거쳐 가드 · 로그인 만료로 다른 화면에 replace 됐다가 휴대폰 뒤로로 돌아와도 같습니다(앱 안 replace 가 모두 기록을 거침).
- 머리줄 보고 버튼은 내 정보와 같이 회원 상태로 갈 곳을 고릅니다(`reportHrefFor` — 비회원 보고하려던 로그인 `/login?region=…&intent=report` · 회원은 홈의 보고 진입). 비회원은 버튼 글자가 `로그인하고 보고하기` 입니다. 동네 · 알림은 "준비하고 있어요" 알림입니다. 재동의 · 동네 다시 고르기 가드(`useRequiredStepsGate`)는 걸지 않습니다 — 공개 정보라 비회원과 같은 내용을 봅니다.

**연동 요구사항 · 백엔드와 정할 점**

- 초안 `GET /api/official/latest`(docs/api-contract-draft.md)에 화면이 쓰는 값: 집계 단위(지역 이름) · 기준 주(질병관리청 주차와 기간 시작 · 끝 날짜) · 발표일 · 감염병 이름 · 조사 방식(표본감시 · 전수신고) · 발표 단계 · 쉬운 요약 문장 · 원문 주소. 백엔드 #83~#85 의 `official_surveillance` 는 수치(분율 · 신고 수)와 기간 · 수집 시각만 담습니다 — **발표 단계("유행주의보 발령 중")와 쉬운 요약의 출처가 스키마에 없습니다.** 단계는 질병관리청 발표 원문의 값(주의보 발령 · 해제)을 어디서 받을지, 요약은 누가 쓰는지(AI 는 출처가 확인된 집계값을 옮기는 초안에만 쓰고 운영자가 검토해야 합니다 — 루트 CLAUDE.md) 정해야 합니다. 요약의 작성 주체가 정해지면 내 정보 `AI 사용 방식` 안내(`features/me/info-pages.ts`)의 첫 문장 "AI는 동네 안내문의 초안을 쓰는 데에만 써요." 를 함께 고칩니다(위 "서비스 안내"). 정하기 전에는 단계 · 요약 없이 수치만 보이는 모양(시안 없음)이 필요할 수 있습니다.
- 받은 발표가 없을 때의 응답(204 · `null` · 빈 목록)을 정합니다. 화면은 `empty` 하나로 받습니다.
- 표본감시(인플루엔자 분율) · 전수신고(발생 수)가 함께 오면 화면에 무엇을 몇 개 보일지 정합니다. 지금 화면은 감염병 하나 · 단계 하나입니다. 공공누리 제4유형이라 원값을 그대로 보이고, 파생값(전주 대비 등)을 보이면 파생값임을 밝혀야 합니다(backend entity-design §3-2).
- 수집 시각(`synced_at`)을 화면에 보일지 정합니다(시안에는 없음).

**시안과 다르게 둔 것**

- 태블릿 · 데스크톱의 단계 글자와 `쉬운 요약` 제목은 19px 대신 20px(`text-screen-title`)입니다 — 19px 토큰이 없습니다. 동네 안내(Guide-*-T · -D)의 h2 도 19px 라 함께 토큰을 둘지 정합니다.
- `원문 보기` 는 터치 영역 44(`min-h-touch`)를 갖습니다(시안은 글자 높이) — 위아래 간격이 시안보다 조금 넓습니다. 밑줄은 다른 글자 링크처럼 두지 않습니다.
- 받은 발표가 없을 때 · 데스크톱 뒤로의 이름은 시안에 없어 더했습니다.

## 동네 안내 (S07 · Guide-published · Guide-corrected · Guide-none)

- 주소 `/notice/[region]/[week]`: `[region]` 은 행정동 코드(SGIS 8자리, `features/region` 과 같음), `[week]` 는 기준 주 ISO 주 `YYYY-Www`(월요일 시작, 백엔드 `iso_week` 와 같은 모양, 예: `2025-W47`)입니다. 모양이 틀리거나 그 해에 없는 주(`W00` · `W54` · 53주가 없는 해의 `W53`)이거나 모르는 동네면 404 입니다(`features/notice/paths.ts` 의 `parseNoticeRoute`) — 안내 없음으로 보이면 그런 동네 · 주가 있는 것처럼 읽힙니다.
- 기준 주 문구는 주소의 주로 만듭니다(`src/lib/iso-week.ts`): 모바일 `11월 3주 기준`(그 주 목요일이 든 달의 몇째 주), 태블릿 이상 `11월 17일~23일 기준`(달이 바뀌면 `10월 27일~11월 2일`). 발행일 · 정정일은 `YYYY-MM-DD` 로 받아 `formatMonthDay` 로 적고, 읽지 못하면 그 조각을 빼고 그립니다.
- 폭별 구성: 모바일은 머리줄 56(뒤로 · `○○동 이번 주 안내`) + 본문 + 아래 고정 `야간·휴일 문 연 곳 찾기`(발행된 안내만, 탭바 없음). 태블릿은 머리줄 72(뒤로 · 제목 · 알림 · 보고 버튼) + 가운데 640 + 탭바(홈). 데스크톱은 홈과 같은 머리줄 + 가운데 1080(뒤로 · 제목 → 왼쪽 본문 · 오른쪽 360 집계 상자 · 공식 정보 상자 · 버튼). 집계는 모바일(본문 안 칸 · 증상별 변화)과 태블릿 이상(`이번 주 ○○동 집계` 상자)의 자리 · 모양이 달라 두 번 그리고 폭에 따라 하나만 보입니다.
- **발행된 안내**: `운영자 검토` 배지 · `11월 18일 발행 · 기준 주` · 제목 · 집계(참여 · 증상 보고 · 지난 4주 평균) · 증상별 변화 · `이렇게 해 주세요`(번호 목록) · `근거: …` · `공식 질병관리청 발표 보기`(→ `/official`, 둘러보기 동네 `?region=` 을 이음) · AI 초안 고지 "안내문 초안은 AI가 쓰고 운영자가 검토해 발행해요. 진단이 아닌 참고 정보예요. 증상이 심하면 의료기관에 문의하세요." **AI 고지는 발행된 안내를 보일 때 늘 함께 보입니다**(`AI_DRAFT_DISCLOSURE`). 수치는 운영자가 검토할 때 인용한 값입니다(백엔드 advisory `cited_*`).
- **정정된 안내**: 배지 줄의 기준 주 자리에 마지막 정정일(`11월 19일 정정`)을 적고, 제목 위 회색 테두리 상자(`정정 이력`)에 정정을 **최근 것부터 모두** 보입니다(`11월 19일 정정 · 사유`).
- **안내 없음**: `시민 자가보고` 배지 · 기준 주 · `이번 주는 발행된 안내가 없어요` · "운영자가 표본 규모와 반복·이상 보고를 확인한 변화가 있을 때만 동네 안내를 발행해요." · 집계 · `공식 예방수칙 보기`(→ `/official`, 홈 안내 섹션과 같음) · `질병관리청 발표 보기`(둘 다 둘러보기 동네 `?region=` 을 이음). AI 고지 · 할 일은 없습니다. **자료 부족**이면 수치 · 상태색 없이 홈 상태 카드와 같은 참여 진행 막대(`우리 동네 자료를 채우는 중 64 / 100명`)만 보입니다. 데이터 타입이 `자료 부족` 주에 안내 · 수치를 둘 수 없게 막습니다(`features/notice/types.ts` — 백엔드도 `자료 부족` 집계로는 초안을 만들지 않음).
- 공식 정보(질병관리청)는 집계와 다른 요소(`공식` 배지가 달린 링크)로만 잇고 집계 안에 섞지 않습니다.
- **뒤로**(모바일 · 태블릿 머리줄, 데스크톱 제목 앞): 앱 안에서 들어왔으면(홈의 `안내 전체 보기`) `router.back()`, 주소로 바로 들어왔으면 홈 `/` 로 기록을 바꿔 갑니다. 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 없음 — docs/conventions.md "화면의 뒤로"). 진입 링크는 그냥 `Link` 입니다. 주소로 연 안내 → 홈 → 링크로 같은 안내 → 휴대폰 뒤로 두 번이면 앞 기록이 없어 홈으로 replace 합니다(앱 밖으로 나가지 않음). 새로고침 · 새 탭도 홈으로 replace 합니다.
- 머리줄 보고 버튼은 내 정보와 같습니다(`reportHrefFor`): 비회원 `로그인하고 보고하기` → `/login?region=…&intent=report`(보고하려던 로그인), 회원 → `/?report=health-consent` · `/?report=start`. 동네 · 알림 · `야간·휴일 문 연 곳 찾기` 는 "○○ 화면은 준비하고 있어요" 알림입니다. 알림(종)은 회원에게만 그립니다(위 "머리줄 · 탭바 공통 규칙").
- 주소 쿼리 `?region=<코드>`(둘러보기 동네, 경로의 `[region]` 과 다름)를 공식 정보처럼 받아 서비스명 · 메뉴 · 탭바 · 뒤로 · 보고 진입 주소와 공식 정보 링크(`질병관리청 발표 보기` · `공식 예방수칙 보기`, #146 — 홈의 `officialHref` 와 같이 데이터의 `officialHref` 뒤에 붙이고 이미 쿼리가 있으면 `&` 로 이음, `navHref`)에 남깁니다(#123). 홈의 `안내 전체 보기` 는 아래처럼 이 쿼리를 넣지 않아, 지금은 주소에 직접 붙였을 때만 이어집니다.
- **홈에서 잇기**: 홈 안내 섹션의 `안내 전체 보기` 가 `notice.href` 로 갑니다. 홈 목(`?mock=high`)은 안내 예시 동네 `○○동`(지어낸 코드 `99990100`, `NOTICE_EXAMPLE_DISTRICT`) · `2025-W47` · `?mock=published` 로 잇습니다. 둘러보기 동네(`?region=`)는 이 링크에 넣지 않습니다 — 목 안내는 예시 동네 하나뿐이고, 연동 때 매핑 계층이 그 동네 코드 · 기준 주로 href 를 만듭니다. 홈의 안내 없음은 지금처럼 `공식 예방수칙 보기` 로 갑니다.
- **도메인 사이 import**: 홈 목의 안내 링크는 notice 를 import 하지 않고 문자열로 둡니다(목이라 연동 때 사라짐, 같은 값인지는 `notice-client.test.ts` 가 확인). 안내 화면 → 홈의 증상 조각(`TrendBars` · `GROUP_LABEL` · `TREND_*`)은 import 하는 채로 둡니다 — 후속으로 증상 조각을 두 화면이 같이 쓰는 위치(데이터 도메인)로 옮깁니다.
- **목 상태** `?mock=published|corrected|none|insufficient`(`features/notice/mock.ts`). 모르는 값 · 없으면 `insufficient`(자료 부족의 안내 없음)입니다 — 수치 · 안내를 지어내지 않는 쪽이 기본값입니다. 동네는 데이터 출처가 목이면 행정동 목(`findDistrict`)과 예시 동네만 알고, 실데이터면 행정동 API 로 확인합니다(예시 동네는 지어낸 코드라 없는 화면). 안내 내용은 출처와 무관하게 목이고, 주소의 주는 모양만 봅니다(어느 주든 같은 목). 값은 시안 예시 값이고 증상군 비율은 전체 증상 보고 비율을 넘지 않게 맞췄습니다.

**연동 요구사항 · 백엔드와 정할 점**

- `GET /api/notices/{admCd}?week=`(api-contract-draft)가 주는 것: 동네 이름, 발행된 안내(제목 · 할 일 목록 · 근거 · 발행일), 인용 집계(참여 · 증상 보고 비율 · 지난 4주 평균 · 증상군별 변화), 정정 이력(정정일 · 사유, 최근 것부터). 안내가 없으면 그 주 집계만(자료 부족이면 참여 · 공개 기준만). 함수 안만 바꿉니다(`features/notice/notice-client.ts` 의 `getRegionNotice`). 모르는 동네는 404 로 돌려주기를 요청합니다.
- **정정 모델이 어긋납니다**: 시안 · api-contract-draft 는 발행된 안내를 정정(`correct`)하고 정정 이력을 보이지만, 백엔드 `entity-design.md` §2-5 는 "PUBLISHED 본문은 고치지 않는다 — 철회하고 새 안내를 만든다" 입니다. 정정을 철회 + 새 발행으로 볼지(그때 화면이 이전 안내의 정정 사유를 어디서 받는지), PUBLISHED 에 정정 전이를 더할지 정해야 합니다. 화면은 정정 이력 목록(`corrections`)만 받으면 됩니다.
- 할 일 목록 · 근거는 advisory 의 `title` · `body` 한 덩어리로는 나오지 않습니다. 목록 · 근거를 따로 주거나 본문 형식을 정해야 합니다.
- **철회된 안내**: api-contract-draft 는 철회 이력을 포함한다고 적지만 시안이 없어 만들지 않았습니다. 철회된 주를 안내 없음으로 볼지, "철회됨" 을 따로 보일지 정합니다.
- 미래 주 · 아직 집계가 없는 주를 어떻게 줄지(404 · 자료 부족) 정합니다. 목은 모양만 보고 어느 주든 그립니다.
- 지난 주를 열어도 머리줄 · 집계 제목이 `이번 주 안내` · `이번 주 ○○동 집계` 이고, 기준 주 문구에 연도가 없습니다(`11월 3주` · `11월 17일~23일`). 지난 주 안내를 열 길(알림 · 이력)이 생기면 문구와 연도 표기를 정합니다.

**시안과 다르게 둔 것**

- 태블릿 · 데스크톱 안내 없음의 두 번째 문장 "우리 동네는 지난주보다 조금 늘었어요. 다만 안내를 낼 만큼 큰 변화는 아니었어요." 는 넣지 않았습니다. 운영자가 발행하지 않은 이유처럼 읽히는데 백엔드에 그 판단을 남기는 값이 없습니다. 변화는 집계 상자의 증상별 변화가 보입니다.
- 태블릿 · 데스크톱 집계 상자의 `왜 이렇게 보나요?` 는 넣지 않았습니다. 판단 기준 시트(S11)는 홈 데이터 모양(`MeasuredHomeWeekly`)을 받아 이 화면에서 열 수 없습니다 — 후속 후보입니다.
- 태블릿 · 데스크톱 집계 상자에 증상군을 모두(시안은 발열·기침·인후통 하나), 변화 문구(`많이 늘었어요` 등)와 함께 보입니다. 상태는 색과 글자를 함께 보인다는 규칙을 따릅니다. 막대는 홈 증상별 변화와 같은 `TrendBars`(폭 6 · 높이 24, 시안 10 · 26)이고 안내 없음의 늘어난 증상군도 홈과 같은 상태색입니다.
- 데스크톱 뒤로는 시안의 `#back` 링크 대신 뒤로 버튼 + 제목(`h1`)입니다. 링크는 기록을 쌓아 뒤로 가기가 이 화면으로 돌아옵니다.
- 화면 제목(`h1`)은 `○○동 이번 주 안내` 이고(모바일 · 태블릿 머리줄, 데스크톱 뒤로 옆 — 폭마다 하나만 읽힘), 안내 제목은 `h2` 입니다(시안은 모바일 `p` · 태블릿 이상 `h1`). 정정 상자는 시안의 `role=status` 대신 이름 있는 영역(`정정 이력`)입니다 — 처음부터 있는 내용이라 알림으로 읽히지 않게 했습니다.
- 할 일 제목 `이렇게 해 주세요` 의 태블릿 이상 글자 크기는 20 입니다(시안 19 — 토큰 없음). 행 높이는 `ListRow` 의 56 입니다(시안 52 · 48). 제목은 낱말 단위로 줄을 바꿉니다(시안은 모바일에 줄바꿈을 직접 넣음).

## 홈 화면 추가 · 알림 미지원 (S12 · Settings-nopush · State-push-inapp)

- **알림 권한을 묻지 않습니다.** 푸시 구독 · 서비스 워커 등록은 2단계 기능이라 아직 없습니다. 화면은 이 기기에서 푸시를 받을 수 있는지만 읽습니다(`src/lib/push-support.ts`).
- **푸시 지원 판단** (`detectPushSupport`): iPhone · iPad 이고 홈 화면 앱으로 열리지 않았으면 `needs-install`(API 가 보여도 iOS 는 홈 화면에 추가한 앱에서만 알림을 받음), 그 밖에는 `PushManager` · 서비스 워커 · `Notification` 이 모두 있으면 `supported`, 아니면 `unsupported` 입니다. 홈 화면 앱인지는 `display-mode: standalone` 또는 iOS 의 `navigator.standalone` 으로 봅니다.
- 기기 종류(`detectPlatform`)는 UA 로 가립니다: iPhone · iPad(iPadOS 13 이상은 Mac UA 라 터치 지점 2 이상이면 iPad) · Android · Chromium(Chrome · Edge, Mac Safari 보다 먼저) · Mac Safari · 그 밖. 설치 안내 묶음 · 문구를 고르는 데만 씁니다.
- 서버는 기기를 몰라 **서버 · 하이드레이션 첫 그림은 판단 전(null)** 이고, 그때는 미지원 안내 · 홈 상단 안내를 그리지 않습니다(`usePushSupport` · `useDevicePlatform`, `src/lib/use-push-support.ts`).
- **QA 덮어쓰기** `?mock-push=supported|needs-install|unsupported`: 기기 판단 대신 이 값을 씁니다(하이드레이션 뒤에만 따름, 모르는 값은 무시). 실제 푸시 구독을 붙일 때 지웁니다. 예: `/me?mock-auth=member&mock-push=needs-install`, `/?mock=high&mock-auth=member&mock-push=unsupported`.

**홈 화면 추가 안내 `/install`** (Install · -T · -D)

- 모바일은 전체 화면(머리줄 56 · 오른쪽 닫기 → 제목 두 줄 · 설명 두 문장 → 방법 묶음 → 아래 고정 `알림 켜기` · 회색 글자 `나중에 할게요`)입니다. 태블릿 · 데스크톱은 회색 바탕 가운데 패널(520 · 480, 제목 한 줄 · 설명 둘째 문장만 · 버튼 한 줄 `나중에 할게요` · `알림 켜기`)입니다. 한 DOM 으로 폭마다 모양만 바꿉니다(`features/install/install-screen.tsx`).
- 방법 묶음은 하이드레이션 뒤 기기로 하나만 보입니다: iPhone → iPhone (Safari), Android → Android (Chrome), iPad · Mac Safari → iPad·Mac (Safari), Chrome · Edge → Chrome·Edge. 판별 전 · 모르는 기기는 모바일에 iPhone · Android, 태블릿부터 iPad·Mac · Chrome·Edge 두 묶음을 보입니다(`install-guides.ts`).
- `알림 켜기` 는 "알림 켜기는 준비하고 있어요" 알림(토스트)만 띄웁니다.
- 닫기 · `나중에 할게요`: 앱 안에서 왔으면(내 정보 · 보고 완료의 진입 링크 등) `router.back()`, 주소로 바로 들어왔으면 홈 `/` 로 기록을 바꿔 갑니다(`region` · `mock-auth` · `mock-push` 만 남김). 판별은 루트 레이아웃의 앱 안 이동 기록이 합니다(`useNavTrail`, 앞 화면 후보 없음 — docs/conventions.md "화면의 뒤로"). 진입 링크는 따로 표시를 남기지 않습니다. 새로고침 · 새 탭이면 앞 기록이 없어 홈으로 갑니다.
- 들어오는 길은 내 정보 알림 섹션의 `홈 화면에 추가하는 방법 보기`(아래)와 보고 완료(S06)의 `다음 주 월요일에 알려드릴까요?`(아래) 두 곳입니다. 둘 다 표시를 남기지 않는 보통 `Link` 입니다.

**보고 완료에서 잇기** (S06 Report-done · -T · -D → S12)

- 완료 화면의 `다음 주 월요일에 알려드릴까요? / 홈 화면에 추가하면 알림을 받을 수 있어요` 행은 **푸시가 `needs-install` 인 기기에만** 그리고, 누르면 `/install` 로 갑니다(`features/report/report-flow.tsx`). 링크는 동네 · 덮어쓰기(`region` · `mock-auth` · `mock-push`)만 넘기고 `report` 는 넘기지 않습니다.

  | 푸시 | 완료 화면의 행 | 이유 |
  | --- | --- | --- |
  | `needs-install` | 보임 → `/install` | 홈 화면에 추가해야 알림을 받는 기기라 행 문구가 그대로 맞습니다 |
  | `supported` | 숨김 | 설치가 필요 없어 "홈 화면에 추가하면" 이 맞지 않고, 알림 켜기(푸시 구독)는 2단계라 갈 곳이 없습니다. 2단계에서 알림 켜기로 잇습니다 |
  | `unsupported` | 숨김 | 설치해도 받지 못합니다(내 정보 미지원 상자가 링크를 두지 않는 것과 같음) |
  | 판단 전(null) | 숨김 | 기기를 모릅니다. 완료는 보낸 뒤에만 보여 실제로는 늘 판단이 끝나 있습니다 |

- 설치 안내의 닫기 · `나중에 할게요` 는 앱 안 진입이라 `router.back()` 으로 `/?report=done` 에 돌아오고, **보고 완료 화면이 그대로 남습니다.** 보고 흐름이 쌓은 기록 한 칸도 남아 `우리 동네 변화 보기` 가 홈으로 닫습니다.
- **보낸 보고는 홈 상태가 아니라 홈 밖 저장소에 둡니다** — 목데이터는 `features/report/report-client.ts` 의 목 모듈 메모리, 실데이터는 이번 주 보고 저장소(`features/report/current-report.ts`, `GET /api/v1/reports/current`, #165)입니다. 홈 상태에 두면 설치 안내로 가며 홈이 사라져 돌아왔을 때 `?report=done` 이 시작 단계로 풀렸습니다. 화면은 `useSyncExternalStore` 로 읽어 서버 · 하이드레이션 첫 그림은 보낸 보고가 없습니다.
  - 같은 사람의 같은 주 보고는 하나라 값도 하나만 둡니다. 고치면 바뀌고 되돌리면 지웁니다.
  - 브라우저 저장소(`localStorage` 등)에 남기지 않습니다(증상은 민감정보). 목데이터는 새로고침 · 새 탭이면 사라져 `?report=done` 은 시작 단계로 보입니다 — 목 회원 세션이 새로고침하면 `guest` 로 돌아가는 것과 같습니다. 실데이터는 다시 읽어 완료로 돌아옵니다(위 "주간 건강 보고").

**앱 매니페스트 · 아이콘 · 서비스 워커 자리** (#13)

- **매니페스트** `app/manifest.ts` → `/manifest.webmanifest`. - **iOS** `app/layout.tsx` `metadata.appleWebApp`: 홈 화면 앱으로 열기(`mobile-web-app-capable`), 이름 `동네체온계`, 상태 표시줄 `default`(흰 바탕 · 검은 글자). `black-translucent` 는 화면이 상태 표시줄 밑까지 올라가는데 머리줄이 위쪽 안전 영역을 비우지 않습니다. 시작 그림(`apple-touch-startup-image`)은 기기마다 크기가 달라 두지 않았습니다(첫 화면은 흰 바탕).
- **아이콘은 임시입니다.** 앱 아이콘 · 로고 시안이 없어 브랜드 색(`color.brand`) 바탕에 흰 체온계 도형을 빌드 때 그립니다(`next/og` `ImageResponse`, 저장소에 PNG 를 넣지 않음, 한글 글꼴을 불러오지 않으려고 글자 대신 도형). **시안이 오면 `src/features/pwa/app-icon.tsx` 의 그림(`AppIconArt`)만 바꿉니다** — 아래 주소가 모두 따라 바뀝니다. 그림을 PNG 파일로 받으면 `renderAppIcon` 이 그 파일을 돌려주게 바꿉니다.

- 서버 인증 가드가 없어(`proxy.ts` 는 화면 요청의 CSP · 첫 진입 · 카카오 콜백 쿼리 옮기기만 맡고 인증 가드는 없습니다, 회원 가드는 화면 안 클라이언트 판단) 매니페스트 · 아이콘 주소는 로그인 없이 열립니다. 서버 가드를 더하면 이 주소들을 빼야 합니다.

**연동 요구사항 · 후속 후보**

- 푸시 구독(2단계): 권한 요청 · 구독 · 서비스 워커 등록은 사용자가 `알림 켜기` · 알림 스위치를 누를 때만 하고, 구독 정보 저장 API 와 알림 동의 기록을 백엔드와 정합니다. 그때 `?mock-push=` 를 지우고 알림 설정 화면(`/me/notifications`)의 스위치를 켤 때 권한 요청 · 구독을 잇습니다(API 초안은 `docs/api-contract-draft.md` "알림 설정" 의 2단계). 워커 파일 · 등록 자리는 위 "서비스 워커 자리" 를 따릅니다.
- 앱 아이콘 · 이름 시안: 받으면 `src/features/pwa/app-icon.tsx` 그림과 `src/lib/app-info.ts` 의 `APP_SHORT_NAME` 을 바꿉니다. 실기기(iPhone · Android) 홈 화면 추가는 아직 확인하지 않았습니다. 설치 가능 판정은 Lighthouse 12 에 PWA 범주가 없어 Chrome 의 설치 가능 오류 목록으로 확인했고 오류가 없었습니다(로컬 프로덕션 빌드, 2026-10-03, `docs/performance.md` "기준선").
- **기획 확인 후보**: ① 둘러보기(`?region=`)로 다른 동네를 볼 때도 그 동네 안내가 발행됐으면 "알림 대신 여기서 알려드려요" 가 뜹니다(알림은 내 동네 기준일 텐데 문구가 같음). ② 내 정보 미지원 상자의 "같은 내용은 홈 상단에서 확인할 수 있어요" 는 동네 안내에만 맞고, 주간 보고 요청 알림에는 홈 상단 대응 표시가 없습니다.
- 홈 상단 안내는 지금 "이번 주 안내가 발행된 주" 전체에 늘 보입니다. 이미 본 안내를 다시 띄우지 않을지(읽음 기록)는 서버 값이 생기면 정합니다.

**시안과 다르게 둔 것**

- 시안의 태블릿 · 데스크톱은 홈 위 대화상자(뒤에 홈이 흐리게 보임)지만, 단독 주소라 뒤에 홈을 그리지 않고 회색 바탕 가운데 패널로 둡니다. 제목은 폭과 무관하게 `h1`, 묶음 제목은 `h2` 입니다(시안 태블릿 · 데스크톱은 `h2` · `h3`).
- 시안은 늘 두 묶음을 보이지만, 기기를 알면 그 묶음 하나만 보입니다.
- 내 정보 미지원 상자의 문구는 시안처럼 폭이 아니라 기기 · 푸시 판단으로 고릅니다(모바일 시안 = iPhone, 태블릿 시안 = iPad). 푸시 API 가 없는 브라우저(`unsupported`)는 설치해도 받지 못해 "앱으로 설치하면 알림을 켤 수 있어요." 를 뺐습니다. `홈 화면에 추가하는 방법 보기` 링크는 시안에 없어 더했습니다.
- 시안 Settings-nopush 의 꺼진 스위치는 내 정보가 아니라 알림 설정 화면(`/me/notifications`)에 있습니다. 시안은 `disabled` 이지만 포커스를 잃지 않게 `aria-disabled` 로 둡니다.
- 홈 상단 안내의 줄 높이는 공통 `Callout` 값(1.5, 시안 1.45)입니다.

  - 회원 화면의 가드(`member-gate.ts` 의 `useMemberGate` · 재동의 · 동네 다시 고르기)는 세션이 비회원이 되는 순간 함께 움직입니다. 만료를 알리면 `lib/session-expiry.ts` 가 만료 진행 표시(`isSessionExpiring`)를 켜고, 가드는 그동안 `useMemberGate` 면 만료 감시와 같은 주소(`/login?reason=expired&next=<그 화면>`)로 보내고 재동의 · 동네 다시 고르기는 이동하지 않습니다(그대로면 토스트 없는 `/login` 이나 홈에 닿음). 표시는 로그인 화면에 닿으면 끕니다.

  - 목 재현 입력: 어느 화면이든 `?mock-session=expired` 를 붙여 열면(예: `/me?mock-auth=member&mock-session=expired`) 하이드레이션 뒤 바로 만료 흐름을 탑니다. 모르는 값은 무시합니다. 이동한 주소에는 덮어쓰기가 없어 다시 만료되지 않습니다.
  - 실데이터 모드(#158): 세션 저장소가 재발급에 실패하면(재로그인 · 두 번째 경합 · 탈퇴 · 정지) 토큰을 지우고 `notifySessionExpired()` 를 부릅니다(이 탭에 세션이 있었을 때만). 화면 코드는 401 을 따로 다루지 않습니다. `?mock-session=` 은 목데이터 모드에서만 듣습니다(QA 덮어쓰기라 실데이터에서 들으면 링크 하나로 로그인을 끊을 수 있습니다).
