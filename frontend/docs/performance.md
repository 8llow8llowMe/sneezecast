# 성능 · 접근성 측정 (Lighthouse)

주요 화면의 Lighthouse 측정 방법 · 예산 · 기준선의 정본이다(#177). 설정은 `lighthouserc.yml`, 측정 전 확인은 `scripts/lighthouse-preflight.mjs`, 요약 표는 `scripts/lighthouse-summary.mjs` 가 만든다. 예산 값을 바꾸면 `lighthouserc.yml` 과 아래 "예산" 표를 함께 고친다.

## 측정 방법

```bash
pnpm build             # 프로덕션 빌드. 개발 서버는 재지 않는다
pnpm perf:lighthouse   # 측정 전 확인 → next start -p 3100 → URL 마다 3회 → 예산 확인(경고만) → 중앙값 표
```

- `lhci autorun` 이 `next start -p 3100` 을 띄워 재고 끝나면 내린다.
- **측정 전 확인(`scripts/lighthouse-preflight.mjs`)이 먼저 돈다.** lhci 는 서버가 준비 문구를 내지 않아도 시간 초과 경고만 찍고 그대로 잰다 — 3100 포트에 다른 서버가 떠 있으면 **그 서버를 재고**, 빌드가 없으면 60초 기다린 뒤 닫힌 포트를 재 실행마다 실패한다. 그래서 3100 포트(`127.0.0.1` · `::1`)에 이미 서버가 있거나 `.next/BUILD_ID` 가 없으면 종료 코드 1 로 멈춘다.
- 확인을 통과하면 지난 결과 중 `lhci collect` 가 지우지 않는 것(`.lighthouseci/assertion-results.json` · `report/`)을 지운다. 수집이 중간에 실패했을 때 지난 예산 결과가 이번 요약에 섞이지 않게 한다(`lhr-*` 는 collect 가 지운다).
- Chrome 은 내려받지 않고 설치된 것을 쓴다(macOS 는 `/Applications/Google Chrome.app` 을 스스로 찾는다). 다른 곳에 있으면 `CHROME_PATH` 로 준다.
- 결과는 `.lighthouseci/`(커밋하지 않음)에 남는다. 실행마다의 보고서는 `.lighthouseci/report/*.html` 을 브라우저로 연다. **외부 업로드(temporary-public-storage · LHCI 서버)는 하지 않는다.**
- 요약 표 아래에는 측정 기기 성능 지표(Lighthouse `benchmarkIndex`, CPU 속도) 중앙값과 경고가 붙는다. 경고는 예산 초과(`lhci assert` 결과)와 **리다이렉트** 두 가지다 — 마지막에 보인 주소의 경로가 요청한 경로와 다르면(예: 쿠키가 빠져 `/` 가 `/start` 로 307) 다른 화면을 잰 것이라 표의 화면 칸에 `→ /start` 처럼 적고 경고에 올린다. 읽지 못한 결과 파일은 건너뛰고 알린다.
- 조건: Lighthouse 기본 설정 = 모바일(화면 412×823, 시뮬레이션 쓰로틀링 — 왕복 150 ms · 약 1.6 Mbps · CPU 4배 감속)이다. 값은 실행 3회의 **중앙값**이다. 시뮬레이션이라 같은 빌드에서 실행마다 거의 같은 값이 나오지만, 측정 기기와 Chrome 판이 바뀌면 달라진다.
- 요청에 쿠키 `sc_visited=1; sc_data_source=mock` 을 싣는다(`extraHeaders`).
  - `sc_visited=1` 은 다시 온 사람이라 `/` 가 `/start` 로 307 되지 않는다(`features/onboarding/first-visit.ts`). 홈은 비회원 둘러보기 화면으로 잰다.
  - `sc_data_source=mock` 은 목데이터로 잰다. 출처를 바꿀 수 있는 사이트 주소로 빌드했을 때만 듣는다(로컬 기본값 · dev 웹, `src/lib/data-source.ts`). 운영 주소로 빌드하면 실데이터가 되어 값이 달라진다.
- `next start` 를 쓴다. `output: 'standalone'` 이라 Next 가 "`next start` 는 standalone 과 맞지 않는다" 고 경고하지만 같은 빌드 산출물을 그대로 서빙한다. 배포 컨테이너(`node .next/standalone/server.js`)와 응답 압축 · 헤더는 같은 Next 서버다.

### CI

`frontend-ci` 의 `verify` 잡이 빌드 뒤에 같은 설정으로 돈다(`.github/workflows/frontend-ci.yml`).

- **경고만 낸다.** 예산은 모두 `warn` 이라 넘어도 종료 코드가 0 이고, 단계에 `continue-on-error` 가 있어 수집 실패 · 10분 초과도 잡을 빨간불로 만들지 않는다.
- 측정 전 확인(위)도 같이 돈다.
- 결과는 실행 요약(Step Summary)의 중앙값 표 · 기기 지표 · 경고 목록과 아티팩트 `lighthouse-report`(14일)로 남는다. 경고(예산 초과 · 리다이렉트)가 1건 이상이면 체크 화면에도 `Lighthouse: 예산 경고 N건` 알림(`::warning`)이 뜬다 — 알림일 뿐 잡은 초록불이다.
- 아티팩트에는 실행마다의 HTML 보고서(`.lighthouseci/report/`)와 예산 확인 결과(`assertion-results.json`)만 담는다. `.lighthouseci` 가 숨김 폴더라 `include-hidden-files: true` 를 준다(없으면 조용히 0개가 된다). 파일이 없으면 경고를 낸다.
- 문서만 바뀐 PR(`docs`)은 빌드가 없어 돌지 않는다(`scripts/classify-frontend-changes.sh`). develop 푸시에서도 돈다.
- CI 빌드는 `NEXT_PUBLIC_SITE_URL=https://dev.sneezecast.com` 이라 목데이터로 잰다. 러너에 깔린 Google Chrome 을 `--no-sandbox` 로 쓴다(ubuntu 러너는 Chrome 샌드박스를 쓸 수 없다).
- 러너는 아래 기준선을 잰 기기와 달라 값이 다를 수 있다. 요약의 `benchmarkIndex` 로 기기 차이를 견주고, 아래 "CI 기준선" 을 첫 PR 실행 값으로 채운다.

## 후속 후보

효과가 클 것으로 보이는 순서다. 하나씩 따로 이슈로 내고, 고친 뒤 이 문서의 기준선을 다시 잰다.

1. **글꼴 전략** — #182 에서 후보 다섯 가지를 실험했다(아래 "글꼴 실험 (#182)"). 웹 글꼴을 유지하는 후보(`optional` · 쓰는 굵기만 · 애플만 시스템 글꼴)는 CI 지표를 줄이지 못했고, 시스템 글꼴로 바꾸는 것만 효과가 있다. **시안 글꼴(Pretendard)을 포기할지는 디자인 결정이라 보류**하고 지금은 현행(가변 글꼴 · `swap`)을 유지한다.
2. **첫 로드 JS 줄이기** — #184 에서 앱 쪽 원인(보고 흐름이 다른 화면에 실림 · 홈 시트 · 개발용 토글)을 고쳐 지도 · 공식 정보의 JS 전송량이 5 ~ 15 KiB, 홈의 첫 로드 스크립트가 8 KiB 줄었다(홈 시트는 하이드레이션 뒤 유휴 시간에 미리 받아 로드 중 전체 전송량은 같다 — 위 "#184 전후"). Lighthouse 의 "사용하지 않는 JS" 26 ~ 52 KiB 는 Next · React 프레임워크 청크라 앱 코드로는 줄지 않는다. 남은 후보: 루트 오류 화면(`app/error.tsx`) 청크(약 7 KiB, 첫 로드에서 94% 미사용 — 연결이 끊겼을 때도 그려야 해 지연 로드하지 않는다), 목 로그인 · 세션 로직(`features/auth/auth-client.ts`, 약 11 KB 중 대부분 미사용 — 실데이터 빌드에서 목 갈래를 따로 받게 나누는 구조 변경), 지도의 판단 기준 · 확인 대화상자(약 2 KiB).
3. ~~**bfcache**~~ — #186 에서 했다(아래 "bfcache (#186)"). RSC 응답만 `private, no-cache` 로 바꾸고 문서는 `no-store` 로 두며, 되살아난 회원 화면은 세션을 다시 확인한다. 실데이터 회원 화면까지 Chrome bfcache 에 넣으려면 세션 힌트 쿠키를 다시 쓰지 않거나 문서를 `no-cache` 로 바꿔야 하는데, 둘 다 개인정보 보호를 덜어 하지 않았다.
4. **개발용 데이터 출처 토글의 접근성 이름** — 스위치를 `실데이터` · `목데이터` 두 버튼(`aria-pressed`)으로 바꾸면 보이는 글자와 이름이 맞는다.
5. **예산 강화** — 위 개선 뒤 화면별 예산(`assertMatrix`)과 차단(`error`)으로 올릴지 정한다.

## 의존성 보안 알림 (`@lhci/cli`)

`pnpm audit` 이 `@lhci/cli` 의 전이 의존성에서 high 를 알린다(2026-10-03): `tmp`(`@lhci/cli` 직접 · `inquirer` 아래), `extract-zip`(`lighthouse` → `puppeteer-core` → `@puppeteer/browsers`), `basic-ftp`(`proxy-agent` → `get-uri`). 받아들이고 덮어쓰기(`pnpm.overrides`)는 하지 않는다. 판단 근거:

- 개발 의존성이다. 배포 산출물(`.next/standalone`)과 브라우저 번들에 들어가지 않는다.
- 우리가 쓰는 길(`lhci autorun` + `upload.target: filesystem`, 로컬 서버만 잼)에서 닿지 않는다. `tmp` 는 `lhci open` · `lhci wizard` 에서만, `extract-zip` 은 브라우저를 내려받을 때(`@puppeteer/browsers`)만 쓰는데 우리는 설치된 Chrome 을 쓰고 `puppeteerScript` 도 쓰지 않는다. `basic-ftp` 는 프록시 환경변수가 있을 때 서버 업로드 요청의 프록시(PAC) 처리에서만 쓰는데 filesystem 업로드는 네트워크 요청을 하지 않는다.
- 그래서 생기는 것은 알림뿐이다. `@lhci/cli` 새 판이 고친 의존성을 올리면 그때 올린다. 같은 목록의 `braces`(`@next/eslint-plugin-next` 아래)는 이 이슈 전부터 있던 것이다.
