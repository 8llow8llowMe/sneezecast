# Cursor 어댑터

Cursor 에이전트와 Cursor CLI 에서 `dev-orchestrator` 를 실행할 때의 모드 선택이다. 작업 분류(SIMPLE ~ LARGE_FEATURE)와 흐름은 [SKILL.md](../SKILL.md) 를 따른다.

Cursor 는 `.agents/skills/<name>/SKILL.md` 를 프로젝트 스킬로 읽고 `/dev-orchestrator` 로 부를 수 있다. 루트 `AGENTS.md` 와 `.cursor/rules/*.mdc` 도 프로젝트 규칙으로 읽는다. **전용 역할 파일은 없다.** Claude Code · Codex 의 모델 ID 를 이 호스트에 복사하지 않는다.

## 모드

| 모드 | 쓰는 일 |
|------|---------|
| Agent | 파일 수정 · 검색 · 터미널, 구현과 검증 |
| Plan | 구현 전에 범위 · 순서 · 검증 · 위험을 고정 |
| Ask | 파일을 바꾸지 않는 탐색 · 원인 조사 · 검토 |

CLI 에서는 `agent`, `agent --mode=plan`, `agent --mode=ask` 에 해당한다. 이미 그 모드에 있으면 다시 열지 않는다.

## 작업 분류별 실행

| 분류 | 실행 |
|------|------|
| SIMPLE | Agent 가 직접 처리한다. Plan · 별도 검토를 두지 않는다 |
| FEATURE | 위치가 불명확할 때만 Ask 로 한 번 탐색한다. Agent 한 명이 구현한다. 공개 API · 보안 · 복수 계층이 걸리면 구현 후 Ask 로 검토를 분리한다 |
| BUG | Ask 로 증거를 모으고 Plan 으로 원인 후보와 최소 수정 범위를 고정한다. 원인이 확정되기 전에 파일을 고치지 않는다. Agent 가 수정하고 Ask 로 검토한다 |
| REFACTOR | Plan 으로 보존할 동작과 범위를 고정한 뒤 Agent 가 단계별로 바꾸고, Ask 로 검토한다 |
| ARCHITECTURE | Plan 으로 설계를 저장소 증거와 맞춘 뒤에만 Agent 가 구현한다. 인증 · 개인정보(민감정보) · 트랜잭션이 걸리면 보안 관점 검토를 한 번 더 둔다 |
| LARGE_FEATURE | Ask 탐색을 나눠 모은 뒤 Plan 하나로 통합하고, 쓰기는 Agent 한 명이 순차로 한다 |

## 하위 에이전트와 모델

세션에 하위 에이전트 기능이 있을 때만 역할을 나눈다. 없으면 메인 실행자가 탐색 → 계획 → 구현 → 검증 → 검토 순서로 직접 한다. 역할 프롬프트가 필요하면 `.claude/agents/<역할>.md` 본문을 읽어 적용한다.

모델을 골라야 하면 **그 세션의 사용 가능 목록**에서 고른다.

| 역할 | 선택 |
|------|------|
| 탐색 · 단순 구현 | 목록에서 가볍고 빠른 모델 |
| 일반 구현 · 리팩토링 | 세션의 구현용 기본 모델 |
| 원인 분석 · 최종 검토 | 더 깊은 추론이 가능한 모델 |
| 설계 | 목록의 최상위 추론 모델 |

목록에 최상위 모델이 없으면 Plan 과 분리된 검토 패스로 같은 절차를 수행하고, 보고에 모델 부재를 적는다. 목록에 없는 모델 ID 를 지정하지 않는다.
